1정책 묶음 배포 리허설 (40분)

Day 2의 정책 예시를 시스템 경로에 배포하고 효과를 확인합니다. 배포는 관리자 권한이 필요하며 실습 환경에서만 하세요. /opt 경로와 TEAM_ID_HERE는 실제 값으로 바꿉니다.

Terminal (Linux, 관리자)
sudo mkdir -p /etc/claude-code /opt/team-tools /opt/claude-governance
sudo cp -r ~/workshop/team-marketplace/. /opt/team-tools/
sudo cp ~/workshop/governance/audit_hook.py /opt/claude-governance/
sudo cp ~/workshop/monthly-report/scripts/stop_gate.sh /opt/claude-governance/ && sudo chmod +x /opt/claude-governance/stop_gate.sh
sudo cp ~/workshop/monthly-report/scripts/reconcile.py /opt/claude-governance/   # root 소유 사본을 실행 (프로젝트의 scripts/는 실행하지 않음)
sudo cp ~/workshop/governance/managed-settings.example.json /etc/claude-code/managed-settings.json
claude doctor

다음을 하나씩 확인하고 표에 기록합니다. 아래 동작은 공식 문서에 설명된 것이며 이 자료에서는 배포 경로에서 직접 확인하지 못했습니다.

확인기대(문서 기준)실제
Shift+Tab 순환에 bypassPermissions가 없다정책으로 제거됨
claude --plugin-dir ./xdisableSideloadFlags를 언급하며 종료
프로젝트의 Stop 게이트 훅allowManagedHooksOnly 때문에 실행되지 않음

2충돌 해결: 게이트를 관리형 훅으로 승격 (30분)

1단계에서 프로젝트 훅(Stop 게이트)이 막히는 것을 확인했다면, 조직이 같은 검사를 관리형 훅으로 배포해야 합니다. 스크립트를 시스템 경로에 두고 관리형 설정에 등록합니다.

관리형 훅은 프로젝트 코드를 실행하면 안 됩니다관리형 훅은 신뢰 대화상자 없이 모든 저장소에서 돕니다. 훅이 프로젝트의 scripts/reconcile.py를 부르면 어떤 저장소의 코드든 사용자 권한으로 실행됩니다. 그래서 /opt/claude-governance/의 root 소유 사본을 쓰도록 RECONCILE을 지정합니다. 이 경로 지정은 실행해 보지 못했습니다(문법만 확인).
managed-settings.json의 hooks 부분 (예시)
{
  "hooks": {
    "Stop": [
      { "hooks": [ { "type": "command", "command": "RECONCILE=/opt/claude-governance/reconcile.py /opt/claude-governance/stop_gate.sh" } ] }
    ]
  }
}

생각할 점: ① 스크립트는 $CLAUDE_PROJECT_DIR의 output/월간보고.xlsx를 본다. 프로젝트가 없으면 어떻게 해야 하나? ② 검사 기준(scripts/reconcile.py)은 누가 소유하고 어떻게 배포하나? ③ 관리형 훅이 실패하면 사용자를 막을 것인가(onFailure: "block"), 통과시킬 것인가?

3사내 마켓과 오프라인 시드 설계 (30분)

외부 마켓에 접근할 수 없는 환경에서는 플러그인을 읽기 전용 시드 디렉터리에 미리 설치해 두고 CLAUDE_CODE_PLUGIN_SEED_DIR로 가리킵니다(공식 문서 기준, 이 자료에서는 실행하지 않았습니다: 설치가 사용자 설정을 바꿉니다). 시드 마켓에는 자동 업데이트가 꺼지고 정책의 허용 목록도 시드의 원본 출처를 검사합니다.

Terminal (빌드 머신에서, 문서의 절차)
CLAUDE_CODE_PLUGIN_CACHE_DIR=/opt/claude-seed claude plugin marketplace add <사내 마켓>
CLAUDE_CODE_PLUGIN_CACHE_DIR=/opt/claude-seed claude plugin install monthly-report@team-tools
# 실행 환경: CLAUDE_CODE_PLUGIN_SEED_DIR=/opt/claude-seed , 관리형 enabledPlugins로 활성화
4게이트웨이 결정표 (30분, 문서 기준 토론)

사용자별 비용 한도 같은 차단이 필요하면 Bedrock 직접 사용에서는 Claude Code 자체 기능이 없으므로 게이트웨이(자체 호스팅 Claude apps gateway의 지출 한도, 또는 LLM 게이트웨이의 예산·속도 제한)가 문서에 확인되는 수단입니다. 도입 여부를 결정하는 표를 채웁니다.

트랙 C-2 체크포인트
보너스 (먼저 끝낸 분)
  • 관리형 훅에서 onFailure: "block"을 쓰면 훅 자체가 실패할 때 어떻게 되는지 설계합니다(문서 기준).
  • 감사 로그(JSONL)의 보존 기간과 위치, 접근 권한을 정하는 표를 추가합니다. 로컬 대화 기록은 평문이며 cleanupPeriodDays로 정리됩니다.
힌트 (막혔을 때)
  • 정책이 적용되지 않는 것 같음: 값을 주는 출처 하나만 적용되는 것이 기본입니다. 서버 관리 설정이 먼저 값을 주면 파일은 무시될 수 있습니다.
  • JSON 오류로 시작이 안 됨: 파일을 지우거나 고친 뒤 다시 시작하세요.

시드 설치와 게이트웨이는 문서 기준 설계 토론이며 실행하지 않았습니다.

Bedrock PrivateLink, 무인터넷 서브넷, DRM·캡처 차단·VDI는 확인하지 못했습니다.
