실습

1B-1 결과 커밋과 규칙 파일 (20분)

B-1을 했다면 먼저 그 결과를 커밋해 두세요(git add -A && git commit -qm "b1: fixes and tests"). 이후 결함 diff만 따로 분리됩니다. 규칙 파일은 B-1에서 이미 만들었다면 확인만 하고, B-2만 하는 경우에만 아래로 만듭니다.

일관성은 사람의 기억이 아니라 파일로 유지합니다. 경로별 규칙(paths:)은 해당 파일을 다룰 때만 적용됩니다.

Terminal
mkdir -p .claude/rules
cat > .claude/rules/money.md <<'WV2EOF'
---
paths:
  - "src/fees.js"
---
금액 계산 파일 규칙: 수수료는 원 단위 정수로 반올림해서 반환한다(`Math.round`). 부동소수점 결과를 그대로 반환하지 않는다.
WV2EOF

이미 B-1에서 CLAUDE.md의 팀 규칙(금액은 정수 반올림, 새 함수에는 테스트)이 있습니다. 봇의 리뷰 사유가 이 규칙을 직접 인용하는 것을 뒤에서 확인합니다.

2리뷰 봇 만들기 (40분)

읽기 전용 도구만 주고(--tools), 연결된 MCP 도구도 막고(--disallowedTools "mcp__*"), 구조화된 JSON으로 결과를 받습니다(--json-schema). 결과의 structured_output이 없으면 통과가 아니라 오류로 처리합니다.

Terminal
mkdir -p scripts
cat > scripts/review_schema.json <<'WV2EOF'
{
  "type": "object",
  "properties": {
    "summary": { "type": "string" },
    "findings": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "file": { "type": "string" },
          "line": { "type": "integer" },
          "severity": { "type": "string", "enum": ["high", "medium", "low"] },
          "message": { "type": "string" }
        },
        "required": ["file", "severity", "message"]
      }
    }
  },
  "required": ["summary", "findings"]
}
WV2EOF

mkdir -p scripts
cat > scripts/review_bot.sh <<'WV2EOF'
#!/usr/bin/env bash
# PR 리뷰 봇: diff를 읽기 전용으로 검토하고 JSON으로 결과를 낸다.
# high 지적이 하나라도 있으면 종료 코드 1을 반환해 CI를 막는다.
# 사용: scripts/review_bot.sh [기준 브랜치]   (기본 origin/main)
set -euo pipefail
BASE="${1:-origin/main}"
DIFF=$(git diff "$BASE"...HEAD)
[ -n "$DIFF" ] || { echo "변경 없음"; exit 0; }

RESULT=$(printf '%s' "$DIFF" | claude -p "이 diff를 코드 리뷰해 줘. 금액 계산 정확성, null 처리, 테스트 누락을 우선 본다. 변경된 줄에 대한 지적만 한다." \
  --model "${REVIEW_MODEL:-sonnet}" --tools "Read,Grep,Glob" --disallowedTools "mcp__*" \
  --permission-prompts none --max-turns 6 --max-budget-usd "${REVIEW_BUDGET:-0.50}" \
  --json-schema "$(cat "$(dirname "$0")/review_schema.json")" --output-format json)

# structured_output이 없으면 실패로 취급한다(검증 없이 통과시키지 않는다).
echo "$RESULT" | jq -e '.structured_output' >/dev/null || { echo "리뷰 결과 형식 오류" >&2; exit 2; }
echo "$RESULT" | jq -r '.structured_output | "요약: \(.summary)", (.findings[] | "[\(.severity)] \(.file):\(.line // "-") \(.message)")'
echo "비용: $(echo "$RESULT" | jq -r '.total_cost_usd') USD" >&2

HIGH=$(echo "$RESULT" | jq '[.structured_output.findings[] | select(.severity=="high")] | length')
[ "$HIGH" -eq 0 ] || { echo "high 지적 ${HIGH}건: 머지 차단" >&2; exit 1; }
WV2EOF
chmod +x scripts/review_bot.sh

5CI에 연결 (40분, 실행하지 않음)
YAML, .github/workflows/pr-review-bot.yml
name: pr-review-bot
on:
  pull_request:

permissions:
  contents: read

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v4
        with:
          node-version: "22"
      - run: npm install -g @anthropic-ai/claude-code
      - name: PR 리뷰 (high 지적이 있으면 실패)
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          BASE_REF: ${{ github.base_ref }}
          REVIEW_BUDGET: "0.50"
        run: scripts/review_bot.sh "origin/$BASE_REF"

PR 제목이나 브랜치 이름 같은 사용자 입력은 run:에 직접 넣지 않고 환경 변수(BASE_REF)로 받습니다. fetch-depth: 0이 있어야 기준 브랜치와의 diff를 계산할 수 있습니다.

6비용 상한 정하기 (10분)

PR이 하루 몇 건인지 곱해 보고 REVIEW_BUDGET(1회 상한)과 --max-turns를 정합니다. 상한은 작업 비용보다 여유 있게 잡으세요(코어 3의 하드 스톱은 한도를 넘길 수 있습니다).
