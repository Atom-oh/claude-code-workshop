트랙 실습의 공통 규칙모든 데이터는 가상입니다. 막히면 힌트 정책대로 '기본 레일 → 보너스 → 힌트' 순서를 따르고, 먼저 끝나면 보너스 카드로 갑니다. 마지막 10분은 쇼케이스 카드를 채웁니다.

실습

1실행기 만들기 (30분)

Skill을 헤드리스로 실행하고, 결과 파일을 대조 스크립트로 다시 판정하는 래퍼입니다. 예산, 턴 수, 자동 거부 옵션을 걸고, 모델이 '완료'라고 말했는지와 무관하게 종료 코드를 정합니다.

Terminal
mkdir -p scripts
cat > scripts/run_monthly.sh <<'WV2EOF'
#!/usr/bin/env bash
# 예약 실행용: Skill로 보고서를 만들고, 모델의 말이 아니라 대조 스크립트로 다시 판정한다.
# 사용: scripts/run_monthly.sh 2026-10        종료 코드 0이면 통과, 아니면 사람이 확인해야 한다.
set -uo pipefail
MONTH="${1:?점검월(YYYY-MM)을 인자로 주세요}"
cd "$(dirname "$0")/.."
rm -f output/월간보고.xlsx output/검증실패.txt

claude -p "/monthly-report $MONTH" \
  --model "${REPORT_MODEL:-sonnet}" --effort low --permission-mode acceptEdits \
  --allowedTools "Read" "Write" "Edit" "Bash(python3 *)" \
  --permission-prompts none --max-turns 25 --max-budget-usd "${REPORT_BUDGET:-1.00}" \
  --output-format json > output/run.json 2> output/run.err
RC=$?
echo "claude 종료 코드=$RC, 비용=$(jq -r '.total_cost_usd // "?"' output/run.json 2>/dev/null) USD"

# 모델이 '완료'라고 말했는지와 무관하게, 결과 파일을 결정적 스크립트로 다시 검사한다.
if [ -f output/월간보고.xlsx ] && python3 scripts/reconcile.py output/월간보고.xlsx; then
  echo "통과: output/월간보고.xlsx"
  exit 0
fi
echo "실패: 보고서가 없거나 대조를 통과하지 못했습니다. 사람이 확인하세요." >&2
exit 1
WV2EOF
chmod +x scripts/run_monthly.sh

python3 make_seed.py --next      # 다음 달 데이터 (양식을 바꿨다면 실행하지 마세요)

왜 두 번 확인하나claude -p의 성공은 '모델이 일을 끝냈다'는 뜻이지 '결과가 맞다'는 뜻이 아닙니다. 마지막 판정은 모델 밖의 스크립트가 합니다. --permission-prompts none은 사람이 답할 수 없는 환경에서 승인이 필요한 동작을 멈추지 않고 자동으로 거부합니다(v2.1.259+).
2입력이 깨졌을 때 멈추는지 시험 (30분)

한 지점 CSV에서 열을 지웁니다. 보고서가 만들어지면 안 됩니다.

Terminal
python3 - <<'PY'
import csv
rows = list(csv.reader(open('data/busan.csv', encoding='utf-8')))
idx = rows[0].index('의심건수')
out = [[c for i, c in enumerate(r) if i != idx] for r in rows]
csv.writer(open('data/busan.csv', 'w', newline='', encoding='utf-8')).writerows(out)
PY
scripts/run_monthly.sh 2026-10; echo "exit=$?"

모델 답변: "중단했습니다. data/busan.csv에 의심건수 열이 없어서 보고서를 만들지 않았습니다. ... 부산지점의 의심건수는 임의로 0이나 추정값을 넣을 수 없습니다."

Skill 절차 1번("파일이 없거나 열이 다르면 멈추고 사람에게 알린다")이 지켜진 것을 확인했습니다. 그래도 모델이 이를 항상 지킨다고 가정하지 않고 실행기가 보고서 부재를 실패로 판정합니다.

3예약 실행 워크플로 작성 (30분, 실행하지 않음)

GitHub Actions 예시입니다. 입력값은 run:에 직접 넣지 않고 환경 변수로 받습니다.

YAML, .github/workflows/monthly-report.yml
name: monthly-report
on:
  schedule:
    - cron: "0 0 2 * *"        # 매월 2일 00:00 UTC (한국 시간 09:00)
  workflow_dispatch:
    inputs:
      month:
        description: "점검월 (YYYY-MM)"
        required: true

permissions:
  contents: read

jobs:
  report:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "22"
      - run: npm install -g @anthropic-ai/claude-code
      - run: pip install openpyxl
      - name: 보고서 생성과 대조
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          MONTH_INPUT: ${{ inputs.month }}
          REPORT_BUDGET: "1.00"
        run: |
          MONTH="${MONTH_INPUT:-$(date -u -d "$(date -u +%Y-%m-01) -1 day" +%Y-%m)}"
          scripts/run_monthly.sh "$MONTH"
      - name: 결과 보관 (실패해도 업로드)
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: monthly-report
          path: output/
예약 실행의 보안과 비용자격 증명은 저장소 비밀(Secrets)로 두고, 예산 상한(REPORT_BUDGET)과 턴 상한을 항상 겁니다. 실제 고객·내부 자료를 저장소에 올리지 마세요. 이 워크플로는 문법만 확인했고 실제로 실행하지 않았습니다.
4사람 승인 단계 설계 (30분)

규제기관 제출처럼 위험이 큰 자료는 자동화가 끝나도 사람이 승인합니다. 아래 표를 채워 승인 기준을 정합니다.

질문내 업무의 답
자동 판정이 통과한 뒤 사람이 보는 것은? (샘플 몇 건, 어느 칸)
자동 판정이 실패하면 누구에게 어떻게 알리나?
제출 전에 보관할 증적은? (입력 파일 해시, 실행 로그, 검증 출력)
모델이나 Skill을 바꿀 때 어떻게 다시 시험하나? (오류 심기 시험 재실행)
