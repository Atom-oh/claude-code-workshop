운영·거버넌스: 측정에서 정책으로

세 팀의 호출을 모아 팀·모델·호출 유형별 비용표를 만들고 모델 정책을 도출합니다.

130분운영·거버넌스 직군 대상

이 트랙에서 하는 일

설문의 비용 질문("조직 내 사용 비용의 가시화", "서브에이전트 사용 시 비용이 기하급수적으로 증가", "팀별 토큰 배분")에 내 팀의 숫자로 답합니다. 코어 3이 한 호출의 비용을 쟀다면, 여기서는 팀 단위로 모으고 정책으로 연결합니다.

항목내용
시간130분 (실습 120분 + 여유 10분)
이어서Day 2 통제의 수신기(otlp_sink.py)
완료 기준팀·모델·호출 유형별 비용표를 만들고, 그 표에서 모델 정책 3줄을 도출한다
트랙 실습의 공통 규칙모든 데이터는 가상입니다. 막히면 힌트 정책대로 '기본 레일 → 보너스 → 힌트' 순서를 따르고, 먼저 끝나면 보너스 카드로 갑니다. 마지막 10분은 쇼케이스 카드를 채웁니다.

실습

1세 팀이 호출한 비용을 모으기 (35분)

터미널 하나에서 수신기를 띄워 두고(Day 2 참고), 다른 터미널에서 팀 태그가 다른 세 번의 호출을 실행합니다. 세 번째는 서브에이전트를 부릅니다(코어 2의 report-verifier와 정상 보고서 필요).

Terminal 2
cd ~/workshop/monthly-report
python3 /dev/stdin <<'PY'
import json, subprocess
def run(team, prompt, model, extra):
    cfg = {'env': {'CLAUDE_CODE_ENABLE_TELEMETRY': '1', 'OTEL_METRICS_EXPORTER': 'otlp', 'OTEL_LOGS_EXPORTER': 'none',
           'OTEL_TRACES_EXPORTER': 'none', 'OTEL_EXPORTER_OTLP_PROTOCOL': 'http/json',
           'OTEL_EXPORTER_OTLP_ENDPOINT': 'http://127.0.0.1:14318', 'OTEL_METRIC_EXPORT_INTERVAL': '1000',
           'OTEL_RESOURCE_ATTRIBUTES': f'team.id={team}'}}
    subprocess.run(['claude', '-p', prompt, '--settings', json.dumps(cfg), '--model', model, '--effort', 'low',
                    '--permission-mode', 'acceptEdits', '--max-budget-usd', '1', *extra], stdin=subprocess.DEVNULL, capture_output=True)
run('lab-a', '2+2는? 숫자만 답해.', 'haiku', [])
run('lab-b', '2+2는? 숫자만 답해.', 'sonnet', [])
run('lab-c', 'report-verifier 서브에이전트에게 output/월간보고.xlsx 검증을 맡기고 결과를 그대로 보여줘.', 'sonnet',
    ['--allowedTools', 'Read', 'Agent', 'Bash(python3 scripts/reconcile.py *)'])
PY

lab-c | claude-sonnet-5-5 | main | 0.2043      # 플러그인이 많은 환경에서 위 명령을 그대로 실행한 값
서브에이전트가 따로 보입니다query_source가 main과 subagent로 나뉩니다. 서브에이전트 모델을 haiku로 제한한 효과가 표로 보입니다. 수신기는 지표의 누적값 중 최댓값을 쓰고, 프로세스를 다시 띄우면 집계가 초기화됩니다. 연습용이며 운영 수집기를 대체하지 않습니다.

4Bedrock에서 팀별로 비용 귀속하기 (30분, AWS 계정 필요, 이 자료에서는 실행하지 않음)

OTel은 Claude Code 쪽의 관측입니다. 청구 쪽에서 팀별로 나누려면 팀마다 애플리케이션 추론 프로파일을 만들고 비용 할당 태그를 붙입니다. 프로파일의 태그는 요청의 청구 기록에 붙습니다. 집계는 일 단위이며 요청 단위 비용은 아닙니다(AWS 문서).

Terminal (AWS CLI)
# 1) 시스템 정의(교차 리전) 추론 프로파일의 ARN 찾기 (읽기 전용)
aws bedrock list-inference-profiles --type-equals SYSTEM_DEFINED \
  --query "inferenceProfileSummaries[?contains(inferenceProfileId,'sonnet-5-5')].[inferenceProfileId,inferenceProfileArn]" --output text

# 2) 팀별 애플리케이션 추론 프로파일 만들기 (리소스가 생성됨: 실습 계정에서만)
aws bedrock create-inference-profile --inference-profile-name team-lab-a-sonnet \
  --model-source copyFrom=<1에서 찾은 ARN> --tags key=team,value=lab-a

# 3) Claude Code가 그 프로파일을 쓰게 하기 (Bedrock 문서: 모델 값에 프로파일 ARN 가능)
export ANTHROPIC_MODEL='arn:aws:bedrock:<리전>:<계정>:application-inference-profile/<id>'
실행 전에 확인하세요create-inference-profile은 리소스를 만듭니다. 실습용 계정에서만 실행하고, 비용 할당 태그를 청구 설정에서 활성화해야 보고서에 나타납니다(활성화 방법과 반영 지연은 이 자료에서 확인하지 못했습니다). 명령 형식은 로컬 AWS CLI의 도움말과 대조했고 실행은 하지 않았습니다.

  • 서브에이전트 행이 없음: 서브에이전트가 실제로 호출됐는지 JSON의 modelUsage에 서브에이전트 모델이 있는지 확인하세요.
검증 기록 (2026-10-21, Claude Code 2.1.306)

팀 태그가 다른 세 번의 호출이 수신기에서 팀·모델·호출 유형별로 집계되는 것을 확인했고, 서브에이전트 호출이 subagent로 분리되어 나타나는 것을 확인했습니다.

Bedrock 애플리케이션 추론 프로파일 생성, 태그 활성화, 청구 반영은 실행하지 못했습니다(AWS CLI 문법만 대조).

availableModels 정책 예시는 문서 기준이며 실행하지 않았습니다.

수신기는 연습용이며 운영 수집기(OpenTelemetry Collector 등)의 대체가 아닙니다.
