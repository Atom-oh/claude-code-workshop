트랙 B-1 · 병렬 리뷰와 격리 실험

개발: 금액 계산, null 처리, 서브에이전트 병렬화

리뷰와 테스트 작성을 동시에 돌리고, 위험한 수정은 격리해서 실험합니다.

130분개발 직군 대상

이 트랙에서 하는 일

개발 직군이 매일 하는 일(코드 이해, 버그 수정, 테스트 추가, 리뷰)을 서브에이전트로 병렬화하고 격리합니다. 금융 코드에서 가장 위험한 금액 계산과 null 처리가 주제입니다.

항목내용
시간130분 (실습 120분 + 여유 10분)
필요Node.js 22 (프리플라이트), git
완료 기준버그를 고치고 테스트가 전부 통과하며, 리뷰·테스트 작성이 병렬로 돌고, 격리 실험이 메인 트리를 건드리지 않는다
트랙 실습의 공통 규칙모든 데이터는 가상입니다. 막히면 힌트 정책대로 '기본 레일 → 보너스 → 힌트' 순서를 따르고, 먼저 끝나면 보너스 카드로 갑니다. 마지막 10분은 쇼케이스 카드를 채웁니다.

cat > src/fees.js <<'WV2EOF'
// 이체 수수료 계산 (연습용)
const RATE = { premium: 0.001, basic: 0.003 };

export function calcFee(amount, grade) {
  const rate = RATE[grade];
  return amount * rate;
}
WV2EOF

cat > test.js <<'WV2EOF'
import { getAccountGrade } from "./src/accountService.js";
import { calcFee } from "./src/fees.js";

let failed = 0;
function check(name, fn, expected) {
  let actual;
  try { actual = fn(); } catch (e) { actual = `throws ${e.constructor.name}`; }
  const ok = actual === expected;
  if (!ok) failed++;
  console.log(`${name}: ${ok ? "PASS" : `FAIL (got ${actual})`}`);
}

check("Test 1 - premium 등급 계좌", () => getAccountGrade(1), "premium");
check("Test 2 - basic 등급 계좌", () => getAccountGrade(2), "basic");
check("Test 3 - kyc 없는 계좌", () => getAccountGrade(3), "unknown");
check("Test 4 - premium 수수료 100000원", () => calcFee(100000, "premium"), 100);
process.exit(failed ? 1 : 0);
WV2EOF

cat > CLAUDE.md <<'WV2EOF'
# account-service-lab (연습용)

계좌 조회와 이체 수수료 계산 샘플. 데이터는 모두 가상이다.

- 테스트는 `npm test`로 실행한다. 코드를 바꾸면 항상 실행해 결과를 확인한다.
- `src/accounts.js`의 데이터 구조는 임의로 바꾸지 않는다.
- 금액 계산은 부동소수점 오류가 없는지 확인한다(원 단위 정수로 반올림).
- 새 함수에는 반드시 테스트를 추가한다.
WV2EOF

3리뷰어와 테스트 작성자를 동시에 (40분)

두 서브에이전트(읽기 전용 리뷰어, 테스트만 쓰는 작성자)를 병렬로 돌립니다.

Claude 세션 입력
code-reviewer와 test-writer 서브에이전트를 동시에(병렬로) 실행해줘. code-reviewer는 src/fees.js의 calcFee를 검토하고, test-writer는 test.js에 calcFee 엣지 케이스 테스트를 추가해. 둘 다 끝나면 각 결과를 한 줄씩 요약해줘.
참고 측정값 (sonnet-5.5 메인, haiku-5.5 서브에이전트, 43초, 0.30달러)
- code-reviewer: calcFee에 high 3건 (반올림 없음, 알 수 없는 등급/prototype 키에서 조용히 NaN, amount 검증 없음)
- test-writer: test.js에 엣지 케이스 테스트 16개 추가. npm test 결과 20개 중 16 통과, 4 실패
  (실패 중 3개는 리뷰어가 지적한 반올림 누락, 1개는 기존 kyc 실패)
둘 다 백그라운드로 시작되어 병렬로 실행됨

관찰: 리뷰어의 지적이 테스트 실패로 교차 확인됩니다. 수정은 둘 다 한 뒤에 합니다. 리뷰어의 tools는 Read, Grep, Glob(쓰기 도구 없음)입니다. 테스트 작성자의 Bash(npm test) 지정은 문서에 기재되지 않은 형식이므로 제한은 허용 규칙으로 확인하세요.

4격리해서 실험하기: worktree (30분)
Terminal
cat > .claude/agents/fee-fixer.md <<'WV2EOF'
---
name: fee-fixer
description: 수수료 계산 코드를 격리된 worktree에서 고치고 테스트로 확인한다. 메인 작업 트리를 건드리지 않고 실험하고 싶을 때 사용한다.
tools: Read, Edit, Bash(npm test)
model: sonnet
isolation: worktree
maxTurns: 10
---
격리된 복사본(worktree)에서만 작업한다. src/fees.js의 calcFee가 원 단위 정수로 반올림해 반환하도록 고친다.
고친 뒤 `npm test`를 정확히 이 한 줄로 실행하고, 변경한 파일과 테스트 결과를 보고한다.
WV2EOF
Claude 세션 입력
fee-fixer 서브에이전트에게 calcFee 반올림 수정을 맡기고, 그 결과를 한 문단으로 알려줘.
참고 측정값
fee-fixer는 src/fees.js의 calcFee에서 `return amount * rate;`를 `return Math.round(amount * rate);`로 바꿨습니다.
변경은 격리된 worktree(.claude/worktrees/agent-..., 브랜치 worktree-agent-...)에 커밋 없이 남아 있습니다.
그러나 Bash 권한이 거부되어 npm test를 실행하지 못했습니다. 메인 작업 트리는 건드리지 않았습니다.
Terminal, 확인
git status --short            # 메인 트리: src/fees.js 변경 없음
git worktree list             # 격리된 worktree 목록
cd .claude/worktrees/agent-*/ && git diff && npm test
worktree에서는 허용 규칙이 안 맞을 수 있습니다측정에서 서브에이전트가 worktree 안에서 npm test를 승인받지 못해 실행하지 못했습니다. 이럴 때는 사람이 그 worktree에서 직접 테스트하면 됩니다. 메인 트리가 깨끗하게 남는 것이 격리의 요점입니다. .claude/worktrees/는 .gitignore에 넣으세요.

보너스 (먼저 끝낸 분)
  • /code-review(문서 기준: 현재 diff의 정확성 리뷰, --fix, --comment 옵션)로 같은 변경을 리뷰하고 서브에이전트 리뷰와 비교합니다.
  • test-writer가 만든 실패 테스트를 근거로 calcFee를 고치고 전부 통과시킵니다.
힌트 (막혔을 때)
  • test-writer가 승인 대기: 허용 규칙(Bash(npm test))과 폴더 신뢰를 확인하세요.
  • 서브에이전트가 순차로 실행됨: 요청에 '동시에(병렬로)'를 명시하세요.
검증 기록 (2026-10-21, Claude Code 2.1.306)

병렬 서브에이전트 2개를 실제로 실행해 둘 다 백그라운드로 시작되고 결과가 교차 확인되는 것을 확인했습니다(43초, 0.30달러).

isolation: worktree 서브에이전트가 메인 트리를 바꾸지 않고 별도 worktree와 브랜치에 변경을 남기는 것을 확인했습니다.

worktree 안에서의 npm test 실행은 권한 거부로 확인하지 못했습니다(위 주의 참고).

/code-review는 실행하지 않았습니다.
