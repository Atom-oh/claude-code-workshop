트랙 A-1 · 양식을 지키는 보고서 자동화

컴플라이언스·업무 자동화

양식이 바뀌어도 검증이 함께 바뀌고, 검증기 자체도 시험합니다.

130분비개발 직군 대상

이 트랙에서 하는 일

비개발 직군의 가장 큰 질문, "사내 양식을 그대로 맞춰야 하고, 숫자가 틀리면 안 됩니다. 어떻게 자동화하나요?"에 답합니다. 코어 1·2에서 만든 보고서를 실제로 일어나는 변화(양식 변경, 검증기의 오류)에 부딪쳐 보며 단단하게 만듭니다.

항목내용
시간130분 (15:20–17:30)
대상컴플라이언스, 기획, 운영 등 비개발 직군 (코드를 직접 쓰지 않아도 됨)
이어서코어 1·2의 ~/workshop/monthly-report
완료 기준양식이 바뀌어도 검증이 함께 바뀌고, 검증 스크립트가 틀렸을 때도 잡힌다는 것을 오류를 심어 확인한다
트랙 실습의 공통 규칙모든 데이터는 가상입니다. 막히면 힌트 정책대로 '기본 레일 → 보너스 → 힌트' 순서를 따르고, 먼저 끝나면 보너스 카드로 갑니다. 마지막 10분은 쇼케이스 카드를 채웁니다.

실습

1양식 호환성 점검 (15분)

사내 양식은 대부분 Excel이나 Word입니다. 도구가 파일을 열고 저장할 때 사라지는 것이 없는지 먼저 확인합니다. 이 스크립트는 파일을 열었다가 저장해 보고 사라진 내부 부분을 찾습니다.

Terminal
mkdir -p scripts
cat > scripts/template_probe.py <<'WV2EOF'
#!/usr/bin/env python3
"""양식 호환성 점검. 양식을 openpyxl로 열고 저장했을 때 사라지는 것이 있는지 실제로 확인한다.
사용: python3 scripts/template_probe.py template/월간점검보고서_양식.xlsx
종료 코드: 0 안전 / 1 주의 요소 있음 / 2 사용 오류
점검 1) 왕복 검사: 열었다가 저장한 파일과 원본의 내부 부품 목록을 비교해 사라진 부분을 찾는다.
점검 2) 구조 요약과 주의 요소: 수식, 시트 보호, 매크로, 외부 링크 등.
"""
import os, sys, tempfile, zipfile
from openpyxl import load_workbook

IGNORE = ("docProps/", "xl/calcChain.xml")   # 저장 때마다 다시 만들어지는 부품


def parts(path):
    with zipfile.ZipFile(path) as z:
        return {n for n in z.namelist() if not n.startswith(IGNORE)}


def main(path):
    try:
        before = parts(path)
        wb = load_workbook(path, keep_vba=path.lower().endswith(".xlsm"))
    except Exception as e:
        print(f"열 수 없음: {e}", file=sys.stderr); return 2
    warn = []
    with tempfile.TemporaryDirectory() as d:
        out = os.path.join(d, "roundtrip.xlsx"); wb.save(out)
        lost = sorted(before - parts(out))
    if lost:
        warn.append("왕복 검사에서 사라진 부분: " + ", ".join(lost) + " → 이 양식은 openpyxl로 편집하면 손실이 생김")
    for ws in wb.worksheets:
        formulas = sum(1 for row in ws.iter_rows() for c in row if isinstance(c.value, str) and c.value.startswith("="))
        print(f"시트 '{ws.title}': 범위 {ws.dimensions}, 병합 {len(ws.merged_cells.ranges)}개, 수식 {formulas}개, "
              f"데이터 검증 {len(ws.data_validations.dataValidation)}개, 조건부 서식 {len(ws.conditional_formatting)}개, "
              f"보호 {'켜짐' if ws.protection.sheet else '꺼짐'}")
        if formulas:
            warn.append(f"시트 '{ws.title}': 수식 {formulas}개 (저장 직후에는 계산된 값이 없어 값 대조가 불가능, 수식 자체는 보존됨)")
        if ws.protection.sheet:
            warn.append(f"시트 '{ws.title}': 시트 보호가 켜져 있음")
    names = before
    if any(n.startswith("xl/charts/") for n in names):
        print("정보: 차트가 있음 (왕복 검사에서 보존됐더라도 저장 후 모양을 눈으로 확인)")
    if any(n.startswith("xl/media/") for n in names):
        print("정보: 이미지가 있음 (저장 후 위치와 크기를 눈으로 확인)")
    if any(n.startswith("xl/externalLinks/") for n in names):
        warn.append("외부 링크가 있음: 값이 오래되었을 수 있음")
    if "xl/vbaProject.bin" in names:
        warn.append("매크로(VBA)가 있음: .xlsm으로 열어 keep_vba=True로 저장해야 보존됨")
    if warn:
        print("주의:"); [print(" -", w) for w in warn]; return 1
    print("점검 통과: 왕복 검사에서 사라지는 부분 없음"); return 0


if __name__ == "__main__":
    sys.exit(main(sys.argv[1]) if len(sys.argv) == 2 else (print(__doc__, file=sys.stderr) or 2))

3요구가 바뀌었다: 양식에 '비고' 열 추가 (40분)

현실에서는 양식이 바뀝니다. 양식과 검증이 따로 놀면 검증이 거짓 안심을 줍니다. 둘을 함께 바꾸게 시킵니다.

Claude 세션 입력
새 규제 요구로 보고서 양식에 '비고' 열을 H열에 추가해야 해.
1) template/월간점검보고서_양식.xlsx에 H3 머리글 '비고'와 H4:H7 노란 입력 칸을 같은 서식으로 추가하고 A1:G1 제목 병합은 유지해.
2) scripts/reconcile.py를 고쳐 H4:H7은 문자열을 허용하되(비어 있어도 됨) 기존 숫자 대조와 양식 훼손 탐지는 그대로 유지해.
3) 수정 후, 비고에 '점검 완료'를 넣은 정상 보고서는 통과하고 제목이나 열 너비를 바꾼 보고서는 실패하는지 직접 만들어 확인해. 확인 결과를 표로 알려줘.
참고 측정값 (sonnet-5.5, 13턴, 약 70초, 0.43달러)
수정 후 Claude가 직접 만들어 확인한 케이스 10개가 모두 기대대로 나왔고, 제가 따로 확인한 4개도 일치했습니다.
비고 '점검 완료' → 통과 / 비고 비움 → 통과 / 제목 변경 → 실패 / 열 너비 변경 → 실패 / 병합 해제 → 실패
채움색 변경 → 실패 / 비고에 숫자 123 → 실패 / 숫자 틀림 → 실패
make_seed.py를 다시 실행하지 마세요make_seed.py는 template/을 예전 모양(H열 없음)으로 다시 만들어 덮어씁니다. 양식을 바꾼 뒤에는 실행하지 않습니다(Claude도 측정 중 이를 먼저 경고했습니다).
4검증 스크립트를 검증하기: 음성 시험 (30분)

"통과"만 보면 스크립트가 맞는지 알 수 없습니다. 일부러 틀린 보고서를 만들어 스크립트가 잡는지 확인합니다. 이것을 음성 시험이라고 합니다.

Claude 세션 입력
scripts/reconcile.py가 놓칠 수 있는 오류 유형 5가지를 찾아줘. 그중 3개는 실제로 그런 보고서를 만들어 스크립트가 잡는지 확인하고, 못 잡는 것이 있으면 스크립트를 고쳐줘. 결과는 '오류 유형 | 잡힘/놓침 | 조치' 표로 알려줘.

관찰할 것: 모델이 제시한 오류 유형 중 스크립트가 놓친 것이 있는가? 놓쳤다면 그것은 사람이 봐야 하는 부분이 아닌가?

5(선택) Word 양식 (15분)

Word 양식은 별도 문서 Skill이 필요합니다. 공식 문서와 저장소 기준으로 마켓 등록과 설치는 다음과 같습니다(외부 접근이 필요하며 이 자료에서는 실행하지 않았습니다).

Claude 세션 입력
/plugin marketplace add anthropics/skills
/plugin install document-skills@anthropic-agent-skills

그 Skill은 기존 .docx 편집 시 압축을 풀어 내부 XML을 고치고 검증 스크립트로 확인하는 경로를 안내합니다. 임의의 사내 양식을 그대로 편집한다는 보장은 문서에 없고, 라이선스가 독점(Proprietary)이므로 재배포 전에 확인이 필요합니다.

트랙 A-1 체크포인트
보너스 (먼저 끝낸 분)
  • 비고 열에 '필수 입력' 규칙을 추가하고(비어 있으면 실패) 기존 정상 보고서가 어떻게 되는지 봅니다.
  • 지점이 4개로 늘어난 경우를 시뮬레이션해 양식, 데이터, 검증을 함께 확장해 봅니다.
힌트 (막혔을 때)
  • Claude가 양식을 망가뜨림: 양식 복사부터 다시 시키고 '노란 칸만 채움' 규칙을 CLAUDE.md에서 확인하세요.
  • 스크립트 수정 후 정상 보고서도 실패: 정상 보고서를 양식에서 새로 만들었는지 확인하세요(예전 양식으로 만든 파일은 H열이 없어 훼손으로 판정됩니다).
검증 기록 (2026-10-21, Claude Code 2.1.306)

양식 호환성 점검을 정상 양식, 차트·수식·보호가 있는 양식, 매크로 부품이 있는 양식에서 실행해 왕복 검사가 실제 손실만 보고하는 것을 확인했습니다.

비고 열 추가 요구를 Claude가 13턴에 수행했고, 수정된 스크립트를 제가 독립적으로 시험해 정상·오류·양식 훼손·비고 형식 위반을 올바르게 판정하는 것을 확인했습니다.

실제 사내 양식(복잡한 수식, 매크로, 보호, 외부 링크)은 검증하지 못했습니다.

Word 문서 Skill 설치와 .docx 편집은 실행하지 않았습니다.

음성 시험의 '놓치는 오류 유형'은 모델 답변에 따라 달라 결과를 고정해 적지 않았습니다.
