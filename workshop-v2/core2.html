검증 서브에이전트와 Stop 게이트

산술은 결정적 스크립트가 하고, 통과 전에는 끝내지 못하게 강제합니다.

70분개념 2개 (서브에이전트, 훅)

이 블록에서 하는 일

컴플라이언스 담당자의 질문, "숫자가 틀리면 바로 문제라 매번 눈으로 대조합니다. 자동으로 검증하는 방법이 있나요?"에 답합니다. 핵심은 산술은 모델이 아니라 결정적 스크립트가 하고, 통과 전에는 끝내지 못하게 강제한다는 것입니다.

항목내용
시간70분 (설명 15 + 실습 55)
이어서코어 1의 폴더와 output/월간보고.xlsx를 그대로 씁니다
완료 기준일부러 심은 오류가 자동으로 잡히고, 고친 뒤에야 작업이 끝난다

설명 15분

규칙(CLAUDE.md)은 부탁이고 게이트는 강제입니다. 현대 모델은 규칙을 대체로 지키고 스스로 검산하기도 하지만, 매번 보장되지는 않습니다. 그래서 사람 대신 보는 마지막 방어선이 필요합니다. 훅의 종료 코드는 위치마다 뜻이 다릅니다.

위치exit 2의 의미쓰임
PreToolUse도구 실행 전에 차단위험한 호출 막기
PostToolUse이미 실행된 뒤. 차단이 아님, stderr를 Claude에게 전달구문 오류를 알려 스스로 고치게 하기 (오류를 알려 스스로 고치게 하는 피드백 루프)
StopClaude가 멈추지 못하고 계속 작업검증 통과 전에는 끝내지 못하게 하기
onFailure: "block" (v2.1.295+)command·http 훅이 실패하면 exit 2처럼 차단훅 자체가 실패해도 통과시키지 않기

실습

1대조 스크립트가 잡는 것 확인

코어 1에서 만든 보고서에 일부러 오류를 심고 대조합니다.

Terminal
mkdir -p scripts
cat > scripts/inject_error.py <<'WV2EOF'
#!/usr/bin/env python3
"""연습용: 보고서에 일부러 숫자 오류 1개를 심는다. 사용: python3 scripts/inject_error.py output/월간보고.xlsx"""
import sys
from openpyxl import load_workbook
p = sys.argv[1]
wb = load_workbook(p); ws = wb["월간보고"]
before = ws["D7"].value; ws["D7"] = before + 3   # 합계 의심건수를 3만큼 틀리게
wb.save(p); print(f"D7 합계 의심건수 {before} -> {before + 3} (일부러 틀림)")
WV2EOF
chmod +x scripts/inject_error.py

python3 scripts/inject_error.py output/월간보고.xlsx
python3 scripts/reconcile.py output/월간보고.xlsx; echo "exit=$?"
기대 출력
D7 합계 의심건수 57 -> 60 (일부러 틀림)
대조 실패 (1건)
 - 숫자 불일치 D7 [합계 의심건수]: 보고서=60 기대=57
exit=1

이 스크립트는 숫자 24칸뿐 아니라 양식 훼손(제목 변경, 열 너비, 서식)과 문자열로 저장된 숫자(예: '1381')도 잡습니다. 종료 코드는 0 일치, 1 불일치, 2 사용 오류입니다.

2읽기 전용 검증 서브에이전트

검증자는 파일을 고치지 못하고 대조 스크립트만 실행해야 합니다. 정의 파일의 tools에 쓴 Bash(...) 형식은 공식 문서에 기재되어 있지 않고 이 자료의 측정에서 동작했을 뿐이므로, 확실한 제한은 허용·거부 규칙이나 PreToolUse 훅으로 겁니다. 아래 허용 규칙과 지침이 그 역할을 합니다.

Terminal
mkdir -p .claude/agents
cat > .claude/agents/report-verifier.md <<'WV2EOF'
---
name: report-verifier
description: 월간 보고서를 읽기 전용으로 검증하고 PASS/FAIL 표로 보고한다. 보고서를 완료로 선언하기 전에 사용한다.
tools: Read, Grep, Glob, Bash(python3 scripts/reconcile.py *)
model: haiku
maxTurns: 6
---
당신은 읽기 전용 검증자다. 어떤 파일도 수정하지 않는다.

1. 아래 명령을 **정확히 그대로, 한 줄로만** 실행한다. `cd`, `&&`, `;`, `echo` 등을 붙이지 않는다. 허용 규칙이 이 모양과 일치할 때만 실행된다.

   `python3 scripts/reconcile.py output/월간보고.xlsx`

2. 출력을 `항목 | 결과(PASS/FAIL) | 근거` 표로 보고한다. 근거는 스크립트 출력만 쓰고 추측하지 않는다. 출력이 "대조 통과"로 시작하면 PASS, "대조 실패"로 시작하면 FAIL이다.
3. 마지막 줄에 `최종: PASS` 또는 `최종: FAIL`을 쓴다. 명령이 실행되지 않았다면 판정하지 말고 `최종: 미검증`이라고 쓴다.
WV2EOF

Python 실행을 승인 없이 허용하는 규칙을 .claude/settings.json에 추가합니다.

Terminal
cat > .claude/settings.json <<'WV2EOF'
{
  "permissions": {
    "allow": [
      "Bash(python3 scripts/reconcile.py *)"
    ]
  }
}
WV2EOF

세션에서 보고서를 정상 상태로 되돌린 뒤(코어 1의 방법으로 다시 생성) 요청합니다.

Claude 세션 입력
report-verifier 서브에이전트에게 output/월간보고.xlsx 검증을 맡기고, 그 결과 표를 그대로 보여줘.
기대 출력 (정상 보고서)
| 항목 | 결과(PASS/FAIL) | 근거 |
| reconcile.py 대조 (output/월간보고.xlsx) | PASS | 대조 통과: 숫자 24칸 일치, 양식 보존 |

최종: PASS
tools와 허용 규칙은 다릅니다서브에이전트의 tools는 쓸 수 있는 도구의 목록일 뿐 승인 없이 실행한다는 뜻이 아닙니다. 승인 없이 실행하려면 허용 규칙이 따로 필요합니다(--tools와 --allowedTools의 차이와 같은 구분). 허용 규칙은 명령 모양이 일치할 때만 적용됩니다. 측정 중 서브에이전트가 cd ... ; echo $?를 덧붙이자 규칙에 맞지 않아 막혔습니다. 그래서 검증자 정의에 '정확히 이 한 줄만 실행'을 적었습니다.
프로젝트 허용 규칙은 폴더 신뢰 뒤에 적용됩니다.claude/settings.json의 허용 규칙은 신뢰 대화상자를 수락한 뒤에만 적용됩니다. 대화형 세션에서는 코어 1에서 이미 수락했습니다. claude -p는 대화상자가 없어 규칙이 보류되므로 --allowedTools "Bash(python3 scripts/reconcile.py *)" 플래그나 추적되지 않는 settings.local.json을 씁니다.
3Stop 게이트로 강제하기

보고서에 대조가 통과하기 전에는 Claude가 끝낼 수 없게 합니다. 3번 고쳐도 안 되면 사람이 보도록 표시 파일을 남깁니다.

Terminal
mkdir -p scripts
cat > scripts/stop_gate.sh <<'WV2EOF'
#!/usr/bin/env bash
# Stop 훅: 보고서가 있으면 대조 스크립트로 검증한다.
# 불일치면 exit 2로 Claude가 멈추지 못하게 하고, 3번 고쳐도 안 되면 사람이 보도록 표시 파일을 남긴다.
cd "${CLAUDE_PROJECT_DIR:-.}" || exit 0
REPORT="output/월간보고.xlsx"
COUNT_FILE=".claude/.gate_count"
[ -f "$REPORT" ] || exit 0

msg=$(python3 scripts/reconcile.py "$REPORT" 2>&1); rc=$?
if [ "$rc" -eq 0 ]; then
  rm -f "$COUNT_FILE" "output/검증실패.txt"
  exit 0
fi

n=$(( $(cat "$COUNT_FILE" 2>/dev/null || echo 0) + 1 ))
echo "$n" > "$COUNT_FILE"
if [ "$n" -gt 3 ]; then
  printf '자동 검증 실패: 3회 수정 후에도 대조가 통과하지 않았습니다. 사람이 확인하세요.\n%s\n' "$msg" > "output/검증실패.txt"
  exit 0
fi
printf '대조 스크립트가 불일치를 찾았습니다. 보고서를 고친 뒤 다시 완료하세요 (%s/3).\n%s\n' "$n" "$msg" >&2
exit 2
WV2EOF
chmod +x scripts/stop_gate.sh
Terminal, .claude/settings.json 전체 교체
cat > .claude/settings.json <<'WV2EOF'
{
  "permissions": {
    "allow": [
      "Bash(python3 scripts/reconcile.py *)"
    ]
  },
  "hooks": {
    "Stop": [
      { "hooks": [ { "type": "command", "command": "$CLAUDE_PROJECT_DIR/scripts/stop_gate.sh" } ] }
    ]
  }
}
WV2EOF

이제 "파이프라인의 한 단계가 보고서를 망가뜨린 상황"을 만듭니다. 새 세션에서 요청합니다.

Terminal
python3 scripts/reconcile.py output/월간보고.xlsx   # 정상인지 먼저 확인
claude
Claude 세션 입력
python3 scripts/inject_error.py output/월간보고.xlsx 를 실행하고, 끝나면 '완료'라고 답해줘.
관찰 포인트
Claude가 오류를 심은 뒤 "완료"라고 하려 하면 → Stop 훅이 대조 실패 메시지와 함께 막는다
→ Claude가 D7을 57로 되돌린다 → 대조 통과 후에야 종료
(측정 결과: 5턴, 약 0.015달러. Claude가 "이전 답변에서 '완료'라고 한 것은 오류가 있는 상태였으니 잘못된 답이었다"고 스스로 정정했다)
4세 겹 방어 정리
겹수단한계
1CLAUDE.md 규칙부탁이라 어길 수 있음
2Stop 게이트 + 대조 스크립트스크립트가 아는 규칙만 검증
3사람의 확인게이트가 통과한 결과에서 샘플로
솔직한 측정 결과이 실습을 준비하며 같은 오류를 모델에게 보여 주자 모델이 스스로 검산해서 불일치를 지적한 경우가 많았고, 사람이 틀린 숫자(60)를 지시해도 데이터와 CLAUDE.md를 근거로 거부했습니다. 게이트는 '모델이 못 잡는 것을 잡는 장치'가 아니라 모델의 성실성에 의존하지 않고 어떤 경우에도 강제하는 장치입니다. 반대로 모델이 수정 자체를 하지 않으면 훅은 발동하지 않습니다.
코어 2 체크포인트
보너스 (먼저 끝낸 분)
  • 양식을 해치는 요청(열 너비 변경, 제목 수정)을 직접 시키고 어떤 메시지로 막히는지 봅니다.
  • Stop 훅 대신 /goal로 'reconcile.py가 종료 코드 0을 낼 때까지'를 조건으로 걸어 비교합니다(공식 문서 기준, 이 자료에서는 실행하지 않았습니다).
힌트 (막혔을 때)
  • 훅이 안 돈다: 스크립트에 실행 권한(chmod +x)이 있는지, .claude/settings.json 경로가 맞는지, 폴더 신뢰를 수락했는지 확인하세요.
  • 서브에이전트가 Bash 승인 대기: 허용 규칙을 추가했는지, 명령이 '정확히 한 줄'인지 확인하세요.
  • 무한히 고치려 한다: 게이트는 3회까지만 막고 output/검증실패.txt를 남깁니다.
검증 기록 (2026-10-21, Claude Code 2.1.306)

대조 스크립트: 정답 통과(exit 0), 숫자 오류(exit 1), 양식 훼손 3종(제목·열 너비·서식, exit 1), 문자열 숫자(exit 1), 파일 없음(exit 2).

Stop 게이트: 오류를 심고 '완료'를 요청하자 훅이 막았고 Claude가 57로 되돌려 대조가 통과했습니다(5턴).

검증 서브에이전트: 정상 보고서는 PASS, 오류 보고서는 FAIL과 근거 출력을 보고하고 파일을 수정하지 않았습니다.

허용 규칙 보류: -p에서 '이 작업 공간이 신뢰되지 않아 permissions.allow를 무시한다'는 경고를 확인했습니다.

대화형 화면에서의 훅 동작은 직접 보지 못했습니다. /goal 대안은 실행하지 않았습니다.
