코어 3 · 비용과 통제

모델과 effort, 컨텍스트, 하드 스톱

비용은 모델 단가, 캐시, 컨텍스트가 함께 만듭니다. 측정으로 확인하고, 가능한 것과 불가능한 것을 구분합니다.

70분개념 1개 (모델·effort)

이 블록에서 하는 일

설문에서 가장 많았던 주제(비용·토큰 8건)에 답합니다. "서브에이전트를 쓰면 비용이 기하급수적으로 늘어난다", "Bedrock이 구독보다 훨씬 비싸다", "비용을 엄격히 통제할 수 있나"를 측정값으로 봅니다.

항목내용
시간70분 (설명 15 + 실습 55)
완료 기준모델별 비용 차이와 캐시 상태에 따른 요동을 측정하고, '가능 / 불가능 / 검증 필요'를 구분해 내 팀 규칙 3줄을 쓴다

설명 15분: 비용은 이렇게 생깁니다

  • 비용은 입력, 출력, 캐시 생성, 캐시 읽기 토큰의 합입니다. 사소한 작업도 시스템 프롬프트, 도구 설명, CLAUDE.md, 스킬 목록이 실려 컨텍스트가 큽니다.
  • 같은 작업이라도 모델 단가, effort, 캐시 상태에 따라 크게 달라집니다.
  • 서브에이전트는 별도 컨텍스트를 가지므로 호출마다 비용이 추가됩니다. 모델과 턴 수를 제한하지 않으면 늘어납니다.

실습

1같은 작업을 모델별로, 두 번씩 측정

스크립트가 haiku, sonnet, opus로 같은 작은 작업을 두 번씩 실행해 비용과 토큰 구성을 표로 보여 줍니다. 모델 호출이 실제로 일어납니다.

Terminal, 코어 1의 폴더에서
mkdir -p scripts
cat > scripts/cost_compare.py <<'WV2EOF'
#!/usr/bin/env python3
"""같은 작업을 모델별로 두 번씩 실행해 비용과 토큰 구성을 비교한다. 모델 호출이 실제로 일어난다.
사용: python3 scripts/cost_compare.py [--safe-mode]    (--safe-mode: 플러그인·CLAUDE.md 등을 끄고 깨끗한 기준으로 측정)
출력의 비용은 Claude Code의 클라이언트 측 추정치이며 실제 청구액과 다를 수 있다."""
import json, subprocess, sys

PROMPT = "data/gangnam.csv의 판매건수 합계를 Python으로 계산해서 숫자만 답해."
extra = ["--safe-mode"] if "--safe-mode" in sys.argv else []
print("모델 | 회차 | 비용(USD) | 캐시 생성 토큰 | 캐시 읽기 토큰 | 출력 토큰 | 턴")
for model in ["haiku", "sonnet", "opus"]:
    for n in (1, 2):
        p = subprocess.run(
            ["claude", "-p", PROMPT, *extra, "--model", model, "--effort", "low", "--permission-mode", "acceptEdits",
             "--allowedTools", "Bash(python3:*)", "Read", "--max-budget-usd", "1.5", "--output-format", "json"],
            capture_output=True, text=True, stdin=subprocess.DEVNULL, timeout=300)
        try:
            d = json.loads(p.stdout); u = next(iter(d["modelUsage"].values()))
        except Exception:
            print(f"{model} | {n} | 실패: {p.stderr.strip()[:100]}"); continue
        print(f"{model} | {n} | {u['costUSD']:.4f} | {u['cacheCreationInputTokens']} | {u['cacheReadInputTokens']} | {u['outputTokens']} | {d['num_turns']}", flush=True)
WV2EOF

관찰 질문: ① 같은 모델끼리 비교하면 어느 회차가 비싼지 매번 다릅니다. 비용 차이를 만드는 열은 어느 것인가? (캐시 생성 토큰) ② 모델 사이의 비율은 어떤가? (캐시가 따뜻할 때 haiku : sonnet : opus는 약 1 : 8 : 16, 처음 값은 약 1 : 14 : 27) ③ 작업이 사소한데도 왜 수만 토큰이 읽히는가?

캐시는 믿을 수 있는 할인이 아니라 변수입니다기본 캐시 유지 시간이 지나거나 앞부분(시스템 프롬프트, 도구 설명, CLAUDE.md)이 바뀌면 캐시가 다시 만들어져 비용이 뛰어오릅니다. 그래서 '같은 작업의 비용'은 한 번의 측정이 아니라 여러 번의 범위로 말해야 합니다.
2컨텍스트가 비용을 좌우한다

이번에는 --safe-mode를 빼고 실행해 보세요. 플러그인, 스킬, MCP가 많을수록 기준 컨텍스트가 커집니다. 세션 안에서는 /context로 내용을 볼 수 있습니다.

환경컨텍스트(캐시 생성 + 읽기)sonnet-5.5 1회 비용
깨끗한 기준 (--safe-mode)약 5,600 + 29,000 토큰0.0272
플러그인·스킬이 많은 개발 환경약 49,600 + 70,000 토큰0.207 (같은 호출 재실행 0.076)
숫자를 그대로 믿지 마세요위 표는 이 자료를 준비한 환경의 값입니다. 가격표와 환경이 다르면 숫자가 달라집니다. 배울 것은 비율, 캐시 효과, 컨텍스트의 영향입니다.

상한 0.004달러에 0.0198달러가 나갔습니다예산은 턴이 끝난 뒤 검사하므로 한도를 넘겨서 멈춥니다(이 측정에서 약 5배). 상한은 작업 하나의 비용보다 여유 있게 잡고(공식 문서도 headroom을 권장), 서브에이전트 비용도 합산됩니다. 사용자·팀 단위의 한도가 아니라 실행 한 번의 안전장치입니다.

6내 팀 비용 규칙 3줄 쓰기

아래 틀에 내 팀의 규칙을 채워 옆 사람과 비교합니다.

메모
1. 기본 모델은 ____, 어려운 계획·설계에만 ____ 를 쓴다.
2. 탐색·검증용 서브에이전트는 model: ____, maxTurns: ____ 로 제한한다.
3. 자동 실행(-p, CI)에는 항상 --max-budget-usd ____ 와 --max-turns ____ 를 건다.
코어 3 체크포인트
보너스 (먼저 끝낸 분)
  • effort를 low, high로 바꿔 같은 작업의 비용을 비교합니다. 사소한 작업에서는 effort가 비용을 일정하게 바꾸지 않는다는 점을 관찰합니다(opus 측정: low 0.463, high 0.416).
  • 작업을 모델별로 나누는 규칙(탐색은 haiku, 구현은 sonnet, 설계는 opus)을 서브에이전트 정의로 만들어 봅니다.
힌트 (막혔을 때)
  • 비용이 0으로 나온다: 구독 계정은 구독 한도 내 사용이라도 목록가 추정치를 보여 줍니다. 실제 청구는 계정 종류에 따라 다릅니다.
  • 스크립트가 실패한다: claude가 PATH에 있는지, 모델 호출이 되는지 프리플라이트를 다시 실행하세요.
검증 기록 (2026-10-21, Claude Code 2.1.306)

모델별 2회 측정을 두 시점에 반복해 캐시 상태에 따라 비용이 요동하는 것을 확인했고, 컨텍스트 크기 차이, 서브에이전트 모델별 비용, 하드 스톱의 한도 초과(0.004 → 0.0198)도 실제 실행으로 확인했습니다. cost_compare.py와 페이지의 jq 명령은 그대로 실행했습니다.

--safe-mode가 플러그인과 CLAUDE.md를 끄므로 깨끗한 기준으로 쓸 수 있음을 확인했습니다. 단 --settings로 넣은 훅도 함께 꺼집니다.

Bedrock 직접 사용 단가, 1시간 캐시 TTL 배수, 애플리케이션 추론 프로파일 태그의 반영 지연은 확인하지 못했습니다.

대화형의 /usage, /context 화면은 직접 보지 못했습니다.
