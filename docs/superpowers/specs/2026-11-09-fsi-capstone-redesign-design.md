## 1. 의도

지금 캡스톤(Press Start 게임, Frame It 미술관, Quake Watch, Market Desk, Trend Radar, Newsroom Lens, Playbook Foundry)은 "멋진 것을 빨리 만들어 CloudFront에 올리기"에 가깝다. 강의에서 배운 Subagent, Skill, Plugin, 가드레일이 결과물에 잘 드러나지 않는다.

새 캡스톤은 **Claude Code로 프로덕션 품질의 작업을 하는 방법**을 익히는 시간이다 (사용자). 결과물의 화려함이 아니라, 교육생이 배운 것(plugin, skill, agent, harness)을 직접 만들어 하나의 재사용 가능한 도구로 완성하는 것이 핵심이다. 거버넌스와 DLP 자체는 Ch2 랩에서 충분히 다루므로 캡스톤의 초점이 아니다 (사용자). 다만 교육생이 만드는 도구에는 가드레일이 들어간다.

**성공의 모습** (사용자): 교육생이 본인만의 agents를 만들고, 계속 쓸 수 있는 plugin을 사내(마켓플레이스)에 배포해 사용하며, 공통으로 쓰는 가드레일을 만든다.

**진짜 결과물** (사용자): 재사용 가능한 plugin, 또는 agent + skill + MCP 세트다. 앱이나 문서는 그 plugin이 제대로 동작한다는 것을 보여 주는 재료다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 교육생 한 명이 하나의 plugin을 만든다. 안에는 자기 agents, skills, MCP 연결(또는 직접 만든 MCP 서버), 가드레일 훅이 들어 있다.
- 그 plugin을 마켓플레이스에 올리고, 새 폴더(동료 입장)에서 설치해 쓴다.
- 같은 plugin 하나로 **서로 다른 반복 업무를 두 가지 이상** 해 낸다 (사용자가 든 예: 데이터 분석, 기획안 작성, AgentCore를 활용한 앱).
- 가드레일이 실제로 막는 장면을 교육생이 직접 확인한다.

**비목표**
- 캡스톤에서 새 기능을 강의하지 않는다. AgentCore도 설명 없이 쓸 수 있게 도구만 깔아 둔다 (사용자).
- AgentCore 배포를 강제하지 않는다 (사용자). 쓰지 않아도 완주다.
- 팀 협업 과정이 아니다. 한 사람이 한 팀이다 (사용자).
- 거버넌스와 DLP 이론의 반복이 아니다 (사용자).

**반목표** (돌아가도 실패로 보는 경우) (설계자)
- 결과물이 한 번 쓰고 버리는 스크립트나 데모 앱뿐이고, plugin으로 묶여 다시 설치되지 않는다.
- 두 번째 업무에서 agent나 skill을 처음부터 다시 짠다 (재사용이 증명되지 않음).
- 가드레일이 문서에만 있고 실제로 아무것도 막지 않는다.
- 빠른 결과를 위해 API 키나 개인정보가 plugin 저장소나 Slack 출품물에 그대로 남는다.
- 화려한 UI를 만드느라 R2 시간을 다 쓰고 배포와 재사용 단계를 못 한다.

## 4. 미션 고르기: R1은 데이터 미션 하나, R2는 재사용 미션 두 개 이상

이전 캡스톤처럼 라운드마다 고를 수 있는 예시 미션을 둔다 (사용자: "R1, R2에 한 개씩만이 아니라 두세 개로 고를 수 있게, 이전처럼"). R1에서는 **무엇을 다룰지**, R2에서는 **어떻게 다시 쓸지**를 고른다 (사용자가 승인한 방향).

| 미션 | 데이터 (트랙) | 만들 agents (예) | 가드레일 (예) |
|---|---|---|---|
| R1-A 고객 맞춤 서비스 | 마이데이터 (A, 랩 Ch3 체크포인트에서 출발) | 고객 한 명의 자산과 소비를 보는 상담 준비 agent, 읽기 전용 검토 agent | 주민번호, 계좌 등 개인정보 차단, 원본 `raw/` 접근 차단 |

### 4.1 데이터 트랙

교육생은 아래 셋 중 하나를 고른다 (사용자: "마이데이터를 활용하거나, 서울 공공데이터 부동산 정보, 혹은 다른 MCP를 붙이는 데이터"). 모든 트랙의 끝은 같다. plugin 하나와 그 plugin으로 해 낸 업무 두 가지 이상이다.

| 트랙 | 데이터 | 데이터에 닿는 방법 | 가드레일이 지킬 대상 (설계자) |
|---|---|---|---|
| A. 마이데이터 확장 | 랩에서 쓰는 합성 마이데이터 (`~/claude-lab/mydata/`, 가명처리본 `pseudo/`) | 파일. 또는 데이터를 감싼 MCP 서버를 직접 만든다 | 개인정보 패턴(주민번호, 카드, 계좌, 휴대폰), 원본 `raw/` 접근 |
| B. 서울 공공데이터 MCP 직접 만들기 | 서울 열린데이터광장의 부동산 정보 (예: 실거래가, 전월세) (사용자) | 공공데이터 API를 감싸는 MCP 서버를 직접 만든다 (사용자) | API 키 노출, 호출 대상과 횟수, 결과에 섞이는 개인 식별 정보 |
| C. 제공되는 MCP 연결 | MCP를 공식 제공하는 서비스의 데이터. 교육생이 자유롭게 고르고, 운영 측은 추천 MCP 목록을 제안한다 (사용자) | 이미 있는 MCP 서버에 연결 | 연결해도 되는 MCP 서버 허용 목록, 외부 호출 범위, 응답의 민감 정보 |

트랙 A의 출발점 (설계자): R1은 Day 1이라 Ch4의 킷이 아직 없다. R1은 **Ch3 체크포인트**(랩의 분석 에이전트 3종, `segments.md`, Ch2의 DLP 스크립트)에서 시작하고, R2에서 Ch4의 "자산분석팀 킷"(옆 세션 설계 5절 4장)을 바탕으로 삼아도 된다. 단, 체크포인트의 에이전트를 쓰는 것만으로는 완주가 아니다. **자기 agent를 새로 하나 이상**(R1), **자기 skill을 새로 하나 이상**(R2) 만들어 넣는다. 체크리스트 1번의 "자기 Subagent 2개 이상"은 트랙 A에서 "새로 만든 1개 이상 + 체크포인트에서 가져와 고친 것"으로 센다. 랩의 첫 번째 일(연금상품 기획)과 다른 두 번째 일(예: 고객별 맞춤 서비스 제안)로 재사용을 보이는 것이 자연스럽다 (설계자).

트랙 B와 C는 같은 구조를 새 영역에서 처음부터 세운다.

## 5. R1: 에이전트와 가드레일 (110분)

R1이 끝났을 때 있어야 하는 것 (사용자: "R1은 에이전트와 가드레일")
- 고른 데이터를 다루는 **자기 Subagent 2개 이상**. 역할이 겹치지 않고, 도구 권한이 역할에 맞게 좁혀져 있다 (Ch3 내용). 최소 하나는 읽기 전용 검토 역할을 권한다 (설계자).
- 데이터에 닿는 경로: 트랙 A는 파일 또는 직접 만든 MCP, B는 직접 만든 MCP 서버, C는 연결된 MCP.
- **가드레일 하나 이상이 실제로 막는다.** 훅(PreToolUse 등, Ch2 Lab 2에서 만든 방식)이나 권한 deny 규칙으로 4장의 "지킬 대상"을 막고, 막히는 장면을 직접 확인한다. fail-closed(오류 경로도 exit 2)를 지킨다.
- 이 작업 폴더의 `CLAUDE.md`(짧게)와 설정이 정리돼 있다. 여기까지가 R2에서 plugin으로 묶을 재료다.

권장 진행 (설계자): superpowers의 brainstorm → plan → execute 흐름을 쓴다. 단, brainstorm의 주제는 "무슨 앱을 만들까"가 아니라 "어떤 반복 업무를 맡길 agents와 무엇을 막을 가드레일"이다.

## 6. R2: 플러그인 배포와 재사용 (180분)

R2가 끝났을 때 있어야 하는 것 (사용자: "R2는 플러그인 배포와 재사용"). 4장의 재사용 미션 중 두 개 이상을 고른다.
- R1의 agents, 새로 만든 skill(반복 업무의 절차와 출력 형식을 담음) 하나 이상, MCP 설정, 가드레일 훅을 **plugin 하나로 묶는다** (Ch4 내용).
- plugin을 **마켓플레이스에 올리고**, 새 폴더에서 동료처럼 `/plugin marketplace add`와 `/plugin install`로 설치해 쓴다. 마켓플레이스는 Ch4 랩처럼 로컬 디렉터리 마켓플레이스로 시작하고, 가능하면 git 저장소로 올린다 (설계자).
- 설치한 plugin으로 **서로 다른 반복 업무 두 가지 이상**을 해 낸다. 4장의 R2-1, R2-2, R2-3이 이것이며, 사용자가 든 예에서 나왔다:
  - 데이터 분석 (MCP로 가져온 데이터에서 지표와 결론)
  - 기획안 작성 (분석 결과를 skill이 정한 형식의 문서로)
  - AgentCore를 활용한 앱 (같은 agent와 skill을 AgentCore에 올려 Claude Code 밖에서 도는 앱으로). 선택이다 (사용자). 실습 EC2가 Administrator 권한이라 배포는 가능하다 (사용자). 안내는 aws-agents 플러그인으로 배포하는 검증된 한 경로를 두고, 끝나면 만든 리소스를 지우는 단계를 넣는다 (설계자).
- 두 번째 업무에서 agent와 skill을 다시 짜지 않았다는 것을 보일 수 있어야 한다.
- 가드레일이 plugin과 함께 따라와서, 설치한 새 폴더에서도 막힌다.

가드레일의 강제력 (설계자): plugin 훅은 사용자가 끌 수 있다. 조직이 강제하려면 Ch2의 managed 정책으로 내린다는 한 문장을 R2 안내에 둔다. 마이데이터 랩 설계 9절과 같은 입장이다.

## 7. 완주 기준과 출품

**완주 체크리스트** (설계자, 사용자 기준을 풀어 쓴 것)
1. 자기 Subagent 2개 이상, 도구 권한이 역할에 맞게 좁혀져 있다.
2. skill 하나 이상 (반복 업무의 절차와 출력 형식).
3. 데이터 경로: MCP 연결 또는 직접 만든 MCP 서버 (트랙 A는 파일도 허용).
4. 가드레일 하나 이상이 실제로 막고, 오류 경로도 막는다 (fail-closed).
5. 위 네 가지가 plugin 하나에 묶여 마켓플레이스에서 설치된다 (새 폴더에서 확인).
6. 그 plugin으로 R2 재사용 미션 두 개 이상을 해 냈다.

## 9. 제약

- 실습 환경: ccb-endpoint(code-server), Claude Code 2.1.x, Amazon Bedrock, Claude Apps Gateway. 인터넷은 모두 열려 있다 (사용자). SETUP의 플러그인 다운로드와 공공데이터 API 호출이 가능하다.
- 서울 공공데이터 API 키는 교육생이 직접 받는다 (사용자). 트랙 B 안내의 첫 단계를 키 발급으로 두고, 발급을 기다리는 동안 샘플 데이터와 mock 모드로 MCP 골격을 먼저 만들게 한다 (설계자). 키는 환경 변수나 사용자 설정으로만 넣고, plugin 저장소에 들어가지 않는 것을 가드레일로 확인한다.
- 권한 (사용자): 실습 EC2는 Administrator 권한이다. 그래서 Claude가 AWS를 바꾸는 명령도 막힘없이 실행된다 (설계자 판단). 가드레일 예시에 "지우거나 비용이 큰 AWS 작업은 확인을 받는다" 같은 규칙(권한 ask 규칙이나 훅)을 하나 넣을 것을 권한다.
- 인원: 한 사람이 한 팀 (사용자). 진행은 각자 속도로 하되 R1과 R2 끝 시간은 고정이다.
- 랩 1–6장은 마이데이터 이야기로 개편 중이다 (옆 세션). 캡스톤은 그 랩에서 만든 것을 전제로 하되, 랩을 끝내지 못한 사람도 시작할 수 있어야 한다 (설계자: 트랙 B, C는 랩 산출물 없이도 시작 가능, 트랙 A는 랩 체크포인트를 받아 시작).
- 구현 기준 브랜치 (설계자): 마이데이터 랩 개편(브랜치 `docs/mydata-lab-storyline`, 아직 main에 없음)이 먼저 병합된 main 위에서 만든다. 그 전에 만들 경우 트랙 A 페이지는 데이터 경로와 체크포인트 이름만 참조하고, 랩 페이지 링크는 병합 후 맞춘다. `index.html`과 Ch3, Ch4 랩 페이지는 두 작업이 모두 고치므로 같은 시점에 겹치지 않게 한다.
- 외부 데이터 대비 (설계자): 트랙 B와 C는 네트워크나 인증이 막혀도 R1을 끝낼 수 있어야 한다. 트랙 B는 캐시된 샘플 데이터와 MCP 골격의 mock 모드를 함께 준다.
- 문구 규칙: 학습자 페이지의 한국어 원칙을 따른다. 리액티브 덱을 고칠 경우 em dash와 가운뎃점 금지 규칙을 지킨다.
