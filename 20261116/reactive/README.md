# November Reactive Decks: Editing Guide

This guide is for speakers who edit the six November chapter decks themselves,
usually by asking Claude Code. The Remarp sources are `0N-*.md`. The HTML files
are generated output, so never edit them by hand.

| File | Role | Edit? |
| --- | --- | --- |
| `01-ch1-how-it-works.md` … `06-ch6-org-cost.md` | Remarp source, one per chapter | Yes |
| `_presentation.md` | Deck-wide settings (title, speaker, block durations, theme) | Yes |
| `assets/` (`fsi.css`, `ch2.css`…`ch6.css`, `stepviz.js`, `theme-toggle.js`, `chapter-video.js`, `sidebar-toggle.js`, `hide-slides.js`, `deck-keys.js`) | Repository-owned styles and scripts every deck loads | Yes |
| `toc.html` | Hand-maintained chapter index (times, taglines, slide counts) | Yes, directly |
| `0N-*.html`, `index.html` | Generated by the compiler | No, rebuild |
| `common/` | Framework copied from the compiler on every build | No; changes are overwritten |

## Presenter shortcuts

`assets/deck-keys.js` (loaded by `stepviz.js`) makes every shortcut a single key, with no
Option chord. It patches the framework at run time because `common/` is rebuilt.

| Key | Action |
| --- | --- |
| N | Presenter view with notes (was P) |
| G | Slide overview (was O) |
| P / O / I / U / Y | Laser, pen, highlighter, eraser, magnifier (was Option+key); Esc leaves pen mode |
| 1-3 / 4-9 | Stroke size / colour; zoom 1-3 in the magnifier (was Option+digit) |
| C | Clear this slide's drawing (was Option+T) |
| F, S, H, T, / | Fullscreen, sidebar, hide slide, theme, search (unchanged) |

Option chords still work. The keys also work in the presenter window, and N/G also work
with the Korean input method on.

The Ch3 deck loads `assets/ch4.css`, and Ch4 loads `ch5.css`. The style files
kept the pre-renumbering chapter names (see the chapter table in
`AGENTS.md`).

## 1. Install the compiler (once)

The compiler ships in the `aws-content-plugin` from the
`Atom-oh/oh-my-cloud-skills` marketplace. This repository's
`.claude/settings.json` registers that marketplace and enables the plugin.
Trusting the folder registers the marketplace, but a plugin enabled only in
project settings does not load until it is installed on your machine (`/plugin`
lists it under Errors as "enabled in project settings but isn't installed").
Install it once, then run `/reload-plugins`. In Claude Code:

```
/plugin marketplace add Atom-oh/oh-my-cloud-skills
/plugin install aws-content-plugin@oh-my-cloud-skills
```

Or from a shell:

```bash
claude plugin marketplace add Atom-oh/oh-my-cloud-skills
claude plugin install aws-content-plugin@oh-my-cloud-skills
```

Requirements: Python 3 with PyYAML (`python3 -m pip install pyyaml`). The
optional browser checks need Playwright (`python3 -m pip install playwright &&
python3 -m playwright install chromium`).

The plugin includes the `reactive-presentation` skill. Its full syntax
references are under the installed plugin:
`~/.claude/plugins/cache/oh-my-cloud-skills/aws-content-plugin/<version>/skills/reactive-presentation/`.
They cover `REMARP.md`, `references/remarp-format-guide.md` and
`references/authoring-rules.md`.

## 2. Edit, build, check

```bash
20261116/reactive/build.sh validate   # syntax and rule check only
20261116/reactive/build.sh            # validate, then rebuild all decks
```

`build.sh` finds the newest installed compiler. You can point it at a
specific copy with `REMARP_COMPILER=/path/to/remarp_to_slides.py`. It runs
`validate`, stopping on any CRITICAL finding, then `build`. It restores
`toc.html`, because the build overwrites it, and strips trailing whitespace
from the generated HTML. The compiler prints a few dozen style warnings on the
current decks; only new warnings from your change matter.

Preview from the repository root with `python3 -m http.server 8000`, then open
`http://localhost:8000/20261116/reactive/03-ch3-subagents.html`. Add `#N` for
slide N and `?theme=light` for projector mode.

After a deck change:
- Update `toc.html` if a title, tagline or slide count changed.
- Re-export the matching `../slides/ClaudeCode_FSI_ChN_20261116.pdf`. These
  are image-only screenshots, one per slide.
- Keep times consistent. Session `HH:MM` times live in `../eDM.html`; the list
  of places to change with them is in `AGENTS.md`.

## 3. Remarp in five minutes

The decks use a small subset of Remarp:

```markdown
---
<!-- Slide 7: Short English label (keep it; the PDF page mapping uses it) -->
@type: content
@fit: off

## 저장 위치 = 공유 범위
부제는 한 줄, 명사형으로

:::html
<div class="fsi c4-where">…custom HTML using the classes in assets/*.css…</div>
:::

:::script
(window.__fsiq = window.__fsiq || []).push(function (F) {
  // F = window.FSI from assets/stepviz.js: stepviz, countUp, onEnter, bindKeys, …
});
:::

:::notes
{timing: 1.5min}
[요약]
• 발표자가 이 장에서 말할 핵심 두세 개

{cue: demo}
발표 대본. 자연스러운 문장으로.

{cue: transition}
다음 장으로 넘기는 한 문장.

[출처]
• code.claude.com/docs/en/…
:::
```

- A line holding only `---` separates slides. The first slide of each file
  is `@type: cover`, and the last is `@type: thankyou` with `@toc`, `@next`,
  `@next-label` and `@message`.
- `##` is the slide title, and the line after it is the subtitle.
- `:::html` holds the slide body. Use the existing `fsi` component classes
  (`fsi-grid-3/4`, `pick`, `fsi-section`, `fsi-statement`, `fsi-survey`…)
  before writing new CSS. New CSS goes in that chapter's `assets/chN.css`,
  using theme tokens (`var(--accent)`, `var(--text-primary)`…), never raw
  colours.
- `:::script` runs after `stepviz.js` loads. Query elements inside
  `.slide-deck` first: the sidebar clones every slide, so a bare
  `getElementById` can find the thumbnail copy. Step-through visuals register
  ArrowDown and ArrowUp with `F.bindKeys` and reset in `F.onEnter`. Their
  default view must be the complete picture, because the PDF export captures
  each slide as it first appears.
- `:::notes` is required on every slide. It holds `{timing: Nmin}`, then a
  `[요약]` list, a spoken script, and optional `{cue: demo|pause|poll|transition}`
  and `[출처]`. Keep the `{timing}` values of a chapter close to its `duration` in
  `_presentation.md` (Ch3 matches exactly; Ch1 and Ch4 currently run a few
  minutes over).

## 4. House style for these decks

- **Titles (`##`)** are short noun phrases or equations, not sentences ending
  in 다 or 한다. Examples: "저장 위치 = 공유 범위", "배포 전 여섯 가지 점검",
  "원리 6, 캐시 보존". Questions are fine for quiz slides ("tools를 빼면 무엇을
  쓸까?"). Aim for 28 characters or fewer.
- No em dash (U+2014) and no middle dot (U+00B7, U+30FB) in new authored text,
  including notes. Use a comma, colon or parentheses. (Some older slides and
  `toc.html` still contain middle dots.)
- **Opening order:** cover (with the 1분 미리보기 video button), then the
  pre-survey slide, then the agenda. Ch1, Ch3 and Ch4 have survey openings;
  Ch2's survey opens Part 3.
- Facts about Claude Code must match the official docs at code.claude.com/docs
  and the version on the cover. Cite them in `[출처]`.
- Every page opens dark. Light (`T` key or `?theme=light`) is the projector
  mode, so check new colours in both.

## 5. Asking Claude Code to make the change

Open the repository root in Claude Code. `CLAUDE.md` loads `AGENTS.md`, which
points here. Then ask in plain words, for example:

- "Ch3 7번 슬라이드 제목을 '저장 위치와 공유 범위'로 바꾸고 빌드해줘"
- "Ch5 원리 4 장에 발표자 노트 한 문단 추가해줘"
- "Ch2 아젠다 시간을 eDM과 맞춰줘"

Claude edits the `.md` source, runs `build.sh`, previews the slide, and lists
what else must change (toc, PDF, times). Review `git diff` and open a pull
request; see `docs/review.md` for the merge gate.

## Viewer controls

`←` `→` and Space move between slides. `↓` `↑` step through a slide's visual.
`F` is fullscreen, `P` opens the presenter view with notes and timer, `O` is
the overview, `T` toggles dark and light, and `S` or the `‹` `›` tab on the left
edge hides or shows the slide sidebar. The sidebar choice is remembered across
decks.

To skip slides in a talk, right-click a thumbnail in the sidebar and choose
"슬라이드 숨기기" (or press `H` on the slide) before going fullscreen. next and
previous then skip it everywhere, and the presenter view's "Next" preview
shows the next visible slide; clicking its thumbnail (or Home, End, `#N`) still
opens it. "숨긴 슬라이드 모두 보이기" clears only the current chapter's hides. Hidden slides are dimmed in the sidebar, the choice
is saved per chapter slide in this browser (`fsi-hidden-slides`, shared by the
chapter deck and `index.html`), and exports keep every slide.

Step-through visuals (`↓`) must move in reading order: top to bottom, left to
right, or by their printed numbers. When you add or reorder steps, place the
diagram nodes or list items in that same order.
