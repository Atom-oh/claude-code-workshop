Ch5. 비용 효율적으로 쓰기

Hands-on Lab / Chapter 5

Claude Code Deep Dive Workshop, Chapter 5 - 비용 효율적으로 쓰기 (컨텍스트 엔지니어링) 실습

TASK 02 · 출력 필터 훅으로 로그 줄이기 (10분)

테스트나 빌드 로그 전체가 컨텍스트에 들어가는 것을 막고, 실패 줄만 넘기도록 Bash 명령을 바꿔 주는 PreToolUse 훅입니다. 공식 비용 문서의 filter-test-output.sh 예시를 이 프로젝트에 맞게 씁니다.

Step 1 · 시끄러운 테스트 만들기

Terminal, 전체 복사

bash
cd ~/claude-lab/ch6
cat > noisy-test.js << 'EOF'
for (let i = 1; i <= 400; i++) console.log(`ok ${i} - fixture case ${i} passed`);
console.log("FAIL getUserPlan: expected 'pro' but got 'unknown'");
process.exit(1);
EOF
node -e 'const p=require("./package.json");p.scripts["test:all"]="node test.js && node noisy-test.js";require("fs").writeFileSync("package.json",JSON.stringify(p,null,2))'
npm run test:all 2>&1 | wc -l

400줄이 넘는 출력이 나옵니다. 이것이 그대로 Claude의 컨텍스트로 들어갑니다.

Step 2 · 필터 훅 설치

bash
mkdir -p .claude/hooks
cat > .claude/hooks/filter-test-output.sh << 'EOF'
#!/bin/bash
# npm test / npm run test* 를 "그대로" 실행할 때만 실패 줄 중심으로 줄여서 컨텍스트로 넘긴다
input=$(cat)
cmd=$(echo "$input" | jq -r '.tool_input.command // empty')
if [[ "$cmd" =~ ^npm\ (test|run\ test[[:alnum:]:_-]*)$ ]]; then
  filtered="$cmd 2>&1 | grep -E -A 3 '(FAIL|Error|error:)' | head -50; exit \${PIPESTATUS[0]}"
  jq -n --arg c "$filtered" '{hookSpecificOutput:{hookEventName:"PreToolUse",permissionDecision:"allow",updatedInput:{command:$c}}}'
else
  echo '{}'
fi
EOF
chmod 755 .claude/hooks/filter-test-output.sh
cat > .claude/settings.json << 'EOF'
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash", "hooks": [{ "type": "command", "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/filter-test-output.sh" }] }
    ]
  }
}
EOF
for c in "npm run test:all" "npm test" "npm run test:all | tail -80" "cat package.json && npm test"; do
  printf '%-32s -> ' "$c"
  jq -n --arg c "$c" '{tool_input:{command:$c}}' | .claude/hooks/filter-test-output.sh | jq -c '.hookSpecificOutput.updatedInput.command // "(그대로)"'
done

앞의 두 줄은 … | grep -E -A 3 … | head -50; exit ${PIPESTATUS[0]}로 바뀌고, 뒤의 두 줄은 (그대로)여야 합니다. 정규식 끝의 $가 명령 전체가 정확히 테스트 명령일 때만 바꾸게 합니다. 이것이 없으면 npm run test:all > out.txt; cat x처럼 이어 붙인 명령의 마지막 조각에만 파이프가 붙어 엉뚱하게 동작합니다.

Step 3 · 비교

bash
claude
text
npm run test:all 을 파이프나 다른 명령 없이 그대로 한 번 실행하고, 그 출력만 보고 실패 원인을 알려줘

화면의 도구 호출은 원래 명령 Bash(npm run test:all)로 표시되지만, Claude가 받은 결과는 FAIL getUserPlan: expected 'pro' but got 'unknown' 한 줄과 Exit code 1뿐입니다(원래는 408줄). 훅이 바꾼 것은 실행되는 명령이지 화면 표시가 아닙니다. 다시 /context를 실행해 TASK 01과 Messages 토큰 증가량을 비교하세요.

ℹ

왜 "그대로 실행"이라고 지시하나요

그냥 "실행하고 원인을 알려줘"라고 하면 Opus 5.5는 스스로 | tail -80이나 > /tmp/out.txt; grep -vn '^ok '처럼 출력을 줄여 실행하는 경우가 많습니다(실습 환경에서 확인). 모델이 알아서 줄이면 훅이 낄 자리가 없습니다. 훅은 모델이 잊거나 다른 모델·서브에이전트가 실행할 때도 같은 기준을 보장하는 장치입니다. 실습에서는 차이를 보기 위해 그대로 실행하게 합니다.

ℹ

명령이 바뀌지 않았다면

/hooks에서 PreToolUse 훅이 보이는지 확인합니다. 보이지 않으면 세션을 다시 시작하고, 프로젝트 신뢰 확인에서 Yes를 골랐는지 확인하세요. 그래도 바뀌지 않으면 진행자에게 버전을 알려 주세요.

⚠

필터 훅은 "무엇을 버리는가"를 정하는 정책입니다

너무 공격적으로 자르면 Claude가 원인을 못 찾아 재실행을 반복하고 오히려 토큰이 늘어납니다. 위 실습에서도 Claude는 "출력만으로는 어느 부분이 원인인지 알 수 없다, 소스를 열어 보겠다"고 답합니다. 실패 줄 앞뒤 몇 줄은 남기고, 팀 단위로는 Ch4의 플러그인 훅으로 배포하세요.

✓

TASK 04 · 압축(compaction)을 내가 정한 때에 (15분)

대화가 길어지면 Claude Code는 오래된 기록을 요약해 자리를 만듭니다. 이것이 compaction입니다. 자동으로도 일어나지만, 언제·무엇을 남기고 압축할지를 정하면 비용과 품질이 함께 좋아집니다.

방식 언제 이 랩에서
자동 압축 대화가 auto-compact window에서 버퍼를 뺀 지점에 닿을 때 (1M 모델은 창 1M − 버퍼 33K ≈ 967K) Step 4
/compact [지시] 내가 원할 때, 남길 것을 지정 Step 2
/rewind 부분 요약 특정 메시지부터·까지만 요약 참고
Idle compaction 1시간 캐시 TTL 세션을 오래 비웠을 때, 캐시가 식기 직전 Step 5
/clear 관련 없는 작업으로 넘어갈 때, 비용 0 참고

Step 1 · 압축 전 상태 기록

Terminal

bash
cd ~/claude-lab/ch6 && claude --continue
text
/context
text
/usage

Messages 토큰과 Prompt cache (main) 줄을 적어 둡니다.

Step 2 · 남길 것을 정해서 압축

text
/compact 테스트 실패 원인과 수정한 파일, 남은 할 일만 남겨줘

Compacted (ctrl+o to see full summary)가 나오면 다시 /context를 실행해 Messages가 줄어든 것을 확인합니다. 압축 직후 /usage에는 Prompt cache (main) 줄이 없다가, 다음 요청 뒤에 다시 나타나며 캐시 적중률이 낮아져 있습니다(실습 환경에서 88% → 64%). 압축으로 접두부가 바뀌어 캐시를 새로 쌓기 때문입니다.

압축 후에 무엇이 다시 들어오는지 확인합니다.

항목 압축 후
루트 CLAUDE.md, auto memory 디스크에서 다시 주입
최근 읽거나 고친 파일 최근 수정 순으로 최대 5개 다시 읽음
사용한 스킬 본문 다시 주입 (스킬당 5,000, 합계 25,000 토큰 한도)
paths: 규칙, 하위 폴더 CLAUDE.md 요약되어 사라짐, 해당 파일을 다시 읽을 때 재로드
SessionStart 훅(compact matcher) 다시 실행되어 결과가 추가됨

Step 3 · 압축 지침과 DLP 규칙을 고정하기

압축 요약에 매번 남길 것을 CLAUDE.md에 적고, 압축 뒤에도 사라지면 안 되는 규칙은 SessionStart 훅(compact matcher)으로 다시 넣습니다. /exit로 나와 실행합니다.

Terminal, 전체 복사

bash
cd ~/claude-lab/ch6
cat >> CLAUDE.md << 'EOF'

# Compact instructions
압축할 때는 테스트 결과, 바꾼 파일 목록, 결정 사항만 남긴다.
EOF
jq '.hooks.SessionStart = [{"matcher":"compact","hooks":[{"type":"command","command":"echo \"[사내 규정] 고객 주민등록번호·카드번호는 출력하거나 파일에 쓰지 않는다\""}]}]' \
  .claude/settings.json > /tmp/s.json && cp /tmp/s.json .claude/settings.json
jq '.hooks | keys' .claude/settings.json
claude --continue
text
/compact
text
압축 뒤에 새로 받은 사내 규정이 있으면 그대로 알려줘

Claude가 "압축 직후 실행된 SessionStart:compact 훅이 사내 규정 한 줄을 전달했습니다"라며 규정 문장을 그대로 옮기면 성공입니다. CLAUDE.md는 세션 중에 고쳐도 바로 반영되지 않고 /compact, /clear, 재시작 때 다시 읽힌다는 점도 기억하세요.

ℹ

PreCompact · PostCompact 훅

PreCompact는 압축 직전에 돌며 exit 2로 압축을 막을 수 있고, PostCompact는 압축 뒤 기록용입니다. 감사 목적이라면 압축 전 대화를 보관하는 PreCompact 훅을 붙일 수 있습니다.

Step 4 · auto-compact window를 조정해 미리 압축하기

auto-compact window는 컨텍스트가 얼마나 찼을 때 자동 압축할지를 정하는 값입니다. 1M 컨텍스트 모델은 기본 창이 모델 한도와 같은 1M이고, /context에 보이는 Autocompact buffer: 33k tokens (3.3%)만큼을 남겨 약 967K에서 압축합니다. 거의 끝까지 차오른 뒤에야 압축하므로, 그 사이의 매 요청이 수십만 토큰을 입력으로 다시 보냅니다. 창을 낮추면 더 일찍 압축되어 요청당 입력이 작아집니다.

같은 세션에서 현재 값을 확인합니다.

text
/autocompact

Current setting for Opus 5.5: 1m tokens (default for this model)와 함께 ←/→로 값을 고르는 창이 뜹니다. 여기서는 Esc로 닫고 명령으로 직접 지정합니다. 창을 400K로 낮추면 Auto-compact window for Opus 5.5 set to 400k tokens가 나오고, 값은 바로 적용되어 사용자 설정에 모델별로 저장됩니다(v2.1.288+).

text
/autocompact 400k

/exit 후 저장된 위치를 확인합니다.

Terminal

bash
jq '.modelSettings // {} | with_entries(select(.value.autoCompactWindow)) ' ~/.claude/settings.json

{"claude-opus-5-5": {"autoCompactWindow": 400000}}이 보이면 됩니다.

조정 방법 범위 비고
CLAUDE_CODE_AUTO_COMPACT_WINDOW 환경 변수 그 셸·프로세스 가장 우선. v2.1.304+는 500k, 1M 표기 허용 (200만 쓰면 200토큰)
claude --autocompact 400k 그 세션 저장된 값을 바꾸지 않고 덮어씀
/autocompact 400k 사용자 설정, 모델별 modelSettings.<model>.autoCompactWindow에 저장. /autocompact auto로 기본값 복귀
autoCompactWindow (settings) 파일 스코프 100000~1000000 또는 "auto". 같은 파일에서는 모델별 값이 우선. managed에 두면 조직 기본값이 되어 사용자의 /autocompact를 덮음

실제 압축 시점은 이 값과 모델의 최대 컨텍스트 중 작은 쪽입니다. 자동 압축 자체를 끄려면 autoCompactEnabled: false 또는 DISABLE_AUTO_COMPACT=1(이때도 /compact는 동작)을 씁니다.

text
/config

검색창에 idle을 입력해 Idle compaction 항목을 찾아봅니다(v2.1.302 이상에서 /config에 표시, 설정 키는 idleCompaction). 이 기능은 1시간 캐시 TTL로 도는 큰 대화를 오래 비워 두면, 캐시가 만료되기 직전에 미리 압축해 다음 메시지가 전체 기록을 비싼 값에 다시 처리하지 않게 합니다. 이 랩에서도 값은 true로 보이지만, 아래 표처럼 Bedrock 기본 5분 캐시에서는 동작할 일이 없습니다. 확인 후 Esc를 두 번 눌러 닫습니다.

⚠

/config에서 Enter·Space는 값을 바꿉니다

/config는 목록에서 Enter·Space로 바로 토글합니다. 리허설 중 검색창에서 키를 잘못 눌러 맨 위 항목인 Auto-compact가 false로 바뀐 일이 있었습니다. 실수로 바꿨다면 다시 토글하거나 use_bedrock_direct로 사용자 설정을 기본값으로 되돌립니다.

접속 방식 메인 대화 기본 TTL Idle compaction
Claude 구독(플랜 사용량 안) 1시간 동작
API 키 · Amazon Bedrock(이 랩) 5분 기본으로는 해당 없음
Bedrock + promptCacheTtl: "1h" 1시간(모델별 지원 확인) Anthropic feature flag 조회가 필요해 Bedrock에서는 동작하지 않는다는 보고가 있음(리허설 확인). 1시간 캐시 쓰기 단가가 더 높음

⚠

Bedrock 사용자의 습관: 자리 비우기 전에 압축하거나 지우기

Bedrock 기본값(5분)에서는 5분만 자리를 비워도 캐시가 식습니다. 식은 뒤에 /compact를 하면 전체 기록을 비캐시 입력으로 다시 읽는 큰 요청이 됩니다. 긴 작업 중 자리를 비울 때는 떠나기 전에 /compact, 이어 할 필요가 없으면 /clear가 가장 쌉니다. 되돌리고 싶은 경로라면 /rewind가 이미 캐시된 지점으로 돌아가므로 압축보다 쌉니다.
