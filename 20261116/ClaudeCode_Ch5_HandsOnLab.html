Ch5. 비용 효율적으로 쓰기

Hands-on Lab / Chapter 5

Claude Code Deep Dive Workshop, Chapter 5 - 비용 효율적으로 쓰기 (컨텍스트 엔지니어링) 실습

한 사람의 세션이 같은 일을 더 적은 토큰으로 하도록 만드는 컨텍스트 엔지니어링을 실습합니다. 고객자산 분석 담당자가 Ch4까지 만든 팀 킷으로 카드 거래 파일을 매일 열어 보다 보면 토큰이 순식간에 쌓입니다. 먼저 기준선을 재고, 거래 CSV 출력을 줄이는 출력 필터 훅, CLAUDE.md 다이어트와 모델 선택, 압축(compaction)을 내가 정한 때에 하는 법까지 차례로 해 봅니다. 조직이 비용을 보고 막는 방법은 Ch6에서 이어집니다.

소요 시간 40분 내외, Task 준비 + 4개, 기준 버전 Claude Code 2.1.290 이상, Update 2026.11

TASK 00 · 사전 준비 확인 (3분)

이번 챕터의 작업 폴더는 ~/claude-lab/ch6이고, 분석 데이터는 가명 처리된 pseudo/만 씁니다. Ch4에서 만든 asset-team-kit이 설치되어 있으면 그대로 쓰고, 없을 때만 키트의 기준본으로 설치합니다. 키트를 이미 받았다면 내려받기 줄은 아무 일도 하지 않습니다.

그림은 Preflight에서 본 키트 내려받기 전체입니다. 아래 블록의 3-4번째 줄은 그중 복사와 풀기만 하고, 이미 받았다면 아무것도 하지 않습니다.

Terminal, 전체 복사

bash

이 블록이 하는 일 (붙여넣는 곳: 터미널)

  6. 마켓플레이스를 등록하고(출력은 버림) 플러그인을 설치합니다. 27번째 줄 fi가 if 블록의 끝입니다. 마지막 두 줄은 grep -A2로 플러그인 이름 줄과 그 뒤 두 줄(버전·상태)을 보여 주고, ls pseudo | head -4로 CSV 이름 앞 네 개를 보여 줍니다. 플러그인이 disabled로 보여도 됩니다.

TASK 02 · 출력 필터 훅으로 거래 CSV 출력 줄이기 (10분)

거래 파일 전체가 컨텍스트에 들어가는 것을 막고, 머리글과 앞 50행, 전체 행 수만 넘기도록 Bash 명령을 바꿔 주는 PreToolUse 훅입니다. 공식 비용 문서의 filter-test-output.sh 예시와 같은 방식으로, 걸러내는 대상만 *_transactions.csv로 바꿨습니다.

아래 그림은 TASK 01의 기준선과 이 TASK의 필터 훅을 한 장으로 비교합니다. 컨텍스트 창은 Claude가 한 번에 볼 수 있는 대화의 자리이고, 여기에 들어간 글자가 곧 토큰 비용입니다.

Step 1 · 큰 거래 파일 확인

Terminal

bash
cd ~/claude-lab/ch6
wc -lc pseudo/card_transactions.csv pseudo/bank_transactions.csv
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. 실습 폴더로 들어갑니다.
  2. wc -lc는 파일마다 줄 수(-l)와 바이트 수(-c)를 셉니다. 카드 거래는 36,062줄(머리글 포함), 은행 거래는 29,890줄이 나오고, 파일이 둘이라 마지막에 합계 줄이 붙습니다(숫자는 참고용).

카드 거래는 36,062줄(머리글 포함), 은행 거래는 29,890줄입니다. cat으로 열면 파일 전체가 출력되지만, Claude Code는 약 30,000자를 넘는 Bash 출력을 파일로 저장하고 짧은 미리보기만 모델에 보여 줍니다. 그래서 이 랩은 한도 안에 들어오는 head -n 400(약 20,000자)으로 비교합니다.

ℹ

왜 400행인가요

Claude Code 자체가 약 30,000자를 넘는 Bash 출력을 파일에 저장하고 미리보기만 보여 주기 때문에, 전체 cat으로는 훅 전후 차이가 흐려집니다. 앞 400행은 약 20,000자라 한도 안에 들어오고, 훅을 거치면 약 2,600자가 됩니다.

Step 2 · 필터 훅 설치

bash
mkdir -p .claude/hooks
cat > .claude/hooks/filter-tx-output.sh << 'EOF'
#!/bin/bash
# cat, head -n N, tail -n N (N > 50) 로 *_transactions.csv 를 "그대로" 열 때만
# 머리글 + 50줄 + 전체 행 수로 줄여서 컨텍스트로 넘긴다
input=$(cat)
cmd=$(echo "$input" | jq -r '.tool_input.command // empty')
re='^(cat|head|tail)( +-n +([0-9]+))? +([[:alnum:]_./-]*_transactions\.csv)$'
if [[ "$cmd" =~ $re ]]; then
  op="${BASH_REMATCH[1]}"; n="${BASH_REMATCH[3]}"; f="${BASH_REMATCH[4]}"
  if [ "$op" = cat ] || { [ -n "$n" ] && [ "$n" -gt 50 ]; }; then
    if [ "$op" = tail ]; then body="head -n 1 $f; tail -n 50 $f"; else body="head -n 51 $f"; fi
    filtered="$body; echo \"[필터] 전체 \$((\$(wc -l < $f) - 1))행 중 머리글과 50행만 표시\""
    jq -n --arg c "$filtered" '{hookSpecificOutput:{hookEventName:"PreToolUse",permissionDecision:"allow",updatedInput:{command:$c}}}'
    exit 0
  fi
fi
echo '{}'
EOF
chmod 755 .claude/hooks/filter-tx-output.sh
cat > .claude/settings.json << 'EOF'
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash", "hooks": [{ "type": "command", "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/filter-tx-output.sh" }] }
    ]
  }
}
EOF
for c in "head -n 400 pseudo/card_transactions.csv" "tail -n 200 pseudo/bank_transactions.csv" "head -n 5 pseudo/card_transactions.csv" "cat pseudo/customers.csv" "cat pseudo/card_transactions.csv | wc -l"; do
  printf '%-44s -> ' "$c"
  jq -n --arg c "$c" '{tool_input:{command:$c}}' | .claude/hooks/filter-tx-output.sh | jq -c '.hookSpecificOutput.updatedInput.command // "(그대로)"'
done
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. mkdir -p로 훅 폴더를 만들고, cat > … << 'EOF'(heredoc)로 19번째 줄 EOF까지의 내용을 filter-tx-output.sh에 씁니다. 훅은 도구를 쓰기 직전에 JSON을 표준입력으로 받습니다. input=$(cat)이 그것을 읽고, jq -r '.tool_input.command // empty'가 Claude가 실행하려는 Bash 명령 글자만 꺼냅니다(없으면 빈 문자열).
  2. 8번째 줄 정규식은 명령 전체가 cat|head|tail + 선택적 -n 숫자 + *_transactions.csv 파일 하나일 때만 맞습니다. 끝의 $ 때문에 파이프나 리다이렉션이 붙은 명령은 맞지 않습니다. 맞으면 BASH_REMATCH에서 명령(op), 줄 수(n), 파일(f)을 꺼냅니다. 11번째 줄 조건은 cat이거나 줄 수가 50보다 클 때만 참이라, head -n 5는 건드리지 않습니다.
  3. tail이면 머리글 한 줄과 마지막 50행을, 아니면 head -n 51(머리글 + 50행)을 body로 정합니다. 13번째 줄은 그 뒤에 "[필터] 전체 N행 중 …"을 찍는 echo를 붙이는데, N은 wc -l에서 머리글 1줄을 뺀 값입니다(\$는 실행할 때 계산하라는 뜻). 14번째 줄 jq -n이 "이 도구 사용을 허용하되 명령을 updatedInput.command로 바꿔라"는 JSON 응답을 만들어 출력합니다.
  4. exit 0으로 끝냅니다. 조건에 맞지 않는 명령은 echo '{}'가 빈 JSON을 돌려주고, 이것은 "아무것도 바꾸지 않음"입니다. 19번째 줄 EOF가 첫 heredoc의 끝입니다.
  5. chmod 755로 스크립트에 실행 권한을 줍니다. 이어서 .claude/settings.json을 새로 씁니다(>는 기존 내용을 덮어씁니다). PreToolUse의 matcher: "Bash"는 Bash 도구를 쓰기 직전마다 이 스크립트를 실행하라는 뜻이고, $CLAUDE_PROJECT_DIR은 프로젝트 폴더로 바뀝니다.
  6. Claude를 열지 않고 훅만 시험합니다. 명령 5개를 차례로 돌며, jq -n으로 훅이 받는 모양의 JSON을 만들어 스크립트에 넣고, jq -c로 바뀐 명령(updatedInput.command)만 한 줄로 봅니다. 바뀌지 않았으면 "(그대로)"를 찍습니다. 앞의 두 명령만 바뀌고 나머지 셋은 그대로여야 합니다.

앞의 두 줄은 head -n 51 … ; echo "[필터] 전체 …행 중 …" 꼴로 바뀌고(tail은 머리글 한 줄과 마지막 50행), 뒤의 세 줄은 (그대로)여야 합니다. 5행만 보는 head -n 5는 이미 작아서, 다른 파일(customers.csv)은 거래 파일이 아니어서, 파이프가 붙은 명령은 정규식 끝의 $에 걸려서 건드리지 않습니다. 이 앵커가 없으면 cat x_transactions.csv > out.txt; cat y처럼 이어 붙인 명령의 마지막 조각만 바뀌어 엉뚱하게 동작합니다.

바뀐 명령을 직접 실행해 보면 머리글 1줄, 거래 50줄, 요약 1줄로 총 52줄이 나옵니다. 마지막 줄은 [필터] 전체 36061행 중 머리글과 50행만 표시(카드 거래 기준)입니다.

Step 3 · 비교

TASK 04 · 압축(compaction)을 내가 정한 때에 (15분)

대화가 길어지면 Claude Code는 오래된 기록을 요약해 자리를 만듭니다. 이것이 compaction입니다. 자동으로도 일어나지만, 언제·무엇을 남기고 압축할지를 정하면 비용과 품질이 함께 좋아집니다.

방식 언제 이 랩에서
자동 압축 대화가 auto-compact window에서 버퍼를 뺀 지점에 닿을 때 (1M 모델은 창 1M − 버퍼 33K ≈ 967K) Step 4
/compact [지시] 내가 원할 때, 남길 것을 지정 Step 2
/rewind 부분 요약 특정 메시지부터·까지만 요약 참고
Idle compaction 1시간 캐시 TTL 세션을 오래 비웠을 때, 캐시가 식기 직전 Step 5
/clear 관련 없는 작업으로 넘어갈 때, 비용 0 참고

Step 4 · auto-compact window를 조정해 미리 압축하기

auto-compact window는 컨텍스트가 얼마나 찼을 때 자동 압축할지를 정하는 값입니다. 1M 컨텍스트 모델은 기본 창이 모델 한도와 같은 1M이고, /context에 보이는 Autocompact buffer: 33k tokens (3.3%)만큼을 남겨 약 967K에서 압축합니다. 거의 끝까지 차오른 뒤에야 압축하므로, 그 사이의 매 요청이 수십만 토큰을 입력으로 다시 보냅니다. 창을 낮추면 더 일찍 압축되어 요청당 입력이 작아집니다.

같은 세션에서 현재 값을 확인합니다.

text
/autocompact
이 입력이 하는 일 (붙여넣는 곳: Claude 입력창)

autoCompactWindow (settings) 파일 스코프 100000~1000000 또는 "auto". 같은 파일에서는 모델별 값이 우선. managed에 두면 조직 기본값이 되어 사용자의 /autocompact를 덮음

실제 압축 시점은 이 값과 모델의 최대 컨텍스트 중 작은 쪽입니다. 자동 압축 자체를 끄려면 autoCompactEnabled: false 또는 DISABLE_AUTO_COMPACT=1(이때도 /compact는 동작)을 씁니다.

Step 5 · Idle compaction과 Bedrock의 캐시 수명

text
/config
이 입력이 하는 일 (붙여넣는 곳: Claude 입력창)
  1. /config는 설정 목록을 엽니다. 검색창에 idle을 입력해 Idle compaction 항목을 찾아보기만 합니다. 이 목록에서 Enter와 Space는 값을 바로 바꾸므로 조심하고, 확인 뒤에는 Esc를 두 번 눌러 닫습니다.

검색창에 idle을 입력해 Idle compaction 항목을 찾아봅니다(v2.1.302 이상에서 /config에 표시, 설정 키는 idleCompaction). 이 기능은 1시간 캐시 TTL로 도는 큰 대화를 오래 비워 두면, 캐시가 만료되기 직전에 미리 압축해 다음 메시지가 전체 기록을 비싼 값에 다시 처리하지 않게 합니다. 이 랩에서도 값은 true로 보이지만, 아래 표처럼 Bedrock 기본 5분 캐시에서는 동작할 일이 없습니다. 확인 후 Esc를 두 번 눌러 닫습니다.

⚠

/config에서 Enter·Space는 값을 바꿉니다

/config는 목록에서 Enter·Space로 바로 토글합니다. 리허설 중 검색창에서 키를 잘못 눌러 맨 위 항목인 Auto-compact가 false로 바뀐 일이 있었습니다. 실수로 바꿨다면 /config에서 같은 항목을 다시 토글해 되돌립니다. use_bedrock_direct는 모드 키만 바꾸므로 이 값을 되돌리지 않습니다.

Bedrock 사용자의 습관: 자리 비우기 전에 압축하거나 지우기

Bedrock 기본값(5분)에서는 5분만 자리를 비워도 캐시가 식습니다. 식은 뒤에 /compact를 하면 전체 기록을 비캐시 입력으로 다시 읽는 큰 요청이 됩니다. 긴 작업 중 자리를 비울 때는 떠나기 전에 /compact, 이어 할 필요가 없으면 /clear가 가장 쌉니다. 되돌리고 싶은 경로라면 /rewind가 이미 캐시된 지점으로 돌아가므로 압축보다 쌉니다.
