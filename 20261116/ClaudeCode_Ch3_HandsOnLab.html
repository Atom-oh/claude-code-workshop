Hands-on Lab / Chapter 3

Claude Code Deep Dive Workshop, Chapter 3 - Subagent로 일 나눠 맡기기 실습

이번 이야기의 주인공은 고객자산 분석 담당자입니다. 고객 1,000명을 소비, 자산, 위험 점검까지 혼자 보기에는 일이 많아서, 일을 spending-analyst, portfolio-analyst, risk-reviewer 3종의 서브에이전트에게 나눠 맡기고 고객을 세그먼트로 묶어 세그먼트별 맞춤 서비스를 제안하려 합니다. 이 랩에서는 세 에이전트를 직접 정의하고, 도구 권한 격리를 체험한 뒤 자동 / 명시 / 병렬 디스패치 3가지 패턴과 Headless 통합까지 실습합니다. 분석 담당자가 가장 먼저 맡기는 일은 누가 어떻게 쓰는가를 읽는 것입니다. .claude/agents/에 spending-analyst를 정의하고 등록을 확인한 뒤, 연령대별 소비 패턴 분석을 첫 위임으로 보냅니다.

ℹ

Subagent가 왜 필요한가, Context Isolation

서브에이전트는 자신만의 컨텍스트 창, 시스템 프롬프트, 도구 권한, 모델을 갖는 독립 에이전트입니다. 고객 천 명의 데이터를 집계하는 무거운 분석을 위임하면 서브에이전트 컨텍스트에서 소비되고, 메인에는 요약만 반환되어 메인 컨텍스트가 보호됩니다.

Step 1 · 에이전트 정의 파일 작성

name: spending-analyst
description: |

  월별 카드 소비 요약, 계좌 잔액, 고객 기본 정보를 근거로 삼음.
  사용 시점: 소비 성향, 선호 카테고리, 연령대별 생애 단계 분석이 필요한 경우.
tools: Read, Grep, Glob, Bash(python3:*)
model: sonnet
---

- 개별 고객 ID와 토큰 값은 쓰지 않고 집계만 보고합니다.
EOF

Step 2 · JSON 후처리

Terminal

bash
jq -r '.result' segments.json | head -20                 # 세그먼트 JSON(텍스트)
jq -r '.result' segments.json | sed '/^```/d' | jq -r '.[] | "\(.segment)\t\(.size)\t\(.service)"'   # 코드 펜스가 붙어 오면 제거 후 표로

이 블록이 하는 일 (붙여넣는 곳: 두 번째 터미널)

  2. result가 코드 펜스(```)로 감싸져 올 때를 위한 줄입니다. sed '/^```/d'가 ```로 시작하는 줄을 지우고, 뒤의 jq가 배열의 각 항목에서 segment, size, service를 탭으로 나눠 한 줄씩 출력합니다.
  3. num_turns, total_cost_usd, is_error 세 값만 뽑아 대화 턴 수, 비용, 오류 여부를 봅니다.

  5. subagent_stats에서 서브에이전트가 몇 번 떴는지와 종류별 횟수를 봅니다.
  6. permission_denials에서 허용 규칙에 없어 거부된 명령만 모아 봅니다.

--output-format json의 결과는 고정된 메타데이터 + 텍스트 result 입니다. 세그먼트 내용이 별도 필드로 나뉘어 오지는 않으므로, 프롬프트에서 JSON 형식을 지정하고 result를 다시 파싱하거나 --json-schema를 씁니다.

같은 명령을 GitHub Actions에 넣으면 매일 밤 세그먼트 리포트가 만들어집니다. 아래는 강의에서 다룬 직렬(세그먼트 리포트) + 병렬(근거와 PII 점검) 복합 패턴의 워크플로입니다. GitHub 저장소가 있다면 push해서 실험해 보세요. 선택 과제입니다.

yaml
name: Nightly Segment Report
on:
  schedule:
    - cron: "0 17 * * *"   # 매일 02:00 KST
  workflow_dispatch:

jobs:
  segment-report:
    runs-on: ubuntu-latest
    permissions: { id-token: write, contents: read }
    env:
      CLAUDE_CODE_USE_BEDROCK: "1"
      AWS_REGION: us-east-1
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: us-east-1
      - run: npm install -g @anthropic-ai/claude-code
      - run: aws s3 sync s3://YOUR_ANALYSIS_BUCKET/pseudo ./pseudo --only-show-errors

      # 직렬: portfolio-analyst로 세그먼트 먼저 계산
      - name: Segments
        run: |
          claude -p "portfolio-analyst 에이전트로 세그먼트 (a)~(c)의 고객 수와 서비스 제안을 JSON 배열로만 답해 주세요" \
            --allowedTools "Read,Grep,Glob,Bash(python3:*)" \
            --output-format json > segments.json

      # 병렬 요청: 근거 검증과 PII 점검을 한 번에
      - name: Evidence + PII check
        run: |
          claude -p "risk-reviewer 에이전트로 segments.json의 근거와 식별자 노출 여부를 점검해 주세요" \
            --allowedTools "Read,Grep,Glob" \
            --output-format json > risk.json

      - uses: actions/upload-artifact@v4
        with: { name: segment-report, path: "segments.json\nrisk.json" }
이 워크플로가 하는 일 (붙여넣지 않음, 참고용)
  1. 워크플로 이름과 실행 시점입니다. cron "0 17 * * *"은 매일 UTC 17시이고 한국 시간으로 새벽 2시입니다. workflow_dispatch는 버튼으로 수동 실행하는 방법입니다.
  2. Ubuntu 서버에서 job을 실행합니다. id-token: write는 GitHub가 임시 신원 토큰(OIDC)을 발급하게 하는 권한이고, env는 Bedrock을 us-east-1에서 쓰라는 설정입니다.
  3. 순서대로 소스를 받고, OIDC로 AWS 역할을 받고(저장된 액세스 키 없이), Claude Code를 설치하고, S3의 가명 데이터를 내려받습니다. YOUR_ANALYSIS_BUCKET은 자리 표시이므로 본인 버킷 이름으로 바꿔야 합니다.
  4. 첫 번째 step으로 portfolio-analyst가 세그먼트를 계산해 segments.json을 만듭니다. TASK 05 Step 1과 같은 형태의 claude -p 명령입니다.
  5. 두 번째 step으로 risk-reviewer가 segments.json의 근거와 식별자 노출을 점검합니다. 읽기 도구만 허용합니다. 30번 줄의 주석은 "병렬 요청"이라고 하지만, 이 step은 근거 검증과 PII 점검을 한 번의 claude -p 요청에 담은 것입니다. job은 하나이고 step은 위에서 아래로 차례로 실행되므로, 앞 step이 만든 segments.json을 읽습니다.
  6. 산출물을 보관합니다. path의 \n은 줄바꿈이라 segments.json과 risk.json 두 파일이 올라갑니다.
