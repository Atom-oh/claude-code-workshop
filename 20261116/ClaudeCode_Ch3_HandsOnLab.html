Ch3. Subagent로 일 나눠 맡기기

Hands-on Lab / Chapter 3

Claude Code Deep Dive Workshop, Chapter 3 - Subagent로 일 나눠 맡기기 실습

이번 이야기의 주인공은 고객자산 분석 담당자입니다. 고객 1,000명을 소비, 자산, 위험 점검까지 혼자 보기에는 일이 많아서, 일을 spending-analyst, portfolio-analyst, risk-reviewer 3종의 서브에이전트에게 나눠 맡기고 고객을 세그먼트로 묶어 세그먼트별 맞춤 서비스를 제안하려 합니다. 이 랩에서는 세 에이전트를 직접 정의하고, 도구 권한 격리를 체험한 뒤 자동 / 명시 / 병렬 디스패치 3가지 패턴과 Headless 통합까지 실습합니다. TASK 00에서 준비하는 작업 폴더(~/claude-lab/ch4)에서 pseudo/ 가명 데이터를 대상으로 진행합니다.

소요 시간 필수 40분 + 선택 7분 · Task 준비 + 4개 + 선택 1개 · 기준 버전 Claude Code 2.1.x · Update 2026.11

⚠

가명 데이터만 사용하세요

이 랩은 pseudo/(가명 토큰) 데이터만 읽습니다. 원본 식별자가 있는 raw/는 열지 않습니다. 모든 값은 형식만 맞춘 가짜 데이터입니다.

TASK 01 · 첫 Subagent, spending-analyst 만들기 (10분)

분석 담당자가 가장 먼저 맡기는 일은 누가 어떻게 쓰는가를 읽는 것입니다. .claude/agents/에 spending-analyst를 정의하고 등록을 확인한 뒤, 연령대별 소비 패턴 분석을 첫 위임으로 보냅니다.

ℹ

Subagent가 왜 필요한가, Context Isolation

서브에이전트는 자신만의 컨텍스트 창, 시스템 프롬프트, 도구 권한, 모델을 갖는 독립 에이전트입니다. 고객 천 명의 데이터를 집계하는 무거운 분석을 위임하면 서브에이전트 컨텍스트에서 소비되고, 메인에는 요약만 반환되어 메인 컨텍스트가 보호됩니다.

Step 1 · 에이전트 정의 파일 작성

정의 파일은 YAML frontmatter 핵심 4필드(name / description / tools / model, 필수는 name과 description)와 시스템 프롬프트 본문으로 구성됩니다. 작업 폴더에서 아래 블록을 실행하세요.

Terminal, 전체 복사

bash
cd ~/claude-lab/ch4
mkdir -p .claude/agents

cat > .claude/agents/spending-analyst.md << 'EOF'
---
name: spending-analyst
description: |
  고객 또는 고객 그룹의 소비 패턴과 생애 단계를 추정하는 소비 분석가.
  월별 카드 소비 요약, 계좌 잔액, 고객 기본 정보를 근거로 삼음.
  사용 시점: 소비 성향, 선호 카테고리, 연령대별 생애 단계 분석이 필요한 경우.
tools: Read, Grep, Glob, Bash(python3:*)
model: sonnet
---
당신은 소비 데이터를 읽는 고객 분석가입니다.

# 사용할 데이터 (pseudo/ 아래 가명 데이터만)
- card_spend_monthly.csv: customer_id, month, merchant_category, amount (최근 3개월 월별 요약)
- bank_accounts.csv: customer_id, account_type, balance
- customers.csv: customer_id, age, gender, region, income_band
- 이름에 transactions가 들어간 거래 원장 파일은 읽지 않습니다.

# 분석 순서
1. 대상 고객 그룹을 customers.csv에서 조건으로 고릅니다.
2. python3(csv 모듈)로 카테고리별 비중과 월별 추세를 집계합니다.
3. 나이, 소득 구간, 계좌 잔액으로 생애 단계를 추정합니다.

# 출력 형식
- 대상 그룹: 고객 수, 평균 나이
- 소비 패턴, 생애 단계, 근거(파일과 열 이름)
- 개별 고객 ID와 토큰 값은 쓰지 않고 집계만 보고합니다.
EOF
필드역할이 예시의 선택
name고유 식별자, kebab-case 영문 소문자spending-analyst
description자동 디스패치의 판단 기준, 사용 시점까지 명시소비 성향, 생애 단계 분석이 필요할 때
tools도구 화이트리스트, Bash는 명령 패턴으로 제한읽기 도구 + python3 집계만
model별칭 sonnet / opus / haiku, 전체 모델 ID, 또는 inherit. 생략 시 inherit(메인 모델 상속)sonnet, 일상 분석의 표준

TASK 02 · 도구 권한 격리 체험 (7분)

분석 결과를 공유하기 전에 점검하는 risk-reviewer는 읽기만 해야 합니다. 이 읽기 전용 에이전트에 일부러 권한 밖 요청(파일 저장)을 보내 거부 동작을 관찰하고, tools 필드에 권한을 명시적으로 추가한 뒤 새 위임으로 차이를 체험합니다. 마지막에는 정의를 원래대로 되돌립니다. 최소 권한 원칙과 정의 갱신 타이밍의 실습입니다.

ℹ

Tools란 무엇인가

서브에이전트 정의의 tools 필드는 그 에이전트가 쓸 수 있는 손발의 목록입니다. Read(파일 읽기), Grep/Glob(검색), Edit/Write(수정과 생성), Bash(명령 실행)처럼 하나하나가 구체적 능력이고, 목록에 없는 도구는 시도 자체가 차단됩니다. 이 Task는 그 울타리를 일부러 밟아 보며 최소 권한이 실제로 동작하는지 확인하는 실험입니다.

Step 1 · 읽기 전용 risk-reviewer 작성

Terminal, 전체 복사

bash
cat > .claude/agents/risk-reviewer.md << 'EOF'
---
name: risk-reviewer
description: |
  분석 결과의 근거와 개인정보 노출 여부를 점검하는 읽기 전용 리스크 리뷰어.
  사용 시점: 분석이나 제안서를 공유하기 전에 근거 검증과 PII 노출 점검이 필요한 경우.
tools: Read, Grep, Glob
model: sonnet
---
당신은 분석 결과를 공유 전에 점검하는 리스크 리뷰어입니다.
점검 결과를 보고합니다. 분석 대상 데이터 파일은 수정하지 않습니다.

# 점검 항목
1. 근거: 주장마다 pseudo/ 아래 어느 파일, 어느 열에서 나왔는지 확인되는가
2. PII 노출: 주민등록번호, 카드번호, 휴대폰, 계좌번호 형태의 값이나
   개별 고객을 특정할 수 있는 ID와 토큰이 결과물에 들어 있지 않은가
3. 범위: 이름에 transactions가 들어간 거래 원장 파일을 읽지 않았는가

# 출력 형식
- 항목별 PASS | WARN | FAIL
- FAIL과 WARN은 파일 이름과 줄 위치, 권장 조치
EOF

tools에 Write가 없는 상태에서 점검 결과를 파일로 저장하라고 요청합니다. Claude Code가 .claude/agents/를 감시하므로 파일 저장 후 몇 초 안에 자동 인식됩니다(TASK 01에서 디렉토리를 만든 뒤 세션을 시작했기 때문에 재시작 불필요).

Claude 세션 입력

risk-reviewer 에이전트를 사용해서 CLAUDE.md와 pseudo/customers.csv의 앞 20줄에 주민등록번호, 카드번호, 휴대폰, 계좌번호 형태의 값이 있는지 점검하고, 점검 결과를 review-notes.md 파일로 저장해 주세요

text출력 예시

⚠

tools 필드 생략의 위험

tools 필드를 아예 생략하면 메인의 모든 도구를 상속합니다(지양). 화이트리스트를 명시하는 습관이 안전의 기본입니다. 반대로 대부분을 상속하되 일부만 빼려면 disallowedTools: Write, Edit처럼 거부 목록을 쓸 수 있습니다.

Step 3 · 권한을 명시적으로 부여

Terminal, tools에 Write 추가

bash

jq '[.permission_denials[] | .tool_input.command]' segments.json  # 거부된 명령

--output-format json의 결과는 고정된 메타데이터 + 텍스트 result 입니다. 세그먼트 내용이 별도 필드로 나뉘어 오지는 않으므로, 프롬프트에서 JSON 형식을 지정하고 result를 다시 파싱하거나 --json-schema를 씁니다.

헤드리스는 Manual로 시작합니다

claude -p는 auto mode가 아니므로, 허용 규칙에 없는 명령은 묻지 못하고 거부되어 permission_denials에 남습니다. 위 Step 1에서 --allowedTools로 python3 집계를 미리 허용한 이유입니다. 이 옵션을 빼고 다시 실행하면 거부 목록에 python3 명령이 쌓이는 것을 볼 수 있습니다. CI에서는 필요한 명령을 이렇게 명시해 줍니다.

Step 3 · CI 통합 패턴 확인 (참고)

같은 명령을 GitHub Actions에 넣으면 매일 밤 세그먼트 리포트가 만들어집니다. 아래는 강의에서 다룬 직렬(세그먼트 리포트) + 병렬(근거와 PII 점검) 복합 패턴의 워크플로입니다. GitHub 저장소가 있다면 push해서 실험해 보세요. 선택 과제입니다.

.github/workflows/nightly-segments.yml, 참고용

yaml
name: Nightly Segment Report
on:
  schedule:
    - cron: "0 17 * * *"   # 매일 02:00 KST
  workflow_dispatch:

jobs:
  segment-report:
    runs-on: ubuntu-latest
    permissions: { id-token: write, contents: read }
    env:
      CLAUDE_CODE_USE_BEDROCK: "1"
      AWS_REGION: us-east-1
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: us-east-1
      - run: npm install -g @anthropic-ai/claude-code
      - run: aws s3 sync s3://YOUR_ANALYSIS_BUCKET/pseudo ./pseudo --only-show-errors

      # 직렬: portfolio-analyst로 세그먼트 먼저 계산
      - name: Segments
        run: |
          claude -p "portfolio-analyst 에이전트로 세그먼트 (a)~(c)의 고객 수와 서비스 제안을 JSON 배열로만 답해 주세요" \
            --allowedTools "Read,Grep,Glob,Bash(python3:*)" \
            --output-format json > segments.json

      # 병렬 요청: 근거 검증과 PII 점검을 한 번에
      - name: Evidence + PII check
        run: |
          claude -p "risk-reviewer 에이전트로 segments.json의 근거와 식별자 노출 여부를 점검해 주세요" \
            --allowedTools "Read,Grep,Glob" \
            --output-format json > risk.json

      - uses: actions/upload-artifact@v4
        with: { name: segment-report, path: "segments.json\nrisk.json" }
ℹ

CI에서의 안전장치

무인 실행에서는 키를 저장하지 말고 GitHub OIDC로 AWS 역할을 받아 Bedrock을 호출하세요(역할에는 Ch2의 최소 IAM만 부여). 읽기 전용 검사라면 --allowed-tools "Read,Grep,Glob"으로 도구를 제한하세요. 입력은 항상 pseudo/ 가명 데이터만 두고, 원본(raw)은 CI에 올리지 않습니다.
