Ch1. Claude Code는 어떻게 동작하는가

Hands-on Lab / Chapter 1

Claude Code Deep Dive Workshop, Chapter 1 - Claude Code는 어떻게 동작하는가 실습

강의에서 본 에이전트 루프, 컨텍스트, 세션, 권한, 데이터 경로를 이 환경에서 직접 눈으로 확인합니다. 오늘 시나리오는 고객자산 분석 담당자의 첫 세션입니다. 아침에 Claude Code를 처음 열고, 마이데이터 고객 파일로 작은 분석을 맡겨 보면서 동작 원리를 확인합니다. 이 랩의 ccb-endpoint는 기본적으로 Amazon Bedrock을 인스턴스 역할(SigV4)로 직접 호출합니다. 키를 입력할 필요가 없습니다.

소요 시간 20분 내외 · Task 준비 + 4개 · 기준 버전 Claude Code 2.1.x · Update 2026.11

TASK 00 · 사전 준비 확인 (2분)

Step 1 · 버전과 모드 확인

이 환경은 두 가지 모드가 있습니다. 기본은 Bedrock 직접 호출(use_bedrock_direct)이고, Ch2 Lab 1의 TASK 06과 Ch6의 게이트웨이 랩에서만 use_gateway로 바꿉니다.

Terminal, 전체 복사

bash
claude --version
jq '.env | {CLAUDE_CODE_USE_BEDROCK, AWS_REGION, ANTHROPIC_DEFAULT_OPUS_MODEL, ANTHROPIC_DEFAULT_SONNET_MODEL}' ~/.claude/settings.json
cat /etc/claude-code/managed-settings.json
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. Claude Code 버전을 출력합니다. 2.1.x 계열이면 됩니다.
  2. jq는 JSON에서 필요한 칸만 뽑는 도구입니다. 내 설정 파일에서 Bedrock 사용 여부, 리전, 모델 이름 네 값만 보여줍니다.
  3. 회사가 강제하는 설정 파일을 그대로 출력합니다. 내용이 {}로 비어 있으면 기본 모드(Bedrock 직접 호출)입니다.

출력 예시

text출력 예시
2.1.x (Claude Code)
{
  "CLAUDE_CODE_USE_BEDROCK": "1",
  "AWS_REGION": "us-east-1",
  "ANTHROPIC_DEFAULT_OPUS_MODEL": "global.anthropic.claude-opus-5-5",
  "ANTHROPIC_DEFAULT_SONNET_MODEL": "global.anthropic.claude-sonnet-5-5"
}
{}
이 출력은 이렇게 읽습니다 (붙여넣지 않음, 참고용)
  1. 첫 줄은 버전입니다. 2.1.x로 시작하면 됩니다.
  2. 설정 파일에서 뽑은 네 값입니다. CLAUDE_CODE_USE_BEDROCK이 1이면 Bedrock을 쓰고, AWS_REGION이 us-east-1이면 그 리전으로 호출합니다. 모델 이름 두 줄은 Opus와 Sonnet이 어떤 모델로 연결되는지 보여줍니다.
  3. managed-settings.json이 비어 있다는 뜻입니다. 강제 설정이 없는 기본 모드입니다.
ℹ

managed-settings.json이 {}로 비어 있다면 기본 모드입니다

forceLoginMethod가 들어 있다면 이전에 게이트웨이 모드로 바꾼 상태입니다. use_bedrock_direct를 실행해 기본 모드로 되돌리세요.

Step 2 · 실습 폴더 만들기

분석 담당자는 가명처리된 pseudo/ 데이터만 씁니다. 실습 폴더에서 data라는 이름으로 연결해 두면, 이후 프롬프트에서 data/customers.csv처럼 짧게 부를 수 있습니다.

아래 블록의 네 번째 줄이 키트를 내려받는 줄입니다. 그림은 Preflight에서 본 전체 과정이고, 이 줄은 그중 복사와 풀기만 합니다. Preflight에서 받았다면 이 줄은 아무것도 하지 않습니다.

Terminal, 전체 복사

bash
git config --global user.name  >/dev/null || git config --global user.name  "Workshop Participant"
git config --global user.email >/dev/null || git config --global user.email "participant@example.com"
KIT=${WS_KIT:-s3://ws-assets-prod-iad-r-iad-ed304a55c2ca1aee/5b8d0649-9ad2-43a8-8ff5-10ce7bb42e6f/mydata-kit.zip}
[ -d ~/claude-lab/mydata/pseudo ] || (aws s3 cp "$KIT" /tmp/mydata-kit.zip --only-show-errors && mkdir -p ~/claude-lab/mydata && unzip -qo /tmp/mydata-kit.zip -d ~/claude-lab/mydata)
mkdir -p ~/claude-lab/ch1-loop && cd ~/claude-lab/ch1-loop && git init -q
ln -sfn ~/claude-lab/mydata/pseudo data
git add . && git commit -qm "init" && ls -l data && head -2 data/customers.csv data/pensions.csv
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. git은 변경 이력을 남기는 도구입니다. 이름과 이메일이 아직 없을 때만 임시 값을 넣습니다. 뒤에서 git commit을 하려면 필요합니다.
  2. KIT 변수에 키트(mydata-kit.zip)가 있는 S3 주소를 담습니다.
  3. ~/claude-lab/mydata/pseudo 폴더가 없을 때만 키트를 내려받아 풉니다. Preflight에서 이미 받았다면 아무것도 하지 않습니다.
  4. 이번 실습 폴더 ch1-loop를 만들고 그 안에서 git 저장소를 시작합니다.
  5. data라는 이름의 바로가기(심볼릭 링크)를 만들어 pseudo/ 폴더를 가리키게 합니다. 이후 프롬프트에서 data/customers.csv처럼 짧게 부를 수 있습니다.
  6. 첫 상태를 커밋하고, data 링크를 확인한 뒤 두 CSV의 앞 2줄(제목줄과 첫 행)을 보여줍니다. 고객 이름이 고객0001 형태면 가명처리 데이터를 제대로 연결한 것입니다.

Preflight CHECK 06에서 데이터를 이미 내려받았다면 첫 번째 [ -d ... ] 줄은 아무 일도 하지 않습니다. 폴더가 없을 때만 키트를 다시 내려받습니다.

TASK 01 · 에이전트 루프 관찰 (5분)

Step 1 · 첫 세션과 /status

Terminal, 전체 복사

bash
cd ~/claude-lab/ch1-loop && claude
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. 실습 폴더로 이동한 뒤 Claude Code를 시작합니다. &&는 앞 명령이 성공했을 때만 뒤 명령을 실행하라는 뜻입니다.

환경에서 claude를 처음 실행하면 테마 선택 화면(Choose the text style…)이 먼저 나옵니다. 기본값(Dark mode) 그대로 Enter를 누르면 됩니다. 이어서 처음 여는 폴더라 Accessing workspace 확인 창이 뜹니다. 기본 선택이 No, exit이므로 ↓로 Yes, I trust this folder를 고른 뒤 Enter를 누릅니다. 이후 챕터에서 새 폴더를 열 때마다 같은 창이 뜹니다.

세션이 열리면 아래를 입력합니다.

text
/status
이 입력이 하는 일 (붙여넣는 곳: Claude 입력창)
  1. 현재 세션의 상태를 보여주는 슬래시 명령입니다. 모델을 어느 서비스(API provider)와 리전에서 부르는지 확인합니다. Claude Code가 열린 뒤에 입력합니다.

API provider가 Amazon Bedrock, 리전이 us-east-1인지 확인합니다. 시작 화면 로고 옆에도 Opus 5.5 · Amazon Bedrock이 보입니다. 이 값이 "추론이 어느 계정·리전에서 일어나는가"에 대한 답입니다.

Step 2 · 수집 → 수행 → 검증을 지켜보기

아래 프롬프트를 입력하기 전에, 한 번의 프롬프트가 Claude Code 안에서 어떻게 도는지 그림으로 먼저 봅니다.

text
먼저 data/customers.csv와 data/pensions.csv의 맨 앞 5행씩을 보여주고, 그 데이터로 연령대(20대~60대)별 고객 수와 퇴직연금(DB, DC, IRP) 보유율을 표로 만들어줘. 한 고객이 연금을 여러 개 가질 수 있으니 고객 단위로 세고, 끝나면 숫자를 다른 방법으로 다시 계산해서 검증해줘
이 입력이 하는 일 (붙여넣는 곳: Claude 입력창)
  1. 이 한 문장에 수집(앞 5행 보기), 수행(연령대별 표 만들기), 검증(다른 방법으로 다시 계산)이 모두 들어 있습니다. 위 그림의 순서대로 Claude Code가 도구를 고르는지 지켜보세요. 한 고객이 연금을 여러 개 가질 수 있다는 말은 중복을 세지 말라는 힌트입니다.

작업이 끝나기 전에 /context 같은 슬래시 명령을 입력하면 다음 프롬프트에 섞여 들어가니, 응답이 끝난 뒤 입력하세요. Claude가 도구를 고르는 순서를 지켜보세요. 보통 앞부분 행 보기(수집) → Python으로 집계(수행) → 합계·중복 확인(검증) 순서입니다. 검증에서 숫자가 어긋나면 집계 방식을 고치고 다시 계산하는 수행 → 검증 반복도 볼 수 있습니다. 1,000행이 넘는 파일을 눈으로 읽는 대신 코드를 짜서 계산하는 점에도 주목하세요. 확인 창이 거의 뜨지 않는다면 정상입니다. Claude Code v2.1.283 이상은 Bedrock 대화형 세션을 모드 지정 없이 시작하면 auto 모드로 시작합니다. auto에서는 별도 분류기 모델이 위험한 동작만 막고 나머지는 묻지 않고 실행합니다. 입력창 아래 모드 표시를 확인해 보세요. auto의 경계 설정은 Ch2 Lab 2의 TASK 03에서 다룹니다.

TASK 02 · 컨텍스트와 세션 파일 (6분)

Step 1 · /context로 무엇이 자리를 차지하는지 보기

같은 세션에서 실행합니다.

text
/context
이 입력이 하는 일 (붙여넣는 곳: Claude 입력창)
  1. 컨텍스트(모델이 한 번에 볼 수 있는 글의 양)를 무엇이 얼마나 차지하는지 보여주는 명령입니다. 같은 세션의 Claude 입력창에 입력합니다.

시스템 프롬프트, 도구 정의, 메모리 파일, 대화가 각각 얼마나 차지하는지 보입니다. Ch5에서 이 숫자를 줄이는 방법을 다룹니다.

Step 2 · CLAUDE.md는 매 요청에 실린다

text
이 프로젝트용 CLAUDE.md를 10줄 이내로 만들어줘. data/는 가명처리된 읽기 전용 데이터다, 분석은 Python 3 표준 라이브러리로 한다, 집계 결과는 반드시 다른 방법으로 한 번 더 검증한다는 규칙을 넣어줘
이 입력이 하는 일 (붙여넣는 곳: Claude 입력창)
  1. CLAUDE.md는 Claude가 세션을 시작할 때마다 읽는 규칙 파일입니다. 이 프롬프트가 데이터는 읽기 전용, 분석은 Python 표준 라이브러리, 집계는 이중 검증이라는 세 규칙을 파일로 만들게 합니다. 10줄 이내로 제한하는 이유는 짧을수록 컨텍스트를 덜 쓰기 때문입니다.

CLAUDE.md는 세션을 시작할 때 읽히므로, 같은 세션에서 바로 /context를 실행하면 아직 보이지 않습니다. /exit로 나온 뒤 claude -c로 이어서 열고 /context를 실행해 Memory files 항목이 생긴 것을 확인합니다. 짧게 유지해야 하는 이유가 이 숫자입니다(공식 권장 200줄 이하). /context에는 Auto-compact window: 1m tokens도 보이는데, Ch5에서 이 값을 조정합니다.

Step 3 · 세션은 로컬 평문 파일

/exit로 나온 뒤 터미널에서 실행합니다.

Terminal, 전체 복사

bash
ls -lt ~/.claude/projects/*ch1-loop*/ | head -5
F=$(ls -t ~/.claude/projects/*ch1-loop*/*.jsonl | head -1)
wc -l "$F" && grep -o '"type":"[a-z_]*"' "$F" | sort | uniq -c | sort -rn | head
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. 내 실습 폴더(ch1-loop)의 세션 파일이 있는 폴더를 시간순으로 보여줍니다. 가장 위가 가장 최근 파일입니다.
  2. 가장 최근 .jsonl 파일의 경로를 F 변수에 담습니다. JSONL은 한 줄에 JSON 하나를 적는 텍스트 형식입니다.
  3. wc -l로 줄 수를 세고, 각 줄의 "type" 값(user, assistant 등)이 몇 번 나오는지 세고, 많이 나온 순으로 위 10개만 보여 줍니다. 대화가 줄 단위로 쌓인 모습을 볼 수 있습니다.

대화와 도구 결과가 이 PC(ccb-endpoint)에 JSONL로 남아 있습니다. 방금 읽힌 고객 데이터가 세션 파일에 그대로 들어 있는지 세어 봅니다.

Terminal, 전체 복사

bash
F=$(ls -t ~/.claude/projects/*ch1-loop*/*.jsonl | head -1)
grep -o '고객0' "$F" | wc -l
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. 방금과 같은 방법으로 가장 최근 세션 파일을 F에 담습니다.
  2. grep -o는 찾은 글자만 한 줄씩 출력하고, wc -l이 그 줄 수를 셉니다. 즉 파일에 고객0이 몇 번 나오는지 셉니다. 0이 아니면 고객 행이 평문으로 저장된 것입니다.

0이 아닌 숫자가 나오면 고객 행(고객0001 같은 이름)이 세션 파일에 원문 그대로 저장된 것입니다. 이번 데이터는 가명처리본이라 괜찮지만, 실제 고객 데이터라면 같은 방식으로 PC에 평문이 남습니다. 세션 파일의 보존 기간(cleanupPeriodDays)과 DLP 정책은 Ch2 Lab 1·2에서 다룹니다.

⚠

체크포인트가 되돌리지 못하는 것

DB 변경, 외부 API 호출, 배포, git push는 되돌릴 수 없습니다. 이런 작업은 실행 전에 막아야 하고, 그 방법이 Ch2 Lab 2의 가드레일입니다.

Step 2 · 권한 모드 전환

Shift+Tab을 눌러 모드가 바뀌는 순서를 확인합니다. auto에서 시작했다면 default(Manual) → accept edits → plan 순으로 돕니다. default에서는 편집과 명령 실행 전에 확인을 묻습니다. plan 모드에서 아래를 요청하면 파일을 고치지 않고 계획만 내놓습니다.

text
연령대별 표에 소득구간(income_band)별 퇴직연금 보유율을 추가하고, 결과를 summary.md로 저장하는 계획을 세워줘
이 입력이 하는 일 (붙여넣는 곳: Claude 입력창)
  1. plan 모드에서 입력합니다. plan 모드는 파일을 고치지 않고 계획만 세우는 모드입니다. 소득구간별 보유율을 더하는 계획이 나오는지 확인하세요.

계획 전에 Claude가 "표를 어떤 모양으로 만들까요?"처럼 선택지를 먼저 물을 수 있습니다. 추천 항목을 고르면 계획이 이어서 나옵니다. 계획만 확인하고 승인하지 않은 채 /exit로 나옵니다.

TASK 04 · Bedrock 데이터 경로 확인 (2분)

Bedrock 호출이 내 AWS 계정을 거쳐 기록된다는 것을 AWS 쪽 기록으로 확인합니다. 실제로 어느 리전에서 처리되는지는 추론 프로필이 정합니다.

Terminal, 전체 복사

bash
aws sts get-caller-identity --query Arn --output text
aws cloudtrail lookup-events --region us-east-1 --max-results 5 \
  --lookup-attributes AttributeKey=EventSource,AttributeValue=bedrock.amazonaws.com \
  --query 'Events[].{time:EventTime,name:EventName}' --output table
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. 지금 AWS에 접속한 주체(이 인스턴스의 역할)의 ARN을 출력합니다. 누구 이름으로 Bedrock을 부르는지 보여줍니다.
  2. CloudTrail(AWS 호출 기록)에서 Bedrock이 남긴 기록만 골라 가장 최근 5개를 가져옵니다. 줄 끝의 \ 는 명령이 다음 줄로 이어진다는 표시입니다.
  3. 시각과 이벤트 이름만 골라 표로 보여줍니다.

호출 주체가 이 인스턴스의 역할이고, Bedrock 호출 이력이 CloudTrail에 남는 것을 확인합니다. 이벤트가 아직 없다면 CloudTrail 반영에 몇 분 걸릴 수 있습니다.

⚠

호출 리전과 처리 리전은 다릅니다

이 랩은 us-east-1로 호출하지만 모델은 global 추론 프로필(global.anthropic.claude-*-5-5)입니다. global 프로필은 요청을 상용 리전 전체로 보낼 수 있으므로, 처리 리전이 호출 리전과 같다고 볼 수 없습니다. 처리 리전을 묶어야 하면 us.·apac. 같은 지역 프로필을 고정합니다(Ch2). PrivateLink는 네트워크 경로를 사설망으로 묶는 장치이고, 처리 리전과는 별개의 통제입니다.

ℹ

Bedrock 경로의 기본값

Bedrock 경로에서는 Anthropic으로 가는 오류 리포트와 텔레메트리가 기본으로 꺼져 있습니다. 이 환경의 사용량 텔레메트리는 같은 PC의 OpenTelemetry Collector로 가며, Ch6에서 대시보드로 확인합니다.
