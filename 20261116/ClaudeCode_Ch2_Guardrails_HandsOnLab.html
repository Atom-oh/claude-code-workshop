Ch2 Lab 2. 가드레일과 DLP

Hands-on Lab / Chapter 2, Lab 2

Claude Code Deep Dive Workshop, Chapter 2 Lab 2 - Bedrock 위에서 안전하게 쓰기, 가드레일과 DLP 실습

Claude Code에는 네이티브 DLP 기능이 없습니다. 이번 이야기의 주인공은 IT보안·플랫폼 담당자입니다. 분석팀이 마이데이터 고객 데이터를 Claude Code로 다루게 되면서, 원본 식별자가 프롬프트나 도구 입력으로 새어 나가지 않게 막는 일이 맡겨졌습니다. Ch2 강의에 이어지는 55분 실습 세션으로, 강의에서 본 DLP 5층 중 핵심인 훅(3층)을 managed 정책으로 강제하고, 고장 난 훅이 조용히 통과되는 fail-open 문제를 직접 확인합니다. 이어서 확인 창을 줄이는 auto mode에서 사람의 확인과 분류기의 판단 사이에 경계를 긋습니다. 시간이 남으면 선택 트랙으로 Sandbox(2층), Bedrock Guardrails(4층), 확장 통제(5층)를 이어서 해 봅니다.

소요 시간 필수 35분 + 선택 20분 · Task 준비 + 필수 3개 + 선택 3개 + 원복 · 기준 버전 Claude Code 2.1.x · Update 2026.11

⚠

테스트 데이터만 사용하세요

이 랩의 주민등록번호·카드번호·휴대폰·계좌번호는 형식만 맞춘 가짜 값입니다. raw/ 폴더도 데모용 가짜 데이터입니다. 실제 개인정보를 입력하지 마세요.

TASK 00 · 사전 준비 확인 (3분)

분석팀이 쓰는 데이터는 pseudo/(가명 토큰)이고, raw/에는 식별자가 그대로 있는 데모용 가짜 원본이 있습니다. DLP 훅이 무엇을 막고 무엇을 통과시키는지 보려면 둘 다 필요합니다. 키트를 이미 받았다면 내려받기 줄은 아무 일도 하지 않습니다.

Terminal, 전체 복사

bash
use_bedrock_direct >/dev/null
KIT=${WS_KIT:-s3://ws-assets-prod-iad-r-iad-ed304a55c2ca1aee/5b8d0649-9ad2-43a8-8ff5-10ce7bb42e6f/mydata-kit.zip}
[ -d ~/claude-lab/mydata/pseudo ] || (aws s3 cp "$KIT" /tmp/mydata-kit.zip --only-show-errors && mkdir -p ~/claude-lab/mydata && unzip -qo /tmp/mydata-kit.zip -d ~/claude-lab/mydata)
mkdir -p ~/claude-lab/ch3 && cd ~/claude-lab/ch3 && git init -q
ln -sfn ~/claude-lab/mydata/pseudo pseudo
head -3 ~/claude-lab/mydata/raw/customers.csv > customers.csv
head -3 ~/claude-lab/mydata/raw/cards.csv > cards.csv
sudo jq -e 'del(.forceLoginMethod, .forceLoginGatewayUrl) == {}' /etc/claude-code/managed-settings.json >/dev/null \
  && echo "정책 상태: 깨끗함" || echo "경고: 이전 챕터 정책이 남아 있습니다. 아래 '정책 초기화'를 먼저 실행하세요"
sudo cp /etc/claude-code/managed-settings.json ~/claude-lab/ch3/managed-settings.backup.json
which jq && sudo jq . /etc/claude-code/managed-settings.json
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. use_bedrock_direct는 이 PC를 기본 모드(Bedrock 직접 연결)로 맞추는 도우미 명령입니다. 이전 챕터에서 게이트웨이 모드로 바꿨다면 되돌립니다. >/dev/null은 화면에 나오는 메시지를 버립니다.
  2. 키트가 있는 S3 주소를 KIT 변수에 담고, ~/claude-lab/mydata/pseudo 폴더가 없을 때만 내려받아 풉니다. [ -d … ] ||는 "폴더가 없으면 뒤를 실행"이라는 뜻입니다. WS_KIT는 실습 환경이 미리 넣어 둔 이 이벤트의 키트 주소입니다. 이 값이 비어 있을 때만 :- 뒤의 공개 사본 주소를 씁니다.
  3. 실습 폴더 ch3를 만들고 그 안에서 git 저장소를 시작합니다(-q는 메시지를 줄입니다). 폴더 이름은 예전 번호를 그대로 쓴 것입니다. &&는 앞 명령이 성공했을 때만 다음을 실행합니다.
  4. ln -sfn은 바로가기(심볼릭 링크)를 만듭니다. 작업 폴더의 pseudo가 가명 데이터 폴더를 가리킵니다.
  5. 원본 CSV의 앞 3줄만 작업 폴더로 복사합니다. >는 출력을 파일로 저장합니다. 원본 파일은 건드리지 않습니다. 이 값들은 모두 가짜 데모 데이터입니다.
  6. managed-settings에 이전 챕터의 흔적이 있는지 확인합니다. sudo는 관리자 권한으로 실행하라는 뜻입니다. jq -e는 결과가 거짓이면 실패로 끝나고, del(…) == {}는 게이트웨이용 키 두 개를 빼면 파일이 빈 {}인지 묻습니다. 참이면 "깨끗함", 아니면 경고를 출력합니다. 줄 끝의 \는 다음 줄과 이어진 한 명령이라는 표시입니다.
  7. 지금의 managed-settings를 managed-settings.backup.json으로 복사해 둡니다. TASK 07에서 이 파일로 되돌립니다.
  8. which jq는 jq가 설치된 경로를 보여 주고, 없으면 아무것도 출력하지 않아 뒤 명령이 실행되지 않습니다. DLP 스크립트가 jq에 의존하므로 먼저 확인합니다. 이어서 정책 파일을 읽기 좋게 출력합니다.

customers.csv와 cards.csv는 원본 3줄(가짜 데모 데이터)을 작업 폴더로 복사한 것입니다. head -3로 앞 몇 줄만 복사하므로 원본 데이터는 그대로입니다.

⚠

"이전 챕터 정책이 남아 있습니다"가 나오면, 정책 초기화

이전 챕터의 원복을 건너뛰면 그 정책이 이번 챕터의 백업에 섞여 들어가고, 원복해도 계속 남습니다(예: Opus를 뺀 모델 목록). 백업 전에 아래로 초기화한 뒤 위 블록을 다시 실행하세요.

bash
echo '{}' | sudo tee /etc/claude-code/managed-settings.json >/dev/null
sudo rm -f /etc/claude-code/managed-settings.d/*.json
use_bedrock_direct
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. 빈 JSON {}를 managed-settings.json에 씁니다. 일반 > 리다이렉션은 sudo 권한을 받지 못하므로 sudo tee로 파일에 씁니다. >/dev/null은 화면 출력을 버립니다.
  2. managed-settings.d/ 아래 조각 파일(drop-in)을 모두 지웁니다. -f는 파일이 없어도 오류를 내지 않습니다.
  3. 기본 모드로 되돌리는 도우미 명령을 다시 실행합니다.

CHECKPOINT

TASK 01 · DLP 훅을 정책으로 강제 (10분)

ℹ

회사 PC(macOS · Windows)라면

이 스크립트는 bash와 jq를 전제로 합니다. macOS는 같은 스크립트를 쓰되 jq를 함께 배포하고, Windows는 Git Bash로 실행하거나 PowerShell 스크립트(powershell -File …)로 다시 작성해야 합니다. 의존성이 빠진 PC에서는 훅이 오류로 끝나며 조용히 통과(fail-open) 하므로, TASK 02의 fail-closed 원칙이 더 중요해집니다. 샌드박스(선택 TASK 04)는 macOS는 내장 Seatbelt, Linux·WSL2는 bubblewrap을 쓰며 네이티브 Windows는 지원하지 않습니다.

먼저 훅이 입력을 검사하는 흐름을 그림으로 봅니다. 아래 Step에서 이 스크립트를 직접 만들고 시험합니다.

Step 1 · 검사 스크립트 배치

스크립트는 관리자만 쓸 수 있는 경로(/opt/dlp)에 둡니다. 프롬프트(UserPromptSubmit)는 .prompt, 도구 호출(PreToolUse)은 .tool_input을 검사합니다. exit 2가 차단입니다.

Terminal, 전체 복사

bash
sudo mkdir -p /opt/dlp
sudo tee /opt/dlp/dlp-guard.sh > /dev/null << 'EOF'
#!/bin/bash
INPUT=$(cat)
TEXT=$(echo "$INPUT" | jq -r '.prompt // (.tool_input | tostring)')

# 주민등록번호 · 카드번호 · 휴대폰 · 계좌번호 · AWS 액세스 키 (탐지 예시)
PAT='(^|[^0-9])([0-9]{6}-[1-4][0-9]{6}|[0-9]{4}-[0-9]{4}-[0-9]{4}-[0-9]{4}|01[016789]-[0-9]{3,4}-[0-9]{4}|[0-9]{3}-[0-9]{2,6}-[0-9]{5,7})([^0-9]|$)|AKIA[0-9A-Z]{16}'

if echo "$TEXT" | grep -Eq "$PAT"; then
  echo "DLP: 민감정보 패턴이 감지되어 차단했습니다" >&2
  exit 2
fi
exit 0
EOF
sudo chmod 755 /opt/dlp/dlp-guard.sh
echo '{"prompt":"내 번호는 900101-1234567"}' | /opt/dlp/dlp-guard.sh; echo "exit=$?"
echo '{"prompt":"연락처 010-0123-4567"}' | /opt/dlp/dlp-guard.sh; echo "exit=$?"
echo '{"prompt":"계좌 123-456789-01234"}' | /opt/dlp/dlp-guard.sh; echo "exit=$?"
echo '{"prompt":"안녕하세요"}' | /opt/dlp/dlp-guard.sh; echo "exit=$?"
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. 관리자만 고칠 수 있는 폴더 /opt/dlp를 만듭니다. -p는 이미 있어도 오류를 내지 않습니다.
  2. << 'EOF'부터 EOF까지는 heredoc입니다. 여러 줄을 한 번에 파일로 쓰는 방법입니다. 'EOF'에 따옴표를 붙이면 $ 변수를 셸이 미리 풀지 않고 글자 그대로 파일에 씁니다. sudo tee는 관리자 권한으로 파일에 쓰고, > /dev/null은 화면 중복 출력을 버립니다.
  3. 이 파일을 bash로 실행하라는 첫 줄(shebang)입니다.
  4. Claude Code가 훅에 표준입력으로 넘기는 JSON 전체를 읽어 INPUT 변수에 담습니다. $(cat)은 명령의 출력을 변수에 담는 문법입니다.
  5. jq -r로 JSON에서 검사할 글자를 꺼냅니다. .prompt가 있으면(프롬프트 훅) 그 값을, 없으면 // 뒤의 .tool_input(도구 호출 훅)을 tostring으로 글자로 바꿔 TEXT에 담습니다. -r은 따옴표 없이 글자만 출력하는 옵션입니다.
  6. 탐지할 패턴을 PAT에 담습니다. |로 이은 다섯 개 정규식입니다. 주민등록번호([0-9]{6}-[1-4][0-9]{6}), 카드번호(4자리 4묶음), 휴대폰(01[016789]-…), 계좌번호, AWS 액세스 키(AKIA + 16자)입니다. 앞의 네 개는 (^|[^0-9])( … )([^0-9]|$)로 감싸, 앞뒤가 숫자로 이어지지 않을 때만 걸리게 했습니다. 그래야 170767500-170886300 같은 금액 계산이나 20260928-20261028 같은 기간 표기의 일부가 주민등록번호로 잘못 걸리지 않습니다. 작은따옴표 안이라 셸이 내용을 바꾸지 않습니다.
  7. grep -Eq로 TEXT에 패턴이 있는지 검사합니다. -E는 확장 정규식, -q는 출력 없이 종료 코드만 돌려 줍니다. 일치하면 종료 코드 0이라 then 쪽으로 갑니다.
  8. 차단 이유를 표준 오류(>&2)로 출력합니다. 프롬프트 훅이면 사용자에게, 도구 호출 훅이면 Claude에게 차단 이유로 전달됩니다.
  9. exit 2는 "차단"입니다. 훅에서 차단하는 종료 코드는 2뿐입니다.
  10. 패턴이 없으면 if를 지나 exit 0으로 끝나고, Claude Code는 그대로 진행합니다.
  11. chmod 755는 모든 사용자가 실행할 수 있게 하고 쓰기는 소유자(root)만 허용합니다.
  12. 가짜 JSON을 스크립트에 파이프로 넣어 시험합니다. echo "exit=$?"는 방금 실행한 스크립트의 종료 코드를 보여 줍니다. 주민등록번호·휴대폰·계좌번호는 2, "안녕하세요"는 0이 나와야 합니다.

앞의 세 줄(주민등록번호·휴대폰·계좌번호)은 exit=2, 마지막 줄은 exit=0이 나와야 합니다.

Step 2 · managed 정책에 훅 등록

Terminal, 전체 복사

bash
cat > /tmp/policy.json << 'EOF'
{
  "allowManagedHooksOnly": true,
  "hooks": {
    "UserPromptSubmit": [
      { "hooks": [{ "type": "command", "command": "/opt/dlp/dlp-guard.sh" }] }
    ],
    "PreToolUse": [
      { "matcher": "Bash|Write|Edit|WebFetch",
        "hooks": [{ "type": "command", "command": "/opt/dlp/dlp-guard.sh" }] }
    ]
  }
}
EOF
M=/etc/claude-code/managed-settings.json
sudo jq -s '.[0] * .[1]' $M /tmp/policy.json | sudo tee $M.tmp >/dev/null && sudo mv $M.tmp $M
sudo jq . /etc/claude-code/managed-settings.json >/dev/null && echo "policy OK"
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. heredoc으로 정책 조각을 임시 파일 /tmp/policy.json에 씁니다.
  2. allowManagedHooksOnly: true는 managed 설정의 훅만 실행하고 사용자·프로젝트 훅은 무시하게 합니다.
  3. UserPromptSubmit 훅입니다. 분석가가 프롬프트를 보낼 때마다 /opt/dlp/dlp-guard.sh를 실행합니다.
  4. PreToolUse 훅입니다. matcher의 |는 "또는"이라서 Bash·Write·Edit·WebFetch 도구를 실행하기 직전에만 같은 스크립트를 부릅니다. Read 같은 다른 도구는 이 훅을 부르지 않습니다.
  5. 정책 파일 경로를 M 변수에 담습니다.
  6. jq -s '.[0] * .[1]'은 두 파일을 읽어 합칩니다(*는 깊은 병합이고 같은 키는 뒤 파일이 이깁니다). 결과를 먼저 .tmp에 쓰고 mv로 바꿔 넣으므로, 쓰다가 실패해도 기존 정책이 깨지지 않습니다.
  7. 합쳐진 파일이 올바른 JSON인지 jq .로 확인하고, 통과하면 policy OK를 출력합니다.
ℹ

파일을 덮어쓰지 않고 병합합니다

jq -s '.[0] * .[1]'로 기존 managed-settings에 정책을 합칩니다. 게이트웨이 모드(use_gateway)에서 실행해도 forceLoginMethod·forceLoginGatewayUrl이 지워지지 않고, 원복은 TASK 00의 백업 파일로 합니다.

allowManagedHooksOnly는 사용자·프로젝트 훅을 무시하고 managed 훅만 실행하게 합니다. 사용자가 DLP 훅을 끄거나 덮어쓸 수 없습니다.

  1. 실습 폴더에서 Claude Code를 시작합니다. 시작할 때 managed 정책을 읽어 훅을 적용합니다.

아래 요청을 차례로 보냅니다. 먼저 분석팀이 실제로 하는 일, 곧 가명 데이터 분석이 훅에 걸리지 않는지 봅니다.

이 블록이 하는 일 (붙여넣는 곳: Claude 입력창)
  1. 분석팀이 실제로 하는 일, 곧 가명 데이터 요약 요청입니다. 프롬프트에 DLP 패턴이 없으므로 UserPromptSubmit 훅이 exit 0으로 통과시킵니다.

가명 토큰(CI_...)에는 DLP 패턴이 없으므로 훅을 통과해 요약이 나옵니다. 같은 요청을 비대화형으로 보내도 같습니다.

bash
claude -p "pseudo/customers.csv 연령대 분포를 요약해줘"; echo "claude exit=$?"

TASK 02 · fail-open 함정 확인과 수정 (5분)

스크립트가 고장 났을 때 훅이 막는지 통과시키는지를 먼저 그림으로 비교합니다.

Step 1 · 고장 난 훅은 통과된다

jq가 없는 PC를 흉내 내기 위해 스크립트의 jq를 없는 명령으로 바꿉니다.

Terminal, 전체 복사

bash
sudo sed -i 's/| jq -r/| jq-missing -r/' /opt/dlp/dlp-guard.sh
echo '{"prompt":"내 번호는 900101-1234567"}' | /opt/dlp/dlp-guard.sh; echo "exit=$?"
cd ~/claude-lab/ch3 && claude -p "고객 900101-1234567 을 한 줄로 요약해줘"; echo "claude exit=$?"
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. sed -i는 파일을 직접 고칩니다. s/찾을 글자/바꿀 글자/ 형식으로 | jq -r을 | jq-missing -r로 바꿔, 존재하지 않는 명령을 부르게 만듭니다. jq가 없는 PC를 흉내 내는 방법입니다.
  2. 주민등록번호가 든 입력을 스크립트에 직접 넣습니다. jq를 못 찾아 TEXT가 비고 grep이 아무것도 못 찾으므로, 스크립트는 exit=0으로 끝납니다.
  3. 같은 주민등록번호가 든 프롬프트를 Claude에 보냅니다. 훅이 통과시키므로 Claude가 그대로 응답합니다. 이것이 fail-open입니다.

스크립트는 exit=0으로 끝나고 Claude는 그대로 응답합니다. 훅에서 exit 2만 차단이고, 그 외의 오류는 비차단 오류로 처리되어 작업이 계속됩니다.

Step 2 · fail-closed로 고치기

오류 경로에서도 명시적으로 exit 2를 내도록 바꿉니다.

Terminal, 전체 복사

bash
sudo tee /opt/dlp/dlp-guard.sh > /dev/null << 'EOF'
#!/bin/bash
INPUT=$(cat)
command -v jq >/dev/null || { echo "DLP: 검사기 오류(jq 없음) - 안전을 위해 차단" >&2; exit 2; }
TEXT=$(echo "$INPUT" | jq -r '.prompt // (.tool_input | tostring)') || { echo "DLP: 입력 해석 실패 - 차단" >&2; exit 2; }

PAT='(^|[^0-9])([0-9]{6}-[1-4][0-9]{6}|[0-9]{4}-[0-9]{4}-[0-9]{4}-[0-9]{4}|01[016789]-[0-9]{3,4}-[0-9]{4}|[0-9]{3}-[0-9]{2,6}-[0-9]{5,7})([^0-9]|$)|AKIA[0-9A-Z]{16}'
echo "$TEXT" | grep -Eq "$PAT"; RC=$?
[ "$RC" -eq 1 ] && exit 0      # 1 = 패턴 없음 → 통과
if [ "$RC" -eq 0 ]; then
  echo "DLP: 민감정보 패턴이 감지되어 차단했습니다" >&2
else
  echo "DLP: 검사기 오류(grep 종료 코드 $RC) - 안전을 위해 차단" >&2
fi
exit 2
EOF
echo '{"prompt":"내 번호는 900101-1234567"}' | /opt/dlp/dlp-guard.sh; echo "exit=$?"
echo '{"prompt":"안녕하세요"}' | /opt/dlp/dlp-guard.sh; echo "exit=$?"
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. 앞과 같은 heredoc입니다. 이번에는 스크립트 전체를 오류 처리가 있는 새 내용으로 덮어씁니다.
  2. 훅 입력 JSON을 INPUT에 담습니다.
  3. command -v jq로 jq가 있는지 확인합니다. 없으면 || 뒤의 { …; } 묶음이 실행되어 메시지를 출력하고 exit 2로 차단합니다. >/dev/null은 경로 출력을 버립니다.
  4. 앞과 같은 jq 추출입니다. 끝의 || { … exit 2; }가 더해져, jq 실행 자체가 실패하면(예: 입력이 JSON이 아님) 차단합니다.
  5. 탐지 패턴 PAT입니다. 앞 스크립트와 같습니다.
  6. grep으로 검사한 뒤 종료 코드를 RC에 저장합니다. grep의 종료 코드는 0이 일치, 1이 불일치, 그 밖의 값이 오류입니다.
  7. RC가 1(불일치)일 때만 exit 0으로 통과시킵니다. &&는 앞 조건이 참일 때만 뒤를 실행합니다. 뒤의 # 부분은 설명 주석입니다.
  8. 여기까지 온 것은 RC가 0이거나 오류인 경우입니다. 0이면 "민감정보 감지", 그 밖이면 "검사기 오류" 메시지를 내고, 어느 쪽이든 마지막 exit 2로 차단합니다. 통과 조건을 하나로 좁혀 오류가 나도 막는 것이 fail-closed입니다.
  9. 시험합니다. 첫 줄(주민등록번호)은 exit=2, 둘째 줄("안녕하세요")은 exit=0이어야 합니다.

첫 줄은 exit=2, 둘째 줄은 exit=0입니다. grep도 jq처럼 실행 오류가 날 수 있으므로, 종료 코드를 0(일치)·1(불일치)·그 밖(오류) 으로 나눠 오류일 때도 차단합니다. if grep ...; then 형태로 쓰면 grep 오류가 "불일치"와 같게 처리되어 통과됩니다(실습 환경에서 확인).

Step 3 · 스크립트가 아예 없거나 멈춰도 막기

스크립트 안의 처리로는 스크립트가 없거나, 시작하지 못하거나, 시간 초과인 경우를 막을 수 없습니다. 이때도 그대로 통과됩니다. 훅 설정에 "onFailure": "block"(v2.1.295+)을 넣으면 이런 실패도 차단으로 처리됩니다.

Terminal, 전체 복사

bash
M=/etc/claude-code/managed-settings.json
sudo jq '(.hooks[][].hooks[]) |= . + {"onFailure": "block"}' $M | sudo tee $M.tmp >/dev/null && sudo mv $M.tmp $M
sudo jq -c '[.hooks[][].hooks[].onFailure]' $M
sudo mv /opt/dlp/dlp-guard.sh /opt/dlp/dlp-guard.sh.off
cd ~/claude-lab/ch3 && claude -p "안녕이라고만 답해줘"; echo "claude exit=$?"
sudo mv /opt/dlp/dlp-guard.sh.off /opt/dlp/dlp-guard.sh
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. 정책 파일 경로를 M 변수에 담습니다.
  2. .hooks[][].hooks[]는 이벤트(UserPromptSubmit, PreToolUse)별 목록을 따라 내려가 훅 항목을 하나씩 고릅니다. |= . + {…}가 각 훅 항목에 "onFailure": "block"을 더합니다. 결과는 .tmp에 쓴 뒤 mv로 교체합니다.
  3. 각 훅의 onFailure 값만 한 줄(-c)로 보여 줍니다. 훅이 둘이므로 ["block","block"]이 나와야 합니다.
  4. 스크립트 이름을 .off로 바꿔 "스크립트가 없는" 상태를 만듭니다.
  5. 민감정보가 없는 프롬프트를 보냅니다. 스크립트가 없어도 onFailure: block 때문에 차단됩니다. 뒤의 echo는 종료 코드를 보여 줍니다.
  6. 스크립트를 원래 이름으로 되돌립니다. 이 줄을 빼먹으면 이후 요청이 계속 차단됩니다.

스크립트를 치운 상태에서는 민감정보가 없는 프롬프트도 UserPromptSubmit operation blocked by hook: … blocking because onFailure is "block"으로 차단됩니다. 마지막 줄에서 스크립트를 되돌립니다.

선택 TASK 04 · Sandbox로 curl 갭 막기 (7분)

권한 규칙 deny: Bash(curl *)는 python3 -c "import urllib.request..." 같은 우회를 막지 못합니다. Sandbox는 Claude가 실행하는 Bash 명령의 네트워크를 OS 수준에서 허용 목록으로 묶습니다.

Step 1 · 필요 도구 확인

Linux의 sandbox는 bubblewrap과 socat을 사용합니다.

bash
which bwrap socat || sudo dnf install -y bubblewrap socat
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. 샌드박스에 필요한 bwrap과 socat이 있는지 찾습니다. 하나라도 없으면 || 뒤의 sudo dnf install -y가 둘을 설치합니다. -y는 확인 질문에 자동으로 예라고 답합니다.
ℹ

설치가 실패하면 이 선택 TASK는 건너뛰고 TASK 05로 갑니다.

Step 2 · 정책에 sandbox 추가

bash
sudo jq '. + {"sandbox": {"enabled": true, "failIfUnavailable": true, "allowUnsandboxedCommands": false, "network": {"allowManagedDomainsOnly": true, "allowedDomains": ["pypi.org", "files.pythonhosted.org"]}}}' \
  /etc/claude-code/managed-settings.json | sudo tee /tmp/ms.json >/dev/null && sudo mv /tmp/ms.json /etc/claude-code/managed-settings.json
cd ~/claude-lab/ch3 && claude
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. 기존 정책에 sandbox 설정을 더합니다. enabled로 켜고, failIfUnavailable로 도구가 없으면 시작 자체를 막고, allowUnsandboxedCommands: false로 샌드박스 밖 재실행을 막고, allowManagedDomainsOnly와 allowedDomains로 pypi.org와 files.pythonhosted.org만 허용합니다. 결과는 임시 파일을 거쳐 교체합니다.
  2. 실습 폴더에서 Claude Code를 시작합니다.
text
python3로 https://example.com 에 HTTP 요청을 보내서 상태 코드를 알려줘. curl은 쓰지 마
이 블록이 하는 일 (붙여넣는 곳: Claude 입력창)
  1. curl을 못 쓰게 하고 python으로 우회하게 하는 요청입니다. 샌드박스는 도구가 아니라 OS 수준에서 네트워크를 막으므로, 허용 목록에 없는 example.com 연결은 막힙니다.

허용 목록 밖의 도메인이라 연결이 막힙니다. Claude가 허용 목록을 넓혀 다시 시도하려 해도 allowed_domains cannot widen network access로 거부됩니다. /sandbox로 현재 상태를 확인한 뒤 /exit로 나옵니다.

키 없으면 생기는 일
network.allowManagedDomainsOnly auto 모드에서 Claude가 명령에 allowed_domains를 붙여 목록을 넓히고, 분류기가 승인하면 그대로 연결됩니다(실습 환경에서 example.com 연결 성공을 확인)
allowUnsandboxedCommands: false 샌드박스에서 실패한 명령을 샌드박스 밖에서 다시 실행할 수 있습니다
failIfUnavailable bubblewrap 같은 의존성이 없으면 샌드박스 없이 실행됩니다
⚠

범위

Sandbox는 Claude가 실행하는 Bash에 적용됩니다. Ch4에서 다룰 mod가 띄운 프로세스는 sandbox 밖에서 돕니다.

선택 TASK 05 · Bedrock Guardrails로 계정 쪽 필터 (7분)

Guardrails는 PC가 아니라 AWS 계정 쪽에서 동작하는 층입니다. 한국 주민등록번호 정규식을 차단하는 Guardrail을 만들고 판정을 직접 확인합니다.

ℹ

create-guardrail이 권한·할당량 오류(AccessDenied, ServiceQuotaExceeded)로 실패하면 이 선택 TASK는 강사 화면으로 보고 TASK 06으로 갑니다.

Terminal, 전체 복사

bash
GR=$(aws bedrock create-guardrail --region us-east-1 --name "ws-dlp-$(date +%s)" \
  --blocked-input-messaging "민감정보가 포함되어 차단되었습니다." \
  --blocked-outputs-messaging "민감정보가 포함되어 차단되었습니다." \
  --sensitive-information-policy-config '{"regexesConfig":[{"name":"kr-rrn","pattern":"[0-9]{6}-[1-4][0-9]{6}","action":"BLOCK"}],"piiEntitiesConfig":[{"type":"CREDIT_DEBIT_CARD_NUMBER","action":"ANONYMIZE"}]}' \
  --query guardrailId --output text) && echo "guardrail: $GR"

aws bedrock-runtime apply-guardrail --region us-east-1 --guardrail-identifier "$GR" --guardrail-version DRAFT \
  --source INPUT --content '[{"text":{"text":"고객 900101-1234567 을 조회해줘"}}]' --query '{action:action,out:outputs[0].text}'
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. create-guardrail로 Guardrail을 만듭니다. 이름 끝의 $(date +%s)는 현재 시각(초)이라 이름이 겹치지 않습니다.
  2. 입력이나 출력이 차단될 때 보여 줄 메시지입니다.
  3. 민감정보 정책입니다. kr-rrn은 주민등록번호 정규식을 BLOCK(차단)하고, 카드번호(CREDIT_DEBIT_CARD_NUMBER)는 ANONYMIZE(가림 처리)합니다.
  4. --query guardrailId로 ID만 뽑아 GR 변수에 담고, 성공하면 출력합니다.
  5. apply-guardrail은 모델을 부르지 않고 글자만 Guardrail에 검사시킵니다. --source INPUT은 사용자 입력으로 보라는 뜻이고 DRAFT는 아직 발행하지 않은 작업본입니다. 마지막 --query가 판정(action)과 처리된 글자만 보여 줍니다.

action이 GUARDRAIL_INTERVENED로 나옵니다. Claude Code에 연결할 때는 버전을 발행한 뒤 아래처럼 헤더로 붙입니다(이 랩에서는 읽기만 합니다).

json
{
  "env": {
    "ANTHROPIC_CUSTOM_HEADERS": "X-Amzn-Bedrock-GuardrailIdentifier: <guardrail-id>\nX-Amzn-Bedrock-GuardrailVersion: 1"
  }
}
이 JSON이 하는 일 (붙여넣지 않음, 참고용)
  1. settings.json의 env에 들어갈 모양입니다. ANTHROPIC_CUSTOM_HEADERS에 헤더 두 줄(Guardrail ID와 버전)을 \n으로 이어 Claude Code가 보내는 요청에 붙입니다. 버전은 발행한 번호입니다. 이 랩에서는 읽기만 합니다.
ℹ

cross-region 추론 프로파일을 쓸 때

이 환경처럼 global/us 추론 프로파일을 쓰면 Guardrail에도 cross-region 설정이 필요합니다. 연결 전 공식 문서의 Guardrails 절을 확인하세요.

선택 TASK 06 · 확장 통제 맛보기 (4분)

허가되지 않은 플러그인을 로컬 디렉터리로 몰래 싣는 것(사이드로드)을 막습니다.

bash
sudo jq '. + {"strictKnownMarketplaces": [], "disableSideloadFlags": true}' \
  /etc/claude-code/managed-settings.json | sudo tee /tmp/ms.json >/dev/null && sudo mv /tmp/ms.json /etc/claude-code/managed-settings.json
mkdir -p /tmp/rogue/.claude-plugin && echo '{"name":"rogue","version":"0.0.1"}' > /tmp/rogue/.claude-plugin/plugin.json
cd ~/claude-lab/ch3 && claude --plugin-dir /tmp/rogue -p "hi"; echo "exit=$?"
이 블록이 하는 일 (붙여넣는 곳: 터미널)
  1. 정책에 strictKnownMarketplaces: [](허용하는 마켓플레이스 목록을 빈 목록으로)와 disableSideloadFlags: true(--plugin-dir 같은 사이드로드 플래그 금지)를 더합니다. 결과는 임시 파일을 거쳐 교체합니다.
  2. 시험용 가짜 플러그인 rogue를 만듭니다. plugin.json에는 이름과 버전만 넣었습니다.
  3. --plugin-dir로 로컬 폴더의 플러그인을 몰래 싣는 시도입니다. 정책이 거부하는지 보고, echo가 종료 코드를 보여 줍니다.

--plugin-dir가 정책으로 거부됩니다. 허용 목록(strictKnownMarketplaces)만으로는 사이드로드를 막지 못해서 disableSideloadFlags를 함께 씁니다.

for g in $(aws bedrock list-guardrails --region us-east-1 --query "guardrails[?starts_with(name,'ws-dlp-')].id" --output text); do
