R2-2 기획안 작성: 같은 plugin으로 분석 결과를 상품이나 서비스 기획안으로

R2-1과 같은 agent를 그대로 쓰고, plugin의 proposal-draft skill이 정한 형식으로 기획안을 만든 뒤, 두 업무 모두 agent와 skill을 새로 짜지 않았음을 보인다

분석 리포트와 기획안은 다른 업무지만 데이터, 데이터를 모으는 agent, 근거를 검토하는 agent는 같습니다. 바뀌는 것은 절차와 출력 형식뿐이고, 그것은 R2 공통 단계에서 plugin에 넣은 proposal-draft skill이 맡습니다. 이 미션에서는 동료 폴더 ~/claude-lab/capstone-try/에서 리포트 하나를 근거로 기획안을 만들고, R2-1과 R2-2가 같은 plugin 하나로 됐다는 것을 확인합니다.

5분

plugin이 설치돼 있고 지문이 그대로인지, 근거로 쓸 리포트가 있는지 봅니다.

왜 필요한가요: proposal-draft skill의 입력은 근거 리포트 파일입니다. 리포트가 있어야 기획안의 수치가 그 파일을 출처로 삼습니다.

Terminal, 전체 복사
cd ~/claude-lab/capstone-try && . ~/claude-lab/capstone/r2.env
claude plugin list --json | jq -r '.[] | select(.enabled) | "\(.id) \(.scope)"'
(cd ~/claude-lab/capstone/marketplace/plugins/$KIT && sha256sum -c ~/claude-lab/capstone-try/kit.sha)
ls -A .claude

켜진 plugin 목록에 my-kit@capstone-local local 한 줄만 보이고(다른 plugin이 보이면 R2 공통 04의 3번 블록), 지문이 모두 OK여야 합니다. 이어서 근거 리포트를 봅니다.

Terminal
ls reports/

R2-1을 했다면 리포트가 이미 있습니다. R2-1 대신 R2-3을 고른 사람은 세션에서 R2-1 01 표의 첫 번째 명령 하나만 먼저 보내 근거 리포트를 만듭니다. 그 리포트도 같은 plugin의 skill로 만든 것입니다.

CHECKPOINT
01

기획안 초안

15분

근거 리포트 파일과 기획 주제를 주고 /my-kit:proposal-draft로 기획안을 proposals/에 만듭니다.

왜 필요한가요: R2-1과 다른 업무지만 같은 plugin의 두 agent를 그대로 씁니다. 바뀌는 것은 skill(절차와 출력 형식을 적은 SKILL.md) 하나입니다. 아래 그림의 단계를 넘기며 R2-1과 무엇이 같은지 봅니다.

Terminal
cd ~/claude-lab/capstone-try && claude
Claude 세션 입력, 형식
/my-kit:proposal-draft reports/(근거 리포트 파일) (기획 주제)

파일 이름은 ls reports/에서 본 .md 파일 이름을 그대로 씁니다. 주제는 예시이고, 내 업무에 맞게 바꿔도 됩니다.

트랙예시 (근거 리포트 파일 이름은 내 것으로)
A 마이데이터/my-kit:proposal-draft reports/(세그먼트 a 리포트) 세그먼트 (a) 고객 맞춤 상담 서비스. 고객 사례 한 명은 my-kit:consult-prep 으로 준비
B 서울 부동산/my-kit:proposal-draft reports/(강남구 202610 리포트) 강남구 실거래 시세 브리핑을 곁들인 주택담보대출 사전 상담 서비스
C alphavantage/my-kit:proposal-draft reports/(환율 리포트) 환율과 금리 변동을 알려 주는 외화예금 고객 알림 서비스
C aws-knowledge/my-kit:proposal-draft reports/(서울 리전 리포트) 서울 리전 기반 신규 서비스 도입 검토안
C microsoft-learn/my-kit:proposal-draft reports/(Entra ID 리포트) 영업점 직원 계정의 조건부 액세스 도입안
C deepwiki, docs, github/my-kit:proposal-draft reports/(내 리포트) (리포트 주제로 풀 업무 개선안 한 가지)

트랙 A는 R1에서 새로 만든 consult-prep을 이 미션에서 씁니다. skill은 요청에 적힌 my-kit: agent에게 일을 맡기도록 돼 있어서, skill을 고치지 않고도 고객 사례를 그 agent에게 맡길 수 있습니다.

Terminal 2, 전체 복사
cd ~/claude-lab/capstone-try
ls -l proposals/
for f in proposals/*.md; do echo "== $f"; grep -E '^#' "$f" | head -10; done

제목 줄에 배경과 문제, 대상, 제안 내용, 기대 효과와 측정 지표, 리스크와 유의사항, 근거 표, 검토 결과의 일곱 항목이 그 순서로 있어야 합니다. 근거 표의 출처가 reports/의 파일과 항목을 가리키는지도 봅니다.

CHECKPOINT
02

검토 반영

10분

검토 agent가 낸 WARN이나 FAIL을 프롬프트로 고치고 다시 검토받습니다. skill과 agent 파일은 그대로 둡니다.

기획안 끝의 검토 결과가 PASS면 이 단계는 건너뜁니다. WARN이나 FAIL이면 아래처럼 고칠 부분만 요청합니다.

왜 필요한가요: 이번 기획안 하나의 문제를 프롬프트로 고치면 skill과 agent 파일이 그대로 남아, 03의 지문 검사가 통과합니다.

Claude 세션 입력
방금 검토에서 WARN이나 FAIL로 나온 항목만 고쳐 같은 파일에 다시 저장하고, 같은 검토 agent로 한 번 더 검토해 주세요. skill과 agent 파일은 고치지 마세요.
자주 나오는 지적고치는 방법
근거 표에 없는 수치가 본문에 있다그 수치를 빼거나, 모으는 agent에게 그 수치만 추가로 확인받아 근거 표에 넣는다
기준일이 없거나 오래됐다리포트의 기간을 본문에 적고, 오래된 값은 "확인 필요"로 표시한다
고객이나 거래를 특정할 수 있는 표현이 있다"고객 A", 법정동 수준처럼 R1에서 정한 표기로 바꾼다
왜 프롬프트로 고치나 이번 기획안 하나의 문제는 프롬프트로 고칩니다. 모든 기획안에서 반복되는 문제라면 그때 skill의 형식을 고치고 버전을 올려 다시 배포합니다(R2-1 03의 안내와 같음). 이 구분이 "업무마다 다시 짜기"와 "plugin을 고쳐 가며 쓰기"의 차이입니다.

03

재사용 확인

10분

리포트와 기획안, 두 업무를 같은 plugin 하나로 해 냈고 그동안 agent와 skill을 새로 짜지 않았음을 보입니다.

왜 필요한가요: 리포트와 기획안 두 업무를 같은 plugin으로 해 냈다는 것이 완주 체크리스트 6번입니다. 지문 검사가 그 기준입니다.

Terminal 2, 전체 복사
cd ~/claude-lab/capstone-try && . ~/claude-lab/capstone/r2.env
(cd ~/claude-lab/capstone/marketplace/plugins/$KIT && sha256sum -c ~/claude-lab/capstone-try/kit.sha)
find . -path ./.git -prune -o \( -path '*/agents/*' -o -name SKILL.md \) -print
ls -lt ~/.claude/agents ~/.claude/skills 2>/dev/null
claude plugin details $KIT@capstone-local | grep -E 'Skills|Agents|Hooks|MCP servers'

sha256sum -c가 모두 OK, find 출력이 비어 있고, claude plugin details의 수가 R2 공통 04와 같으면 됩니다. ls -lt ~/.claude/agents ~/.claude/skills에 보이는 사용자 수준의 것은 앞선 실습에서 만든 것이라 "새로 짠 것"으로 세지 않습니다(이름에 my-kit:이 없어 구분됨). 날짜가 오늘 R2 시간대인 파일이 있으면 이번 업무를 위해 새로 짠 것이니 지우거나 plugin으로 옮깁니다. 세션에서도 물어봅니다.

Claude 세션 입력
이번 세션에서 쓴 skill과 subagent의 이름을 모두 적고, 각각 어디서 왔는지(plugin 이름, 또는 이 폴더) 알려 주세요.

아래 표를 채워 출품 양식 3번에 붙입니다. "새로 짠 것" 칸이 비어 있어야 재사용이 증명됩니다.

업무 1 (R2-1 정기 리포트)업무 2 (R2-2 기획안)
skillmy-kit:periodic-reportmy-kit:proposal-draft
agent모으는 agent, 검토 agent같은 두 agent (트랙 A는 consult-prep도)
데이터 경로같은 plugin의 MCP 서버 (트랙 A는 pseudo/ 파일)
가드레일같은 plugin 훅과 폴더 설정의 deny 규칙
새로 짠 것없음없음

04

정리와 출품

5분

결과물에 개인정보 패턴과 키가 없는지 보고, 출품 양식을 채웁니다.

왜 필요한가요: 출품 양식은 Slack 워크숍 채널에 올라가 모두가 봅니다. 올리기 전에 결과물에 개인정보 패턴과 키가 없는지 확인합니다.

Terminal 2, 전체 복사
cd ~/claude-lab/capstone-try
grep -nE '(^|[^0-9])([0-9]{6}-[1-4][0-9]{6}|[0-9]{4}-[0-9]{4}-[0-9]{4}-[0-9]{4}|01[016789]-[0-9]{3,4}-[0-9]{4})([^0-9]|$)' reports/*.md reports/*.html proposals/*.md || echo "개인정보 패턴 없음"
jq -r '.. | objects | (.SEOUL_API_KEY?, .ALPHA_VANTAGE_API_KEY?, .Authorization?) | strings | sub("^Bearer "; "")' ~/.claude.json 2>/dev/null \
  | while IFS= read -r V; do [ ${#V} -ge 8 ] && grep -rlF -- "$V" reports/ proposals/ ; done
echo "키 검사 끝 (위에 파일 이름이 나오면 그 파일에 키나 토큰이 있습니다)"

키 검사는 R1에서 read -rs로 받아 ~/.claude.json에 등록한 값만 찾습니다. 설치 창(userConfig)에만 넣은 키는 비밀 저장소에 있어 찾지 못하니, 그 키를 붙여 넣은 파일이 없는지 스스로도 확인합니다. 아래는 개요의 출품 양식을 트랙 B로 채운 예입니다. 내 plugin 이름, 트랙, 고른 미션으로 바꿔 Slack 워크숍 채널에 올립니다.

출품 양식, 예시
1. plugin: my-kit 0.1.0, R1-B 서울 부동산 시세, R2-1 정기 분석 리포트와 R2-2 기획안 작성
   한 줄 설명: (무엇을 하는 plugin인지)
2. 설치: /plugin marketplace add ~/claude-lab/capstone/marketplace
         /plugin install my-kit@capstone-local   (git 저장소면 그 주소)
3. 업무 두 가지: reports/(파일) 요약 한 줄, proposals/(파일) 요약 한 줄, 화면 캡처
4. 가드레일이 막은 장면: (R2 공통 04의 캡처)
5. (선택) AgentCore 앱 주소
올리기 전에 캡처와 파일에 API 키, 토큰, ~/.claude.json 내용, 고객이나 거래를 특정할 수 있는 정보가 보이지 않는지 확인합니다.
