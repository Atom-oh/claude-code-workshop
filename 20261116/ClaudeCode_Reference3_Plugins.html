REFERENCE 3 / PLUGINS

플러그인, 팀의 하네스를 배포하는 단위

워크샵 사용 플러그인 3종과 설치, mods, 금융권 통제 요령

스킬 하나를 복사해 나르던 시대에서, 스킬과 훅과 에이전트를 한 묶음으로 설치하는 시대로 넘어가는 장치가 플러그인입니다. 마켓 등록 → 설치 → 세션 재시작, 세 박자면 끝납니다.

플러그인이란

스킬, 커맨드, 서브에이전트, 훅, MCP 서버를 하나로 묶어 설치하는 배포 단위입니다. Chapter 4에서 만든 킷의 완성형이 곧 플러그인입니다.

Terminal, 기본 동사
claude plugin marketplace add <git URL 또는 마켓 이름>   # 마켓 등록
claude plugin install <플러그인>@<마켓>                  # 설치 (세션 재시작 필요)
/plugin                                                 # 세션 안 메뉴: list, enable, disable
/reload-plugins                                         # 재시작 없이 변경 반영

워크샵에서 쓰는 플러그인 3종

캡스톤 M0와 OPTION 하네스 엔지니어링에서 실제로 설치하고 사용합니다.

플러그인역할주요 커맨드워크샵 등장
superpowers@claude-plugins-official 브레인스토밍부터 실행까지의 구조화 개발 워크플로. 계획 승인 후 git worktree로 이동해 작업 /superpowers:brainstorming, /superpowers:writing-plans, /superpowers:executing-plans 캡스톤 M0
project-init@project-init
github.com/whchoi98/project-init		 하네스 스캐폴딩 자동화. 기존 프로젝트 감지 모드로 CLAUDE.md, 훅, 스킬, 테스트 골격 중 없는 것만 생성하고 문서 품질을 0-100 점수로 동기화 /project-init:init-project, /project-init:sync-docs, /health-check, /add-adr, /add-runbook OPTION 하네스
harness-eval@harness-eval
github.com/whchoi98/harness-eval		 하네스 품질을 6개 차원(정확성, 안전성, 완전성, 실행 가능성, 일관성, 검증 가능성)에서 A+~F로 채점. quick 30초, standard 2~3분, full 5~10분 /harness-eval:quick, :standard, :full, :compare OPTION 하네스
신뢰 가드 harness-eval의 standard 이상은 대상 프로젝트의 훅과 테스트를 실제 실행합니다. 본인 프로젝트는 안전하지만 남의 저장소를 평가할 때는 --static-only가 예의이자 안전입니다. 서드파티 마켓의 플러그인은 설치 전 저장소를 한 번 읽어 보는 습관을 권합니다.

기타 추천 플러그인

공식 마켓(claude-plugins-official)은 Claude Code 시작 시 자동 등록되어 있어 marketplace add 없이 바로 install됩니다. 크게 세 갈래입니다: LSP 코드 인텔리전스, 내부 워크플로 도구, 외부 서비스 연동.

플러그인 / 계열역할설치
github@claude-plugins-official 공식 GitHub MCP 서버. 이슈 생성, PR 관리와 리뷰, 저장소 검색을 세션 안에서 직접 /plugin install github@claude-plugins-official
LSP 계열 (예: pyright-lsp) 언어 서버를 물려 정의 이동, 참조 찾기, 편집 직후 타입 오류 확인. VS Code 인텔리전스와 같은 기술. 해당 언어 서버 바이너리가 시스템에 필요 /plugin 목록에서 사용 언어의 LSP 선택
42crunch-api-security-testing OpenAPI 스펙 자동 감사와 OWASP API 리스크(BOLA/BFLA 포함) 탐지, AI 수정 제안 /plugin install 42crunch-api-security-testing@claude-plugins-official
외부 서비스 연동 계열 웹 크롤링/검색, DB, 협업 도구 등 파트너 MCP 묶음. 자격증명은 각 서비스에서 발급 /plugin에서 서비스명으로 검색
두 번째 마켓, 커뮤니티 공식 마켓과 별도로 보안 스캔을 거친 커뮤니티 마켓이 있습니다. 등록과 설치는 두 줄입니다: claude plugin marketplace add anthropics/claude-plugins-community 후 claude plugin install 이름@claude-community. 마켓 add는 owner/repo 축약형과 임의 Git URL, 로컬 경로를 모두 받으므로, 팀 전용 사내 마켓을 만들어 배포하는 것도 같은 문법입니다.

Mods, Claude Code 안에서 실행되는 플러그인

mod는 JavaScript/TypeScript 이벤트 핸들러로 이루어진 플러그인입니다. 스킬이나 설정 훅이 밖에서 스크립트를 부르는 것과 달리 Claude Code 프로세스 안에서 실행되어, 프롬프트 위 밴드와 옆 패널을 그리거나 도구 호출을 가로채 확인 창을 띄울 수 있습니다. Claude Code v2.1.287 이상에서 기본으로 켜져 있습니다.

구분내용
구성 파일.claude-plugin/plugin.json, hooks/hooks.json, hooks/register.js 세 개로 시작
대표 이벤트tool.call(도구 호출 직전), prompt.submit(프롬프트 제출), ui.render(화면 그리기)
내장 mod/diff 패널, AGENTS.md 로드, 보안 가드(cc-plugin-sec-default)가 mod로 구현. /plugin의 Installed 탭 Built-in에서 확인
샘플github.com/anthropics/claude-code-playground 의 claude-code/mods: token-weather, blast-radius(위험한 셸 명령을 잡아 확인 버튼 표시), replay-theater
실행 위치터미널과 Desktop 앱 Code 탭에서 화면까지 표시. VS Code 확장, claude -p, Agent SDK에서는 훅만 실행되고 그리지 않음
Terminal, mod 시험과 사전 점검
claude --plugin-dir ./first-mod        # 이번 세션에만 로드해 시험
claude plugin validate ./some-mod      # 실행 없이 hooks:, calls: 목록만 확인
/plugin                                # "1 mod active" 줄로 로드 여부 확인
/reload-plugins                        # 셸에서 설치한 뒤 세션에 반영
샌드박스 밖에서 사용자 권한으로 실행 mod는 사용자와 같은 권한으로 파일을 읽고 쓰고 프로세스를 시작하며 네트워크를 호출할 수 있고, 모든 프롬프트와 도구 호출을 볼 수 있습니다. Bash 샌드박스를 켜도 mod가 띄운 프로세스는 샌드박스 밖에서 실행됩니다. 설치 전에 claude plugin validate의 calls: 줄에서 $.process.run, $.http.fetch, $.fs.write, $.env.get 같은 호출이 있는지 확인하세요.

금융권 환경의 플러그인과 mod 통제

규제 환경에서는 개인이 마켓을 추가하거나 --plugin-dir로 플러그인을 로드하지 못하게 하고, 심사를 마친 사내 마켓만 허용하는 구성이 기본입니다. 아래 설정은 관리형 설정(managed settings)에 넣으며 사용자가 덮어쓸 수 없습니다. 파일 위치는 Linux /etc/claude-code/managed-settings.json, Windows C:\Program Files\ClaudeCode\managed-settings.json, macOS /Library/Application Support/ClaudeCode/managed-settings.json이고, MDM이나 claude.ai 관리 콘솔로도 배포할 수 있습니다.

키효과
strictKnownMarketplaces허용할 마켓 출처 목록. 목록 밖 출처는 추가와 설치가 차단되며 []이면 공식 마켓까지 모두 차단
enabledPluginstrue는 강제 설치, false는 모든 범위에서 차단하고 목록에서 숨김
disableSideloadFlags--plugin-dir, --plugin-url, --agents 등 목록 밖 로드 경로를 시작 시점에 거부
allowManagedModsOnly내장 보안 가드의 옵션. 조직 mod와 내장 mod만 훅을 실행하고 사용자가 가져온 mod는 거부. 사용자 설정 파일에 넣어도 효과 없음. 조직 mod로 인정되는 조건은 아래 안내 참고
prependPlugins조직 정책 mod를 사용자 mod보다 먼저 실행. 감사 로그나 위험 호출 거부에 사용. 이 키를 쓰면 기본 순서가 대체되므로 목록에 sec-default@builtin을 반드시 포함해야 내장 가드가 유지되고 allowManagedModsOnly가 계속 적용됨
managed-settings.json, 사내 마켓만 허용하고 사용자 mod 차단
{
  "strictKnownMarketplaces": [
    { "source": "github", "repo": "your-org/*" }
  ],
  "extraKnownMarketplaces": {
    "your-marketplace": {
      "source": { "source": "github", "repo": "your-org/your-marketplace" }
    }
  },
  "disableSideloadFlags": true,
  "pluginConfigs": {
    "cc-plugin-sec-default@builtin": {
      "options": { "allowManagedModsOnly": true }
    }
  }
}
조직 mod로 인정받는 조건 allowManagedModsOnly가 허용하는 "조직 mod"는 세 조건을 모두 만족해야 합니다: 관리형 enabledPlugins에서 true, 마켓이 머신의 로컬 디렉터리(절대 경로)로 선언됨, 마켓이 플러그인을 상대 경로로 나열해 제자리에서 로드됨. GitHub, git, URL, npm에서 복사되는 mod는 관리형 설정으로 켜도 사용자 mod로 취급되어 거부됩니다. 위 예시의 GitHub 마켓은 플러그인 설치 허용용이며, 사내 mod를 쓰려면 MDM 등으로 디렉터리를 모든 머신의 같은 경로에 배포하고 관리자만 쓰기 가능하게 하세요. 허용 목록에 skills-dir 항목이 없으면 사용자의 ~/.claude/skills/, .claude/skills/ 아래 플러그인도 로드되지 않습니다.
공식 마켓의 금융 관련 플러그인 공식 마켓에는 금융 서비스 파트너가 올린 연동 플러그인도 있지만 Anthropic이 내용과 동작을 보증하지 않으므로 설치 전 각 제공사 페이지와 저장소를 확인해야 합니다. 위 예시처럼 허용 목록을 쓰면 공식 마켓도 명시적으로 허용한 경우에만 쓸 수 있습니다. 사용 현황은 OpenTelemetry의 claude_code.plugin_installed, claude_code.plugin_loaded 이벤트로 감사할 수 있고, 서드파티 플러그인 이름은 OTEL_LOG_TOOL_DETAILS=1을 켜야 기록됩니다. 허용 목록 예시는 code.claude.com/docs/en/plugins/org, mod 통제는 code.claude.com/docs/en/plugins/mods/admin 기준입니다.
