R2 공통 단계: R1에서 만든 것을 plugin 하나로 묶어 마켓플레이스에 올리기

R1의 agents, 새로 만드는 skill, MCP 설정, 가드레일 훅을 plugin 하나로 묶고, 로컬 마켓플레이스에 올린 뒤 새 폴더에서 동료처럼 설치해 가드레일까지 따라오는지 확인한다

R1의 작업 폴더 ~/claude-lab/capstone/에는 이 폴더에서만 쓰이는 agent, 훅, 설정이 있습니다. 이 단계에서 그것을 다른 폴더, 다른 사람이 설치 한 줄로 받아 쓰는 plugin으로 바꿉니다. plugin 원본은 ~/claude-lab/capstone/my-kit/, 마켓플레이스는 ~/claude-lab/capstone/marketplace/, 동료 역할의 새 폴더는 ~/claude-lab/capstone-try/입니다. 명령 형식은 Ch4 랩의 plugin, 로컬 마켓플레이스와 같습니다. 이 단계를 끝내면 R2 미션 두 개 이상을 같은 plugin으로 합니다.

R1 작업 폴더에 묶을 재료가 있는지 보고, 고른 트랙의 이름들을 r2.env에 적습니다.

왜 필요한가요: 이 페이지와 R2 미션 페이지의 블록이 모두 r2.env의 이름을 읽습니다. 트랙의 이름을 여기서 한 번 적어 두면 뒤의 블록은 트랙과 상관없이 같습니다.

먼저 이 페이지 전체에서 파일이 어디서 어디로 가는지 그림으로 봅니다.

skill 만들기

15분

반복 업무의 절차와 출력 형식을 skill로 적습니다. R2 미션에서 쓸 skill은 여기서 다 만들고, 미션 페이지에서는 새로 짜지 않습니다.

agent는 "누가 하는가", skill은 "어떤 순서로 무엇을 내놓는가"입니다. 아래 두 skill은 R1의 두 agent(모으는 역할과 읽기 전용 검토 역할)에게 일을 나눠 주고, 결과를 늘 같은 형식으로 냅니다. skill 안에서 agent는 plugin 이름이 붙은 my-kit:agent이름으로 부릅니다. plugin에 들어간 agent와 skill은 plugin 이름 아래로 묶이기 때문입니다 (plugin 구성 요소 공식 문서). frontmatter는 name과 description만 씁니다. 이 둘만 쓰면 Claude Code 밖(R2-3의 AgentCore 등)에서도 같은 파일을 그대로 읽을 수 있습니다.

왜 필요한가요: 절차와 출력 형식을 skill 파일에 적어 두면, 미션마다 프롬프트로 형식을 다시 설명하지 않아도 결과가 늘 같은 형식으로 나옵니다.

---
# 정기 분석 리포트

입력은 대상과 기간입니다. 빠졌으면 사용자에게 먼저 묻습니다.

## 절차
1. ${KIT}:${COLLECT} 에이전트에게 대상과 기간의 자료 수집과 집계를 맡깁니다. 요청에 다른 ${KIT}: 에이전트가 적혀 있으면 그 에이전트에게 맡깁니다.
2. 받은 결과를 아래 출력 형식 그대로 정리합니다. 형식의 항목 이름과 순서를 바꾸지 않습니다.
3. ${KIT}:${REVIEW} 에이전트에게 초안 검토를 맡겨 PASS, WARN, FAIL을 받습니다. FAIL이면 지적을 고친 뒤 한 번 더 검토받습니다.
4. reports/ 폴더에 "기간-대상.md" 이름으로 저장합니다. 같은 대상의 지난 리포트가 있으면 3번 항목에서 비교합니다.

## 출력 형식
# (대상) 정기 리포트 (기간)
1. 요약: 세 줄 이내
2. 핵심 표: 항목, 값, 직전 리포트 대비, 출처
3. 눈에 띄는 변화와 이유
4. 확인하지 못한 것
5. 검토 결과: PASS, WARN, FAIL 중 하나와 한 줄 이유

## 지키는 것
- 이 plugin의 에이전트와 MCP 도구가 준 자료만 씁니다.
- 개인 식별 정보(이름, 주민번호, 카드, 계좌, 휴대폰, customer_id, 건물명과 번지)와 키, 토큰 값은 쓰지 않습니다.
EOF

# 기획안 작성

1. 근거 리포트를 읽고, 기획에 쓸 수치와 사실을 고릅니다.

3. 아래 출력 형식 그대로 초안을 씁니다.

7. 검토 결과: PASS, WARN, FAIL 중 하나와 한 줄 이유

## 지키는 것

- 개인 식별 정보와 키, 토큰 값은 쓰지 않습니다.

20분

agents, 훅 스크립트, plugin 매니페스트(이름과 버전), README, 훅 설정, MCP 설정을 my-kit/에 모으고 claude plugin validate를 통과시킵니다.

R1 폴더의 설정은 이렇게 옮겨집니다. 확인한 곳은 plugin 매니페스트 공식 문서와 MCP 공식 문서입니다.

R1 작업 폴더plugin 안바뀌는 점
.claude/agents/*.mdagents/*.md이름이 my-kit:agent이름이 됩니다. MCP 도구 이름은 mcp__plugin_my-kit_서버__도구로 바꿔 적어야 합니다
.claude/hooks/*.shscripts/*.sh스크립트 내용은 그대로입니다
.claude/settings.json의 hookshooks/hooks.json같은 모양을 "hooks" 키로 감쌉니다. 스크립트 경로는 "${CLAUDE_PLUGIN_ROOT}/scripts/…"(설치된 plugin의 위치)로 쓰고 큰따옴표로 감쌉니다
MCP 등록(claude mcp add, ~/.claude.json).mcp.json키와 토큰은 파일에 쓰지 않고 ${user_config.이름}으로 적습니다. 설치하는 사람이 설치 창에서 넣고, 값은 settings.json이 아닌 비밀 저장소에 들어갑니다
(없음).claude-plugin/plugin.json, README.md이름, 버전 0.1.0, 설명, 키를 묻는 칸(userConfig)
permissions.deny, allowedMcpServers넣을 수 없음plugin의 설정 파일은 agent, subagentStatusLine만 적용됩니다. 이 둘은 04에서 업무 폴더 설정으로 나눠 줍니다

왜 필요한가요: R1 폴더의 agent와 훅은 그 폴더에서만 쓰입니다. plugin 폴더 하나로 모아야 다른 폴더, 다른 사람이 설치 한 줄로 같은 것을 받습니다.

1공통: 매니페스트, agents, 스크립트
Terminal, 전체 복사
cd ~/claude-lab/capstone && . ./r2.env
K=~/claude-lab/capstone/$KIT
mkdir -p $K/.claude-plugin $K/agents $K/hooks $K/scripts
for f in .claude/agents/*.md; do
  if [ -n "$SRV" ]; then sed "s/mcp__${SRV}__/mcp__plugin_${KIT}_${SRV}__/g" "$f"; else cat "$f"; fi > "$K/agents/$(basename "$f")"

05

(선택) git 저장소로 올리기

5분

마켓플레이스 폴더를 git 저장소로 만들어, 다른 컴퓨터의 동료가 저장소 주소로 추가할 수 있게 합니다. R2 미션을 끝내고 시간이 남을 때 합니다.

왜 필요한가요: 로컬 폴더 마켓플레이스는 내 컴퓨터에서만 보입니다. git 저장소에 올리면 다른 컴퓨터의 동료도 같은 plugin을 받습니다.

Terminal, 전체 복사
cd ~/claude-lab/capstone/marketplace
git init -q && git add . && git status --short
git config user.name >/dev/null || git config user.name "capstone"
git config user.email >/dev/null || git config user.email "capstone@example.com"
jq -r '.. | objects | (.SEOUL_API_KEY?, .ALPHA_VANTAGE_API_KEY?, .Authorization?) | strings | sub("^Bearer "; "")' ~/.claude.json 2>/dev/null \
  | while IFS= read -r V; do [ ${#V} -ge 8 ] && grep -rlF --exclude-dir=.git -- "$V" . ; done
echo "키 검사 끝 (위에 파일 이름이 나오면 그 파일에 키나 토큰이 있습니다)"
git commit -qm "my-kit 0.1.0" && git log --oneline

키 검사에서 파일 이름이 나오면 커밋하지 말고 그 파일부터 고칩니다. 이 검사는 R1에서 read -rs로 받아 ~/.claude.json에 등록한 값을 찾습니다. 설치 창(userConfig)에만 넣은 키는 비밀 저장소에 있어 여기서 찾지 못하므로, 그 키를 직접 붙여 넣은 파일이 없는지는 눈으로도 봅니다. 키는 plugin이 아니라 설치 창과 MCP 등록에만 있어야 합니다. GitHub 계정이 있으면 비공개 저장소를 만들고 올립니다(내계정을 바꿔 씁니다).

Terminal, GitHub 계정이 있을 때
cd ~/claude-lab/capstone/marketplace
git remote add origin https://github.com/내계정/capstone-marketplace.git
git push -u origin HEAD

동료는 세션에서 /plugin marketplace add 내계정/capstone-marketplace로 추가합니다(owner/repo 형식은 GitHub 저장소로 읽힘, plugin 명령 공식 문서). 같은 이름의 마켓플레이스는 한 사람에게 하나만 등록되므로, 내 컴퓨터에서 시험하려면 먼저 /plugin marketplace remove capstone-local로 로컬 등록을 지워야 하고, 이때 그 마켓플레이스에서 설치한 plugin도 함께 지워집니다. 그래서 이 확인은 R2 미션을 다 끝낸 뒤에 합니다.
