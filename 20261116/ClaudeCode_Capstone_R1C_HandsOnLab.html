직접 고른 서버도 아래 블록과 같은 모양으로 r1c-choice.env 네 줄을 손으로 씁니다. ALLOW_ENTRY는 원격 서버면 등록한 주소 그대로의 serverUrl, 로컬 서버면 등록한 명령과 인자를 순서까지 그대로 적은 serverCommand입니다. TOOLS는 세션의 /mcp에서 본 읽기 도구 이름입니다.

3고른 서버 하나를 연결

고른 서버의 블록 하나만 실행합니다. 각 블록은 먼저 r1c-choice.env(고른 서버 이름, 허용 목록 항목, 허용 호스트, agent에 줄 도구 이름)를 만들고 서버를 등록합니다. 이 파일에는 키를 넣지 않습니다. 01과 02의 블록이 이 파일을 읽어서 같은 값을 씁니다.

alphavantage: 시세, 환율, 경제지표 (무료 키)
Terminal, 이 서버를 골랐을 때 전체 복사
cd ~/claude-lab/capstone
UVX=$(command -v uvx || echo "$HOME/.local/bin/uvx")
cat > r1c-choice.env << EOF
SRV=alphavantage
ALLOW_ENTRY='{"serverCommand": ["$UVX", "--from", "marketdata-mcp-server", "--with", "mcp<2", "marketdata-mcp"]}'
NET_ALLOW="www.alphavantage.co"
TOOLS="mcp__alphavantage__TOOL_LIST, mcp__alphavantage__TOOL_GET, mcp__alphavantage__TOOL_CALL"
EOF
read -rs AV_KEY
claude mcp add --env ALPHA_VANTAGE_API_KEY="$AV_KEY" --transport stdio alphavantage -- "$UVX" --from marketdata-mcp-server --with "mcp<2" marketdata-mcp
unset AV_KEY
claude mcp list

키는 Alpha Vantage 무료 키 신청에서 받고, read -rs 줄에서 붙여 넣고 Enter를 누릅니다(화면과 셸 기록에 남지 않음). 키는 --env로 ~/.claude.json에만 들어갑니다. 제공처 안내의 uvx marketdata-mcp-server 키 한 줄은 2026-11-09 확인 때 실행 파일 이름이 marketdata-mcp로 바뀌어 실패했고, 최신 mcp 2.x와도 맞지 않아서 --from과 --with "mcp<2"로 고정했습니다. 서버는 키를 인자 대신 환경 변수 ALPHA_VANTAGE_API_KEY로도 읽습니다(공식 저장소 소스 확인). 무료 키는 하루 25회라 시험 호출을 아껴 씁니다.

github: 저장소와 이슈, 읽기 전용 (토큰 또는 gh 로그인)
Terminal, 이 서버를 골랐을 때 전체 복사
cd ~/claude-lab/capstone
cat > r1c-choice.env << 'EOF'
SRV=github
ALLOW_ENTRY='{"serverUrl": "https://api.githubcopilot.com/mcp/readonly"}'
NET_ALLOW="api.githubcopilot.com"
TOOLS="mcp__github__get_me, mcp__github__search_repositories, mcp__github__get_file_contents, mcp__github__list_issues, mcp__github__issue_read"
EOF
read -rs GH_PAT
claude mcp add --transport http github https://api.githubcopilot.com/mcp/readonly -H "Authorization: Bearer $GH_PAT"
unset GH_PAT
claude mcp list

기본은 위 블록입니다. 토큰은 GitHub의 fine-grained personal access token으로, 필요한 저장소에 읽기 권한만, 짧은 만료로 만듭니다. 주소 끝의 /readonly는 읽기 도구만 내놓는 공식 주소입니다. 토큰은 -H 헤더로 ~/.claude.json에만 들어갑니다. 도구 이름 다섯 개는 2026-11-10 실습 PC에서 실제 이름과 같음을 확인했습니다. /mcp에서 한 번 더 봅니다.

대안: 토큰을 만들 시간이 없으면 gh로 로그인. 실습 PC에는 GitHub CLI(gh)가 있습니다. 아래 블록은 위 블록과 같은 r1c-choice.env를 만들고, 토큰 대신 브라우저 로그인으로 받은 gh 토큰을 헤더에 넣습니다. 두 블록 중 하나만 실행합니다.

Terminal, gh로 로그인할 때 전체 복사
cd ~/claude-lab/capstone
cat > r1c-choice.env << 'EOF'
SRV=github
ALLOW_ENTRY='{"serverUrl": "https://api.githubcopilot.com/mcp/readonly"}'
NET_ALLOW="api.githubcopilot.com"
TOOLS="mcp__github__get_me, mcp__github__search_repositories, mcp__github__get_file_contents, mcp__github__list_issues, mcp__github__issue_read"
EOF
gh auth login --hostname github.com --git-protocol https --web --expiring && T=$(gh auth token) && [ -n "$T" ] \
  && claude mcp add --transport http github https://api.githubcopilot.com/mcp/readonly -H "Authorization: Bearer $T"
unset T
claude mcp list

gh auth login은 브라우저 로그인 절차를 엽니다. Git 자격 증명 도우미를 설정할지 물으면 Continue without it을 고르고, 화면에 나온 8자리 코드를 https://github.com/login/device에서 입력해 승인합니다. 로그인이 끝나야 다음 줄이 그 토큰(gh auth token)으로 서버를 등록하고, unset T가 셸에 남은 값을 지웁니다. gh가 없거나(설치는 실습 환경이 최선을 다해 시도합니다), 로그인을 취소했거나, --expiring을 모르는 옛 gh면 서버를 등록하지 않고 끝납니다. 그때는 claude mcp list에 github가 없는지 보고, 있으면 claude mcp remove github 뒤 기본 블록을 씁니다.

gh 토큰을 쓸 때 알아 둘 것
  • 권한이 넓습니다. gh 로그인 토큰은 repo(쓰기 포함), read:org, gist 권한을 가지며 줄일 수 없습니다. 도구를 읽기 전용으로 묶는 것은 주소 끝의 /readonly뿐입니다. 회사 저장소에 쓸 때는 기본 블록의 fine-grained 토큰을 씁니다.
  • 8시간 뒤 만료됩니다. --expiring으로 받은 토큰은 8시간짜리이고, MCP 등록에는 등록한 순간의 토큰 값이 들어갑니다. 만료되어 /mcp에서 github가 실패하면 claude mcp remove github 뒤 gh 블록의 gh auth login부터 다시 실행합니다.
  • 실습이 끝나면 로그아웃합니다. 갱신 토큰이 ~/.config/gh/hosts.yml에 6개월 동안 남으므로, 실습을 마칠 때 gh auth logout을 실행합니다. 02의 deny 규칙은 Claude의 파일 읽기 도구가 이 폴더를 읽지 못하게 막습니다. Bash 명령은 막지 않으므로, Claude가 gh auth token이나 이 파일을 여는 명령을 실행하겠다고 물으면 허락하지 않습니다.

1어느 설정을 어디에 둘 수 있나

MCP 접근 통제 공식 문서와 권한 공식 문서에서 확인한 키입니다.

설정둘 수 있는 곳과 동작이 랩에서
allowedMcpServers모든 설정 범위(사용자, 프로젝트, local, managed). 범위마다의 목록이 합쳐집니다. managed의 잠금이 없으면 사용자 설정이 목록을 넓힐 수 있습니다. 설정이 없으면 모든 서버, 빈 배열이면 서버 없음프로젝트 .claude/settings.json에 고른 서버 하나
deniedMcpServers모든 설정 범위. 항상 합쳐지고, 허용 목록보다 먼저 적용됩니다쓰지 않음 (허용 목록으로 충분)
allowManagedMcpServersOnlymanaged 설정에서만 동작. 켜면 managed의 허용 목록만 남습니다쓰지 않음 (조직 강제용)
managed-mcp.json, managedMcpServersmanaged에서만. 서버를 고정 배포하거나 모두에게 내려줍니다쓰지 않음
권한 규칙 mcp__<서버>__<도구>모든 설정 범위. deny는 어느 범위에 있든 allow보다 앞섭니다. 그래서 mcp__*를 deny하고 한 서버만 allow하는 식의 "하나만 빼고 막기"는 되지 않습니다그 대신 mcp-guard 훅으로 고른 서버만 통과시킵니다
enableAllProjectMcpServers, enabledMcpjsonServers, disabledMcpjsonServers프로젝트 .mcp.json 서버의 승인. 저장소가 스스로 승인한 것은 신뢰하지 않은 폴더에서 무시되고, disabledMcpjsonServers는 어디에 있든 거부합니다이 랩은 local 범위로 등록해 .mcp.json을 쓰지 않습니다

허용 목록 항목은 원격 서버를 serverUrl(주소, * 가능)로, 로컬 서버를 serverCommand(명령과 인자 배열, 순서까지 정확히 같아야 함)로 맞춥니다. serverName(등록 이름)은 누구나 아무 이름이나 붙일 수 있어서 공식 문서도 보안 통제가 아니라고 적습니다. 그래서 이 랩은 주소와 명령으로 적습니다.

2도구 훅: mcp-guard.sh

MCP 도구 호출(mcp__로 시작)마다 실행됩니다. 인자로 받은 서버의 도구만 통과시키고, 그 서버의 도구라도 이름에 create, update, delete, write, push, merge, add 같은 말이 든 쓰기 성격 도구는 막습니다. 이름 기준의 예시 패턴이니 고른 서버의 도구 이름을 보고 조정합니다.

Terminal, 전체 복사
cd ~/claude-lab/capstone
cat > .claude/hooks/mcp-guard.sh << 'EOF'
#!/bin/bash
# 사용: mcp-guard.sh <허용할 MCP 서버 이름>...
INPUT=$(cat)
command -v jq >/dev/null || { echo "MCP: 검사기 오류(jq 없음) - 안전을 위해 차단" >&2; exit 2; }
[ $# -ge 1 ] || { echo "MCP: 허용할 서버 이름이 설정에 없음 - 차단" >&2; exit 2; }
TOOL=$(printf '%s' "$INPUT" | jq -er '.tool_name') || { echo "MCP: 입력 해석 실패 - 차단" >&2; exit 2; }

case "$TOOL" in mcp__*) ;; *) exit 0 ;; esac   # MCP 도구가 아니면 관여하지 않는다

for s in "$@"; do
  REST=${TOOL#"mcp__${s}__"}
  [ "$REST" != "$TOOL" ] || continue
  # 허용한 서버라도 쓰기 성격의 도구는 막는다 (도구 이름 기준 예시 패턴)
  if printf '%s' "$REST" | grep -Eiq '(^|_)(create|update|delete|remove|write|edit|move|push|merge|add)(_|$)'; then
    echo "MCP: 쓰기 성격 도구($TOOL)는 차단됩니다" >&2; exit 2
  fi
  exit 0
done
echo "MCP: 허용 목록 밖의 MCP 도구($TOOL). 허용 서버: $*" >&2
exit 2
EOF
chmod +x .claude/hooks/mcp-guard.sh
3호출 대상 훅: net-guard.sh

Bash 명령과 WebFetch의 입력에서 http(s):// 호스트를 뽑아, 인자로 받은 호스트가 아니면 막습니다. 인자는 r1c-choice.env의 NET_ALLOW(고른 서비스의 호스트, docs는 없음)입니다.

Terminal, 전체 복사
cd ~/claude-lab/capstone
cat > .claude/hooks/net-guard.sh << 'EOF'
#!/bin/bash
# 사용: net-guard.sh <허용할 호스트>...   (인자가 없으면 URL이 든 호출을 모두 막는다)
INPUT=$(cat)
command -v jq >/dev/null || { echo "NET: 검사기 오류(jq 없음) - 안전을 위해 차단" >&2; exit 2; }
TEXT=$(printf '%s' "$INPUT" | jq -r '.tool_input | [.. | strings] | join("\n")') \
  || { echo "NET: 입력 해석 실패 - 차단" >&2; exit 2; }

ALLOW=" $* "
HOSTS=$(printf '%s\n' "$TEXT" | grep -oiE "https?://[^/[:space:]\"'<>]+" | sed -E 's#^[A-Za-z]+://##; s#^[^@]*@##; s#:[0-9]+$##' | tr 'A-Z' 'a-z' | sort -u)
for h in $HOSTS; do
  case "$ALLOW" in
    *" $h "*) ;;
    *) echo "NET: 허용되지 않은 호출 대상($h). 허용: ${*:-없음}" >&2; exit 2 ;;
  esac
done
exit 0
EOF
chmod +x .claude/hooks/net-guard.sh

5프로젝트 설정에 허용 목록, 훅, deny 규칙 등록

r1c-choice.env의 값으로 .claude/settings.json을 만듭니다. onFailure: block은 스크립트가 없거나 시작하지 못하거나 시간 초과인 경우까지 막습니다(v2.1.295+, 공식 훅 문서, Ch2 Lab 2 TASK 02). permissions.deny의 WebSearch는 웹 검색 도구를 없애고, Read(~/.claude.json)는 키나 토큰이 저장된 사용자 설정 파일 읽기를 막습니다. Read(~/.config/gh/**)는 github 서버를 gh로 등록할 때 로그인 토큰이 든 폴더를 Claude의 파일 읽기 도구에서 막습니다. 두 규칙 모두 파일 읽기 도구에만 걸리고 Bash 명령은 막지 않으니, 키를 보여 주는 명령은 허락하지 않습니다. 다른 트랙에서 만든 settings.json이 있으면 덮어쓰게 되니, 한 트랙만 진행합니다.

Terminal, 전체 복사
cd ~/claude-lab/capstone && . ./r1c-choice.env
H="$HOME/claude-lab/capstone/.claude/hooks"
jq -n --arg srv "$SRV" --arg net "$NET_ALLOW" --arg h "$H" --argjson entry "$ALLOW_ENTRY" '{
  allowedMcpServers: [$entry],
  permissions: { deny: ["WebSearch", "Read(~/.claude.json)", "Read(~/.config/gh/**)"] },
  hooks: { PreToolUse: [
    { matcher: "mcp__.*",
      hooks: [{ type: "command", command: "\($h)/mcp-guard.sh \($srv)", onFailure: "block" }] },
    { matcher: "Bash|WebFetch",
      hooks: [{ type: "command", command: "\($h)/net-guard.sh \($net)", onFailure: "block" }] }
  ] }
}' > .claude/settings.json && cat .claude/settings.json && echo "settings OK"
출력 예 (aws-knowledge를 고른 경우, 일부)
{
  "allowedMcpServers": [

    }

설정은 세션을 다시 열어야 적용됩니다. 이 폴더에서는 허용 목록에 없는 서버가 모두 목록에서 빠집니다. 사용자 범위로 등록해 둔 서버와 Setup에서 설치한 plugin이 내놓는 MCP 서버도 주소나 명령이 이 항목과 다르면 이 폴더에서는 보이지 않는데, 이것이 의도한 동작입니다. 주소나 명령이 같은 서버는 사용자 범위에 있든 plugin에 있든 함께 통과합니다(00의 microsoft-learn 안내, 03의 claude mcp list 설명). R2에서 plugin으로 묶을 때도 plugin 안의 MCP 서버 주소나 명령이 이 항목과 같아야 연결됩니다.

훅이 보지 못하는 것 훅은 Claude가 부르는 도구의 입력 문자열만 봅니다. MCP 서버 자신이 밖으로 보내는 요청(로컬 서버 프로세스의 호출, 원격 서버 뒤쪽의 호출)과 명령의 결과, 스킴 없이 쓴 호스트, 변수로 조립한 URL은 보지 못합니다. 그래서 어떤 서버에 붙을지를 허용 목록으로 묶고, agent의 tools에서 Bash와 웹 도구를 빼 둡니다. 명령 단위의 네트워크 차단이 필요하면 Ch2 Lab 2의 선택 TASK 04(sandbox)를 겹칩니다. MCP 서버가 돌려준 응답도 이 훅들은 검사하지 않으므로, 응답에 섞인 개인정보나 민감한 내용은 agent 지시문(개인정보, 키, 토큰 값을 쓰지 않는다)과 evidence-reviewer의 검토로만 걸러집니다.
조직이 강제하려면 프로젝트 설정의 허용 목록과 훅은 사용자가 고치거나 끌 수 있습니다. 조직이 강제하려면 Ch2에서 쓴 managed 설정(/etc/claude-code/managed-settings.json)에 allowedMcpServers와 allowManagedMcpServersOnly: true를 함께 넣고, 훅은 allowManagedHooksOnly로 managed 훅만 돌게 합니다. 이 랩에서는 managed 설정을 바꾸지 않습니다.

증상점검
고른 서버까지 목록에서 사라졌다허용 목록 항목이 등록한 값과 다릅니다. claude mcp list가 보여 주는 주소나 명령과 r1c-choice.env의 ALLOW_ENTRY를 글자 단위로 비교하고(로컬 서버는 인자 순서까지), 고친 뒤 02의 Step 5를 다시 실행합니다
목록 밖 서버가 등록된다사용자 설정의 허용 목록이 합쳐져 넓어졌을 수 있습니다. jq '.allowedMcpServers' ~/.claude/settings.json이 null이 아니면 그 목록에 든 서버도 허용됩니다. 세션 밖에서 작업 폴더로 cd 했는지도 봅니다
claude mcp list에서 연결 실패원격 서버는 주소 오타와 네트워크. 로컬 서버는 npx, uvx가 있는지. alphavantage는 uvx --from marketdata-mcp-server --with "mcp<2" marketdata-mcp --help가 되는지. 등록을 고치려면 claude mcp remove <이름> 후 다시 add
alphavantage가 한도 메시지를 낸다무료 키는 하루 25회입니다. 질문을 좁히거나 다른 서버로 R1을 끝내고, 키 쪽은 다음 날 다시 시험합니다
정상 MCP 호출이 막힌다메시지 앞머리를 봅니다. MCP: 쓰기 성격 도구면 mcp-guard의 패턴이 그 도구 이름에 걸린 것이니 패턴을 좁힙니다. 도구 이름의 서버 부분이 SRV와 같은지도 봅니다
훅이 아예 안 돈다세션을 다시 열었는지, 폴더 신뢰(Yes, I trust this folder)를 눌렀는지. Ch2 Lab 2에서 managed 정책에 넣은 allowManagedHooksOnly가 남아 있으면 사용자, 프로젝트, 플러그인 훅이 모두 무시됩니다. sudo jq '.allowManagedHooksOnly' /etc/claude-code/managed-settings.json이 true면 Ch2 Lab 2 TASK 07(전체 원복)을 먼저 합니다
