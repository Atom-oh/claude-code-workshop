HANDS-ON LAB / CAPSTONE OVERVIEW

캡스톤 개요: 내 에이전트와 플러그인을 만들어 다시 쓴다

R1은 데이터 미션 하나, R2는 재사용 미션 두 개 이상

캡스톤의 목적은 본인만의 agents를 만들고 계속 사용 가능한 plugin을 사내에 배포해서 사용하며, 공통으로 사용하는 가드레일을 만든다는 것입니다. 결과물의 화려함이 아니라, 배운 것(plugin, skill, agent, harness)을 직접 만들어 하나의 재사용 가능한 도구로 완성하는 것이 핵심입니다. 진짜 결과물은 재사용 가능한 plugin, 또는 agent + skill + MCP 세트이고, 앱이나 문서는 그 plugin이 제대로 동작한다는 것을 보여 주는 재료입니다.

R1

R1 미션, 셋 중 하나

110분

데이터 미션 하나를 고릅니다. 모든 미션의 끝은 같습니다. 고른 데이터를 다루는 자기 Subagent 2개 이상(역할이 겹치지 않고 도구 권한이 역할에 맞게 좁혀짐, 읽기 전용 검토 역할 하나를 권장)과, 실제로 막는 가드레일 하나 이상(훅이나 권한 deny 규칙, fail-closed)이 동작하고, 작업 폴더의 CLAUDE.md와 설정이 정리돼 있어야 합니다. 이것이 R2에서 plugin으로 묶을 재료입니다. 110분은 SETUP 15분을 포함한 시간이고, 각 미션 페이지의 단계는 SETUP 뒤 95분 안에 끝나도록 짜여 있습니다.

규칙: R1은 셋 중 하나만 고릅니다.
R1-A

고객 맞춤 서비스

데이터: 마이데이터 (랩 Ch3 체크포인트에서 출발)
만들 agents (예)
고객 한 명의 자산과 소비를 보는 상담 준비 agent, 읽기 전용 검토 agent
가드레일 (예)
주민번호, 계좌 등 개인정보 차단, 원본 raw/ 접근 차단
R1-A 미션 페이지로
R1-B

서울 부동산 시세

데이터: 서울 열린데이터광장 실거래가, 전월세 (MCP 직접 제작)
만들 agents (예)
지역별 시세를 정리하는 agent, 이상 거래를 찾는 agent
가드레일 (예)
API 키 노출 차단, 호출 대상과 횟수 제한
R1-B 미션 페이지로
R1-C

내가 고른 MCP

데이터: 교육생이 고른 MCP (추천 목록 제공)
만들 agents (예)
그 데이터를 다루는 agent 2개
가드레일 (예)
MCP 허용 목록, 외부 호출 범위
R1-C 미션 페이지로

미션 표의 agent 이름과 가드레일은 예시입니다. 같은 틀 안에서 주제를 바꿔도 됩니다.

R2

R2 미션, 공통 단계 후 두 개 이상

180분

R2는 R1의 agents를 plugin으로 묶는 공통 단계에서 시작합니다. 그다음 같은 plugin으로 재사용 미션을 해 냅니다. R2 미션은 R1에서 고른 데이터와 상관없이 고를 수 있습니다. 두 번째 업무에서 agent와 skill을 다시 짜지 않았다는 것을 보일 수 있어야 합니다.

규칙: R2 공통 단계를 먼저 하고, 미션 중 둘 이상을 고릅니다. R2-3은 선택 미션이지만 고르면 두 개 중 하나로 셉니다.
R2 공통

plugin으로 묶어 마켓플레이스 배포

할 일
R1의 agents, 새 skill, MCP 설정, 가드레일 훅을 plugin 하나로 묶고, 마켓플레이스에 올려 새 폴더에서 설치합니다.
확인
설치한 새 폴더에서도 가드레일이 막습니다.
R2 공통 단계 페이지로

정기 분석 리포트

같은 plugin으로
정해진 형식의 분석 리포트를 반복해서 만드는 skill과 명령
R2-1 미션 페이지로
R2-2

기획안 작성

분석 결과를 상품이나 서비스 기획안 형식으로 정리
R2-2 미션 페이지로
R2-3 (선택)

AgentCore 앱

같은 plugin으로

R2-3 미션 페이지로
가드레일의 강제력 plugin 훅은 사용자가 끌 수 있습니다. 조직이 강제하려면 Ch2의 managed 정책으로 내립니다.

완주 체크리스트

아래 7가지가 모두 되면 완주입니다. 마지막 판단은 R2 끝에 합니다. 트랙 A(마이데이터)는 1번의 "자기 Subagent 2개 이상"을 새로 만든 1개 이상과 체크포인트에서 가져와 고친 것으로 셉니다.

COMPLETION CHECKLIST
이러면 완주가 아닙니다
  • 결과물이 한 번 쓰고 버리는 스크립트나 데모 앱뿐이고, plugin으로 묶여 다시 설치되지 않는다.
  • 두 번째 업무에서 agent나 skill을 처음부터 다시 짠다 (재사용이 증명되지 않음).
  • 가드레일이 문서에만 있고 실제로 아무것도 막지 않는다.
  • 빠른 결과를 위해 API 키나 개인정보가 plugin 저장소나 Slack 출품물에 그대로 남는다.
  • 화려한 UI를 만드느라 R2 시간을 다 쓰고 배포와 재사용 단계를 못 한다.

Slack 워크숍 채널에 아래 양식으로 올립니다. 모든 미션 페이지의 출품은 이 양식을 따릅니다.

  5. (선택) AgentCore 앱 주소
